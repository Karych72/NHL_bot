**Роль:** инженер-исполнитель.

## 1. Цель этапа

Зафиксировать **явный, воспроизводимый контракт** между артефактами билдера датасета (`dataset_train.csv`, `metadata_train.json`) и будущим кодом обучения: какие файлы обязательны, какие поля в метаданных считаются источником истины для матрицы признаков \(X\), как отделяются ключи, метки и служебные колонки **без эвристик по префиксам имени колонки**, где это уже определено манифестом.

Уже реализованный билдер: `modeling/dataset_builder/`, CLI `python -m modeling.cli build-dataset`. Константы колонок и манифест: `modeling/dataset_builder/schema.py` (`KEY_COLUMNS`, `LABEL_COLUMNS`, `SERVICE_COLUMNS`, `feature_manifest`, `features_hash`). Документ билдера: `docs/modeling_dataset_builder.md`.

---

## 2. Объём работ (делать только этап 1)

### 2.1 Контракт в коде и коротко в документации

- Описать контракт так, чтобы следующий этап (конфиг обучения, сплиты) мог опираться на **одну** функцию загрузки и один формат метаданных.
- Минимум:
  - в модуле загрузки — docstring с перечислением входов, обязательных ключей в JSON и семантикой \(X\) / ключей / меток;
  - короткий подраздел (несколько абзацев или список) в `docs/modeling_dataset_builder.md` **или** новый файл `docs/modeling_training.md` со ссылкой на модуль загрузки и на пример путей артефактов после `build-dataset` — на усмотрение, главное чтобы контракт был discoverable из документации билда/обучения.

Обязательные элементы контракта (зафиксировать явным текстом):

- Путь к табличному файлу обучения: **`dataset_train.csv`** (основной формат на v1) и обязательный рядом **`metadata_train.json`**. Parquet для train допускается **только** если добавлена симметричная поддержка чтения и это отражено в том же контракте (иначе ограничиться CSV).
- В метаданных обучения обязательно присутствуют и используются загрузчиком: **`feature_manifest`** (или эквивалентное поле, совпадающее с тем, что пишет билдер), **`features_hash`**, **`feature_set_version`** — как в текущем выводе билдера; при отсутствии или несовпадении с таблицей — предсказуемая ошибка (fail-fast).

### 2.2 Функция загрузки

Реализовать модуль в пакете `modeling/` (имя на усмотрение, например `modeling/train_input.py` или `modeling/dataset_load.py`) с публичной функцией вида:

- вход: путь к CSV (и при поддержке — parquet), путь к `metadata_train.json`;
- чтение таблицы в `pandas`;
- загрузка JSON метаданных;
- построение матрицы **\(X\) строго по списку имён из манифеста** в порядке манифеста (согласованность с `ordered_columns_for_output` / билдером);
- отделение:
  - ключей: `game_id`, `day`, `season_id`, `home_team_id`, `away_team_id` (как в `schema.KEY_COLUMNS`, если колонка есть в таблице);
  - меток: `y_home_win`, `y_over_5_5` при наличии;
  - служебных: пересечение фактических колонок датафрейма с `schema.SERVICE_COLUMNS` (или тем же списком, что билдер кладёт в train-вывод — не разъезжаться с `schema.py`);
  - **\(X\) не собирать по префиксам и не как «все остальные колонки», если манифест задаёт полный перечень признаков** — исключение только для колонок, явно не входящих в манифест, но присутствующих в файле: либо ошибка, либо игнор с логированием — выбрать одно поведение и задокументировать (предпочтительно fail-fast при лишних колонках в \(X\)-области или несовпадении с манифестом).

Переиспользовать существующую логику из `schema.py` (`assert_feature_parity`, нормализация dtype, константы колонок), не дублировать списки ключей/меток в разных стилях.

### 2.3 Тесты

- Юнит-тесты на синтетическом минимальном CSV + JSON метаданных: корректное разбиение на \(X\), ключи, метки; порядок колонок \(X\) совпадает с манифестом.
- Тест на ошибку при несовпадении имён/порядка признаков с манифестом или при отсутствии обязательных ключей в JSON.

---

## 3. Критерии приёмки

1. Из документации и из docstring ясно: какие два файла нужны для обучения и какие поля JSON обязательны.
2. Одна функция (или узкий фасад) загружает train-таблицу и возвращает \(X\) и сопутствующие структуры согласно манифесту; списки ключей/меток/служебных согласованы с `schema.py`.
3. Нет «угадывания» набора признаков по шаблонам имён там, где манифест уже задаёт состав \(X\).
4. Тесты покрывают успешный путь и ключевой негативный сценарий (несовместимость с манифестом).

---

## 4. Ограничения и вне скоупа

- Не реализовывать этапы 2–15 UPDATE-плана (конфиг YAML, сплиты, метрики, обучение моделей, расширенный CLI `train`) в рамках этой задачи — только контракт и загрузчик + минимальная дока и тесты.
- Не менять контракт билдера без необходимости; если выявится расхождение с реальным `metadata_train.json`, согласовать правку билдера или адаптер — отдельным обоснованием в MR.
