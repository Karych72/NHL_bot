## 1. Принцип ревью

Приоритет: **отсутствие утечки будущего в train**, **детерминизм** сплитов, **fail-fast** на битых конфигах и нехватке данных, **отсутствие шифровки случайностью** (никаких `shuffle=True`), согласованность с уже зафиксированным контрактом входа (этап 1).

Цена ошибки в сплитах максимальна: любой leak здесь обнулит все метрики ниже по пайплайну. Поэтому при сомнении в любом из блокеров ниже — `request changes` без компромиссов.

---

## 2. Сквозные требования

- [ ] `modeling/splits.py` **не импортирует** `psycopg2`, `modeling.dataset_builder.*` (есть тест или явно видно при чтении импортов).
- [ ] Если сплиттер принимает `metadata_train.json` (или его поля) — при расхождении YAML и метадаты по `feature_set_version` / `features_hash` / `rolling_windows` бросается `ConfigError` с диффом полей. Если сплиттер этих полей не касается — это явно отмечено в docstring и тесты не вводят их в заблуждение.
- [ ] Никаких импортов из `sklearn.model_selection`, выводящих `shuffle=True` поведение (`KFold(shuffle=True)`, `StratifiedKFold(shuffle=True)`, `ShuffleSplit`, `train_test_split` без `shuffle=False`).
- [ ] Внутри сплиттера нет `np.random.*` без явного `default_rng(seed)`; на этом этапе случайность не нужна вовсе.
- [ ] Сплиттер не зависит от текущего времени / `datetime.now()` — иначе результаты не воспроизводимы между прогонами.

---

## 3. API и семантика walk-forward

- [ ] Есть явный `SplitConfig` (или эквивалентный dataclass / Pydantic) с полями `method`, `n_test_windows`, `inner_val_games`, `calibration_games`, `holdout_fraction_or_date_range` (+ `outer_block_games` для `fixed_games`). Дефолтов «по тихому» нет — всё либо обязательно, либо имеет явный документированный дефолт.
- [ ] Вход сплиттера — DataFrame ключей с `day` (datetime64) и `game_id`. Перед нарезкой делается **стабильная сортировка** по `(day, game_id)`, а не полагается на исходный порядок.
- [ ] Holdout режется **первым** с конца таймлайна и **исключается** из walk-forward.
- [ ] Для каждого `k`: `train_k` — expanding window до `inner_val_k`. После train идут ровно три последовательных непересекающихся блока: `inner_val_k → calibration_k → test_k`.
- [ ] Финальный holdout строго после всех `test_k`; пересечений по `game_id` нет.
- [ ] Возвращаемая структура содержит **позиционные индексы или `game_id`** (но не оба сразу, без неоднозначности) + диапазоны дат + размеры блоков. Достаточно для логирования в `metrics.json` без повторного прохода по датасету.

---

## 4. Внутренняя валидация (fail-fast в самом модуле, не только в тестах)

- [ ] Монотонность по времени для каждого outer-блока проверяется **внутри сплиттера** перед возвратом: `max(day(train_k)) < min(day(inner_val_k)) ≤ max(day(inner_val_k)) < min(day(calibration_k)) ≤ max(day(calibration_k)) < min(day(test_k)) ≤ max(day(test_k)) < min(day(holdout))`.
- [ ] Пересечение holdout с любым train/val/cal/test по `game_id` — `SplitError`.
- [ ] `|inner_val_k| ≥ split.inner_val_games`, `|calibration_k| ≥ split.calibration_games`, `|test_k| > 0`, `|train_k| > 0` — проверяется и фейлит с понятным сообщением, а не молча обрезает блок.
- [ ] При нехватке данных на `n_test_windows` — `SplitError` с явным сообщением «история короче N окон при текущих параметрах»; не «тихая» отдача меньшего числа окон.
- [ ] `n_test_windows < 5`, `inner_val_games < 300`, `calibration_games < 300` — `ConfigError` при инициализации `SplitConfig`, а не позже.

---

## 5. Embargo и комментарии

- [ ] В `modeling/splits.py` есть **явный** комментарий с словом `embargo`, обоснованием отказа от него (rolling-фичи с `shift(1)`, отсутствие фич «текущего матча») и ссылкой на этап 4 UPDATE-плана.
- [ ] Этот комментарий не закопан в docstring приватной функции, а виден на верхнем уровне модуля или у класса сплиттера.

---

## 6. Тесты

- [ ] `tests/test_modeling_splits.py` присутствует и проверяет:
  - монотонность по времени для каждого outer-блока;
  - отсутствие пересечения holdout с train/val/cal по `game_id`;
  - минимальные размеры `inner_val_k` и `calibration_k`;
  - детерминизм сортировки на двух перетасованных копиях одного датафрейма;
  - fail-fast на `n_test_windows < 5`, `inner_val_games < 300`, `calibration_games < 300`;
  - fail-fast при нехватке данных на запрошенное число окон.
- [ ] `tests/test_modeling_no_shuffle_cv.py` присутствует (базовая версия) и реально срабатывает на искусственном файле с `KFold(shuffle=True)` (можно проверить локально, добавив временный модуль и убедившись, что тест падает).
- [ ] Тесты используют синтетический мини-датасет, **не** обращаются к PostgreSQL и не зависят от реальных артефактов `dataset_train.csv` — иначе CI ляжет.

- [ ] В docstring `SplitConfig` и публичной функции сплиттера явно сказано: что возвращается, в каком порядке, какие гарантии (монотонность, отсутствие утечки, expanding train).
- [ ] Если выбрано хранение `game_id` вместо позиционных индексов (или наоборот) — это явно зафиксировано в docstring; ревьюер проверяет, что в коде/тестах ровно одна из двух конвенций.

## 9. Вердикт

**approve / approve with nits / request changes**.

**Блокеры (любой — `request changes` без обсуждения):**

- Любое нарушение монотонности train → inner_val → calibration → test → holdout, не отлавливаемое сплиттером.
- Пересечение holdout с train/val/cal/test (по `game_id` или по датам), не отлавливаемое сплиттером.
- Использование `shuffle=True` / `ShuffleSplit` / `KFold(shuffle=True)` / `StratifiedKFold(shuffle=True)` где-либо в `modeling/`.
- Молчаливое уменьшение числа окон при нехватке данных вместо fail-fast.
- Отсутствие хотя бы одного из ключевых тестов §6 (монотонность, отсутствие пересечения holdout, минимальные размеры, fail-fast на конфиге).
- Импорт `psycopg2` / `modeling.dataset_builder.*` в `modeling/splits.py`.
- Случайность без явного `default_rng(seed)`; зависимость сплитов от `datetime.now()`.

- Стиль docstring и сообщений ошибок; нейминг полей `SplitConfig`.
- Выбор «позиционные индексы vs `game_id`» — обе конвенции приемлемы, главное чтобы одна.
- Полнота диаграммы в `docs/modeling_training.md`; оформление таблицы YAML-полей.
- Отсутствие `tests/test_modeling_no_db_access.py` хотя бы для `splits.py` — пожелание, не блокер (полный охват — на этапе 11).
