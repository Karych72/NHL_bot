## 1. Цель этапа

Свести воедино и **завершить** автоматические тесты подсистемы моделирования так, чтобы они стали исполнимым контрактом этапов 4–10 и закрывали критерий приёмки §12.2 UPDATE-плана («автотесты этапа 11 проходят целиком»). Тесты обязаны:

1. Защищать инвариант **отсутствия утечки будущего** (сплиты, калибровка).
2. Защищать **корректность метрик** на эталонных мини-векторах.
3. Защищать **архитектурные запреты** проекта (нет доступа к PostgreSQL в train-коде; нет `shuffle=True` CV) статическими AST-проверками.
4. Давать **быстрый smoke** полного CLI-пути `train --dry-run`.
5. Защищать **монотонные ограничения** LightGBM на синтетической монотонной зависимости.

Часть тестовых файлов уже могла появиться в базовых версиях на этапах 4–6. Этот этап их **дополняет до полного охвата §11**, а не переписывает с нуля и не дублирует.

## 2. Сквозные требования (обязательны к применению на этом этапе)

Из раздела «Сквозные требования» UPDATE-плана для тестов действуют:

- **Источник истины фич — `metadata_train.json`.** Любой тест, которому нужна метадата, использует синтетический мок `metadata_train.json` с консистентными `feature_manifest` / `features_hash` / `feature_set_version`; тесты не должны опираться на реальный артефакт.
- **Воспроизводимость.** Тесты детерминированы: единый seed, никаких «плавающих» ассертов по времени. Любая случайность в фикстурах — через `numpy.random.default_rng(seed)` с фиксированным seed.
- **Лимит потоков.** Smoke- и LGBM-тесты выставляют малое число потоков/итераций, чтобы не выжигать CPU в CI.
- **Логи.** Тесты не пишут в `artifacts/reports/...`; используют `tmp_path`/`tmp_path_factory` pytest, не оставляя мусора в репозитории.
- **`<run_id>`.** Smoke-тест не привязывается к конкретному `<run_id>` (он содержит UTC-таймстамп) — проверяет формат/наличие блоков, а не точное значение.
- **Никакого доступа к PostgreSQL.** Все тесты работают на синтетических мини-датасетах в памяти/`tmp_path`; запрещено подключение к БД и чтение реального `dataset_train.csv`. Сам этот инвариант ещё и **проверяется тестом** `test_modeling_no_db_access.py` (см. §3.4).

## 3. Объём работ

Целевой список файлов (из карты файлов UPDATE-плана):

```

  test_modeling_metrics.py

  test_modeling_no_shuffle_cv.py

```

Общая фикстура синтетического мини-датасета (ключи `day`, `game_id`, метки `y_home_win`/`y_over_5_5`, монотонные фичи) выносится в `tests/conftest.py` или локальный helper (`tests/_modeling_fixtures.py`) — без обращения к БД.

### 3.1 `tests/test_modeling_splits.py` (дополнить до полного §11)

Поверх базовой версии этапа 4 обеспечить покрытие именно формулировок §11:

1. **Монотонность по времени** для каждого outer-блока:
   `max(day(train_k)) < min(day(inner_val_k)) < min(day(calibration_k)) < min(day(test_k)) < min(day(holdout))`.
2. **Отсутствие пересечения holdout** с `train`/`inner_val`/`calibration` по `game_id` — для всех `k`.
3. **Минимальные размеры**: `|inner_val_k| ≥ split.inner_val_games`, `|calibration_k| ≥ split.calibration_games`.

Если базовая версия этапа 4 уже покрывает эти три пункта — не дублировать, лишь убедиться в наличии и согласованности имён ассертов.

### 3.2 `tests/test_modeling_metrics.py`

- **Эталонные logloss / Brier / ECE** на ручных мини-векторах (значения посчитаны вручную/независимо, зашиты в тест как константы с `pytest.approx`).
- **ECE на идеально откалиброванном предикторе ≈ 0** (в пределах допуска бинификации).
- **Тривиальный baseline** считается из **train base rate**, а не из test: тест подаёт разные base rate в train и test и проверяет, что константа берётся из train.
- Покрыть клиппинг `p ∈ [ε, 1−ε]`: logloss на `p=0`/`p=1` не даёт `inf` при включённом клиппинге.

### 3.3 `tests/test_modeling_calibration.py`

- На синтетических вероятностях: калибратор обучается **только на `calibration_k`** и **не видит** `test`/`holdout` — проверяется через мок срезов (например, передачей маркированных массивов и проверкой, что в `fit` калибратора попали только индексы `calibration_k`).
- Путь **`calibration_skipped=true`** при `|calibration_k| < calibration.min_samples`: проверить, что флаг выставлен и в отчёт уходит сырая вероятность с пометкой.
- (Желательно) проверка, что `sklearn.calibration.CalibratedClassifierCV` **не используется** в `modeling/calibrate.py` — либо здесь, либо в `test_modeling_no_shuffle_cv.py` как AST-запрет (см. §3.5; согласовать, чтобы запрет был ровно в одном месте).

### 3.4 `tests/test_modeling_no_db_access.py`

- **AST-проверка** (парсинг исходников, не импорт-исполнение), что перечисленные файлы **не импортируют** `psycopg2` и `modeling.dataset_builder.*`:
  - `modeling/train_logreg.py`, `modeling/train_lgbm.py` (любые `modeling/train_*.py`),
  - `modeling/calibrate.py`,
  - `modeling/splits.py`,
  - `modeling/metrics.py`.
- Учесть формы импорта: `import psycopg2`, `from psycopg2 import ...`, `import modeling.dataset_builder...`, `from modeling.dataset_builder import ...`, алиасы. Транзитивные импорты внутри `modeling/` тоже должны быть чисты (если файл импортирует другой `modeling/`-модуль, тянущий БД, — это нарушение; минимально проверить прямые импорты, транзит — желательно).
- Список проверяемых файлов брать программно (glob по шаблонам), чтобы новый `train_*.py` автоматически попадал под проверку.

### 3.5 `tests/test_modeling_no_shuffle_cv.py` (дополнить до полного §11)

- **AST-запрет** в любом файле под `modeling/`:
  - `KFold(shuffle=True)`, `StratifiedKFold(shuffle=True)`, `ShuffleSplit`;
  - (рекомендуется, по духу этапа 4) `train_test_split` без явного `shuffle=False`.
- Базовая версия появилась на этапе 4 — здесь расширить охват на все файлы `modeling/` и убедиться, что тест **реально падает** на искусственном модуле с `KFold(shuffle=True)` (самопроверка приведена в ревью-ТЗ).
- При выборе размещения AST-запрета `CalibratedClassifierCV` (см. §3.3) — зафиксировать его ровно в одном тесте.

### 3.6 `tests/test_modeling_cli_smoke.py`

- На синтетическом мини-датасете запуск `python -m modeling.cli train --dry-run --config <tmp config>`:
  - отрабатывает **за ≤ 5 секунд** (мягкий бюджет; в ассерте использовать с запасом, см. §4 ограничения по времени);
  - печатает **все размеры блоков** train/inner_val/calibration/test/holdout (проверить наличие чисел/меток в stdout);
  - `--dry-run` **не обучает** модели и **не создаёт** артефакты моделей.
- Запуск — через `subprocess` (как реальный CLI) либо через прямой вызов точки входа CLI с перехватом stdout; конфиг и мини-датасет кладутся в `tmp_path`.

### 3.7 `tests/test_modeling_lgbm_monotone.py`

- Синтетический датасет с **заведомо монотонной** зависимостью таргета от фичи `f` (например `P(y=1)` строго растёт с `f`).
- Обучить LGBM с `monotone_constraints`, где для `f` задан положительный знак.
- На тестовом скане признака (сетка возрастающих значений `f` при фиксированных прочих) предсказанная вероятность **не убывает** — знак ограничения не нарушен.
- Тест помечается `@pytest.mark.skipif`, если `lightgbm` не установлен (зависимость из `requirements-modeling.txt`, не из основного `requirements.txt`).

## 4. Ограничения по ресурсам и стабильности

- Все тесты — **детерминированы** и **быстры**: суммарно подсистема моделирования не должна заметно тормозить CI. LGBM-тест — минимальное число деревьев/листьев, достаточное для проявления монотонности.
- Никаких сетевых вызовов, БД, чтения реальных артефактов.
- Бюджет времени smoke-теста (≤ 5 с) — это требование к самому `--dry-run`, а не жёсткий ассерт «упасть на 5.01 с». В ассерте допускается запас на холодный старт CI (например, фейл при > 15 с), но в комментарии зафиксировать целевые 5 с из §11.

## 5. Критерии приёмки

1. Все семь файлов из §3 присутствуют в `tests/` и проходят локально:
   `pytest tests/test_modeling_splits.py tests/test_modeling_metrics.py tests/test_modeling_calibration.py tests/test_modeling_no_db_access.py tests/test_modeling_no_shuffle_cv.py tests/test_modeling_cli_smoke.py tests/test_modeling_lgbm_monotone.py`.
2. Каждый пункт формулировок §11 UPDATE-плана имеет соответствующий ассерт (трассируемость «пункт плана → тест»).
3. `test_modeling_no_db_access.py` и `test_modeling_no_shuffle_cv.py` — **статические AST-проверки**, не импортирующие проверяемые модули ради side-effect; список файлов собирается glob-ом.
4. Все тесты работают на синтетике в `tmp_path`, без БД и без реального `dataset_train.csv`; артефактов в репозитории после прогона не остаётся.
5. LGBM-тест корректно пропускается при отсутствии `lightgbm`, но проходит при установленных `requirements-modeling.txt`.
6. Smoke-тест подтверждает, что `--dry-run` печатает размеры всех блоков и не создаёт артефакты моделей.

- Не вводить новые зависимости в основной `requirements.txt`; тестовые потребности LGBM покрываются `requirements-modeling.txt` (этап 3).
