## 1. Принцип ревью

Приоритет: тесты этапа 11 — это **исполнимый контракт** этапов 4–10. Главные критерии:

- тесты реально **ловят утечку** (сплиты, калибровка), а не просто «зелёные»;
- метрики проверены на **эталонных** мини-векторах с независимо посчитанными значениями;
- архитектурные запреты (нет PostgreSQL в train-коде, нет `shuffle=True`) проверяются **статически (AST)** и реально срабатывают на нарушении;
- тесты **детерминированы, быстры, без БД**.

Тест, который всегда зелёный независимо от поведения кода, — хуже отсутствия теста: он создаёт ложную уверенность. При обнаружении такого — `request changes`.

---

## 2. Сквозные требования

- [ ] Все тесты работают на **синтетике** (`tmp_path` / in-memory), **без** подключения к PostgreSQL и **без** чтения реального `dataset_train.csv` / реальных артефактов.
- [ ] Тесты **детерминированы**: единый seed, любая случайность через `numpy.random.default_rng(seed)`; нет «плавающих» ассертов по времени или порядку.
- [ ] После прогона в репозитории **не остаётся** мусора (нет записи в `artifacts/...`, всё во временных каталогах pytest).
- [ ] Метадата в тестах — синтетический мок `metadata_train.json`; нет зависимости от реального артефакта.
- [ ] LGBM/smoke-тесты ограничивают потоки/итерации, не выжигают CPU.

---

## 3. Покрытие пунктов §11 (трассируемость)

Для каждого подпункта §11 UPDATE-плана должен существовать конкретный ассерт. Проверить наличие:

- [ ] **`test_modeling_splits.py`**: монотонность по времени для каждого outer-блока; отсутствие пересечения holdout с train/val/cal по `game_id`; `|inner_val_k| ≥ inner_val_games`, `|calibration_k| ≥ calibration_games`. (Дубля с этапом 4 быть не должно — либо переиспользование, либо расширение.)
- [ ] **`test_modeling_metrics.py`**: эталонные logloss/Brier/ECE на ручных векторах; ECE идеально откалиброванного предиктора ≈ 0; тривиальный baseline берётся из **train** base rate, а не из test.
- [ ] **`test_modeling_calibration.py`**: калибратор учится только на `calibration_k` (мок срезов подтверждает, что test/holdout не видны); путь `calibration_skipped=true` при малом срезе.
- [ ] **`test_modeling_no_db_access.py`**: AST-запрет импорта `psycopg2`, `modeling.dataset_builder.*` в `modeling/train_*.py`, `calibrate.py`, `splits.py`, `metrics.py`.
- [ ] **`test_modeling_no_shuffle_cv.py`**: AST-запрет `KFold(shuffle=True)`, `StratifiedKFold(shuffle=True)`, `ShuffleSplit` в `modeling/`.
- [ ] **`test_modeling_cli_smoke.py`**: `train --dry-run` отрабатывает быстро (целевые ≤ 5 с) и печатает размеры всех блоков.
- [ ] **`test_modeling_lgbm_monotone.py`**: на монотонной синтетике обученный LGBM не нарушает знак `monotone_constraints` при скане признака.

## 4. Качество тестов (не «зелёные ради зелёного»)

- [ ] **AST-тесты реально срабатывают.** Локально убедиться (или потребовать от исполнителя демонстрации): временно создать модуль `modeling/_canary.py` с `import psycopg2` → `test_modeling_no_db_access.py` падает; с `KFold(shuffle=True)` → `test_modeling_no_shuffle_cv.py` падает. После проверки canary удалить.
- [ ] AST-проверки **парсят исходник** (`ast.parse`), а не импортируют модуль ради побочного эффекта (импорт мог бы потянуть БД и сломать сам тест).
- [ ] Список проверяемых файлов в AST-тестах собирается **glob-ом** по шаблонам (`modeling/train_*.py` и т.п.), чтобы новый `train_*.py` автоматически попадал под запрет, а не хардкодом, который протухнет.
- [ ] **Эталонные метрики** в `test_modeling_metrics.py` — независимо посчитанные константы (ручной расчёт/формула в комментарии), а не «то, что вернул код» (иначе тест не ловит регрессию).
- [ ] **Тест калибровки** действительно доказывает изоляцию `calibration_k`: если убрать защиту от утечки в `calibrate.py`, тест должен покраснеть (мок срезов фиксирует, какие индексы попали в `fit`).
- [ ] **LGBM-монотонность**: знак ограничения и направление зависимости согласованы; тест помечен `skipif` при отсутствии `lightgbm`, но не «выключен навсегда».

## 5. Smoke-тест CLI

- [ ] Запуск идёт через реальную точку входа CLI (`python -m modeling.cli train --dry-run ...` либо прямой вызов entrypoint с перехватом stdout), а не через приватные внутренности в обход CLI.
- [ ] `--dry-run` **не создаёт** артефакты моделей и **не обучает** — проверяется (нет файлов в целевых каталогах артефактов после прогона).
- [ ] Бюджет времени: целевые ≤ 5 с из §11 зафиксированы в комментарии; жёсткий ассерт допускает разумный запас на холодный CI, но не «выключен».
- [ ] Конфиг и мини-датасет создаются в `tmp_path`, не в репозитории.

---

## 6. Скоуп

- [ ] MR этапа 11 **не меняет** продакшн-код этапов 4–10 ради «подгонки» под тест. Если изменения есть — они обоснованы как фикс реального бага и перечислены в описании MR.
- [ ] Нет новых зависимостей в основном `requirements.txt`; потребности LGBM закрыты `requirements-modeling.txt` (этап 3).
- [ ] Нет интеграционных тестов с реальной БД/датасетом (это вне §11).

## 7. Вердикт

**approve / approve with nits / request changes**.

**Блокеры (любой — `request changes` без обсуждения):**

- Отсутствует один из семи тестовых файлов §11 или один из ключевых ассертов (утечка сплитов, изоляция калибровки, эталонные метрики, AST-запреты БД/shuffle).
- AST-тест реализован так, что **не падает** на нарушении (не ловит canary) — ложная защита.
- Эталонные метрики «списаны» с вывода кода, а не посчитаны независимо.
- Тест калибровки/сплитов не краснеет при внесении утечки.
- Тесты обращаются к PostgreSQL / реальному `dataset_train.csv`, либо недетерминированы, либо оставляют артефакты в репозитории.
- Smoke-тест обходит реальный CLI или допускает создание артефактов при `--dry-run`.

**Ниты:**

- Стиль ассертов, имена тестов и фикстур; размещение общей фикстуры (`conftest.py` vs helper).
- Где именно живёт AST-запрет `CalibratedClassifierCV` (в калибровочном или shuffle-тесте) — приемлемо любое, но ровно одно место.
- Точная величина запаса в ассерте времени smoke-теста.
- Полнота транзитивной AST-проверки импортов (прямые импорты — обязательны, транзит — пожелание).
