## 1. Принцип ревью

Приоритет: **изоляция ML-стека от рантайма бота**, **воспроизводимость** (зафиксированные версии библиотек), **минимальный delta** в существующие файлы (`Makefile`, `Dockerfile`, `requirements.txt`). Цель этапа узкая: появляется один новый файл зависимостей, одна новая цель `Makefile`, одно дополнение в документацию.

---

## 2. `requirements-modeling.txt`

- [ ] Файл существует в корне репозитория.
- [ ] Содержит ровно ожидаемый состав: `numpy`, `pandas`, `scikit-learn`, `lightgbm`, `matplotlib`, `pyyaml`, `joblib`. Лишних пакетов нет.
- [ ] **Не** содержит `catboost` (этап 15 UPDATE-плана).
- [ ] **Не** содержит `psycopg2*` и других БД-драйверов (сквозное требование: train-код не ходит в PostgreSQL).
- [ ] **Не** содержит зависимостей бота (`python-telegram-bot`, `requests`, `jinja2` — если они нужны как транзитивные, то приходят через pip resolver, в файл их вписывать не надо).
- [ ] Версии **зафиксированы** для основных ML-библиотек (`scikit-learn`, `lightgbm`, `numpy`, `pandas`, `matplotlib`, `pyyaml`, `joblib`) — иначе будущий этап обучения не сможет честно логировать версии в `metadata.json` артефакта.
- [ ] В начале файла есть короткий комментарий о назначении и о том, что файл **не** относится к рантайму бота / Docker.

---

## 3. `Makefile`

- [ ] Появилась цель `modeling-dev` (именно с таким именем — совпадение с UPDATE-планом).
- [ ] Цель ставит зависимости из `requirements-modeling.txt` через `$(PIP) install -r requirements-modeling.txt`.
- [ ] Цель использует то же `.venv` / `$(PIP)`, что и остальные цели проекта (нет параллельного venv, нет глобального `pip`).
- [ ] Цель добавлена в `.PHONY`.
- [ ] Существующие цели `setup`, `setup-dev`, `run-bot`, `bot`, `ci-local`, `test-fast`, `all-tests` **не** начали ставить `requirements-modeling.txt` — runtime бота и CI бота остались без ML-зависимостей.
- [ ] Никаких глобальных env-переменных потоковости (`OMP_NUM_THREADS`, `MKL_NUM_THREADS`, `LIGHTGBM_*`) в цели `modeling-dev` не зашито (потоки задаются YAML-конфигом моделирования на последующих этапах).

---

## 4. Изоляция от Docker-образа бота

- [ ] `Dockerfile` **не** упоминает `requirements-modeling.txt`.
- [ ] `docker-compose.yml` **не** упоминает `requirements-modeling.txt`.
- [ ] При необходимости `.dockerignore` дополнен так, чтобы локальные артефакты моделирования и сам файл `requirements-modeling.txt` не утекали в контекст сборки бота (опционально — на усмотрение исполнителя; блокером не считать, если изоляция уже обеспечена структурой `Dockerfile`, который копирует только `requirements.txt`).
- [ ] Образ бота, построенный по текущему `Dockerfile`, **не** содержит `lightgbm`, `scikit-learn`, `matplotlib` (проверяется логически — `Dockerfile` ставит только `requirements.txt`).

## 5. Документация

- [ ] В `DEVELOPMENT.md` (или в соответствующем файле документации моделирования — `docs/modeling_dataset_builder.md` / `docs/modeling_training.md`) есть короткий абзац: что такое `requirements-modeling.txt`, как ставить (`make modeling-dev`), почему **не** в runtime бота, ремарка про CatBoost (вынесен в этап 15).
- [ ] Ссылки в документе ведут на актуальные пути (нет битых якорей).

## 6. Сквозные требования UPDATE-плана

- [ ] Воспроизводимость: версии библиотек реально зафиксированы (см. §2). Это предусловие для логирования `metadata.json` в следующих этапах.
- [ ] Нет следов БД-доступа в train-зависимостях (см. §2).
- [ ] Лимит потоков не зашит глобально на уровне Makefile / venv (см. §3).

---

## 7. Скоуп MR

- [ ] В MR **нет** новых файлов в `modeling/` (никаких `splits.py`, `metrics.py`, `train_*.py`, `calibrate.py`, `config.py`, `cli.py`), нет нового `configs/modeling_default.yaml`, нет новых тестов — всё это относится к будущим этапам UPDATE-плана.
- [ ] `requirements.txt`, `requirements-dev.txt` не меняются (или меняются только косметически с явным обоснованием в MR — тогда **не** блокер, но обязательно проговорено).
- [ ] Нет добавления `requirements-modeling-catboost.txt` или Optuna-зависимостей (этап 15).

## 8. Вердикт

**approve / approve with nits / request changes**.

**Блокеры:**

- ML-стек просочился в `requirements.txt` / `requirements-dev.txt` / `Dockerfile`;
- в `requirements-modeling.txt` присутствует `catboost`, `psycopg2*` или другие запрещённые здесь зависимости;
- версии основных ML-библиотек не зафиксированы;
- цель `Makefile` называется иначе, чем `modeling-dev`, либо `setup` / `setup-dev` / `run-bot` начали тянуть `requirements-modeling.txt`;
- в MR есть посторонняя работа из этапов 2 и 4–15 (новые модули моделирования, конфиги, тесты, CLI `train`).

**Ниты:**

- стиль пинов версий (точечный `==` vs диапазон) — согласовать с остальным проектом;
- формулировки документации, расположение абзаца (`DEVELOPMENT.md` vs `docs/modeling_*`);
- наличие / отсутствие записи в `.dockerignore` — не блокер, если изоляция уже обеспечена `Dockerfile`.
