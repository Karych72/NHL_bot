# ТЗ для исполнителя: Фаза 6 — тесты и документация

**Роль:** инженер-исполнитель.  
**Источник требований:** `plan/engineering/refactoring_plan_2.md`, раздел «Фаза 6».

---

## 1. Цель фазы

Повысить предсказуемость релизов за счёт тестового контура и понятности публичного API модулей.

---

## 2. Задача **6.1** — тесты

1. Структура: каталог **`tests/`**, общие фикстуры в **`conftest.py`**.
2. Покрытие:
   - **Unit:** чистые функции (форматирование, маппинг callback, шаблоны, хелперы статистики).
   - **Интеграционные:** по возможности БД/бот — с существующими паттернами проекта (моки, testcontainers, sqlite — **как уже принято** или с обоснованием нового подхода).
3. Тесты должны **стабильно** проходить в CI (см. Фазу 2).

---

## 3. Задача **6.2b** — docstrings

- Добавить **docstrings к публичным функциям** (модули бота, работа с данными, точки входа CLI при необходимости).
- Формат: краткое описание, `Args`/`Returns` где полезно; соответствовать стилю доминирующему в репозитории (Google/NumPy — по факту существующих файлов).

---

## 4. Критерии приёмки

- Новые/расширенные тесты закрывают хотя бы один **реальный регресс** из недавней истории или критичный путь (например, путаница полей статистики из Фазы 1).
- Публичные функции, которые вызываются из нескольких модулей, имеют docstring.
- Документация не дублирует очевидное; нет опечаток в именах параметров.

---

## 5. Ограничения

- Не раздувать интеграционные тесты до e2e без инфраструктуры.
- Не добавлять «пустые» тесты ради coverage.
