# ТЗ для ревьюера: Фаза 6 — тесты и документация

**Роль:** независимый reviewer.  
**Источник:** `plan/engineering/refactoring_plan_2.md`, Фаза 6. Пара ТЗ: [`executor_tz.md`](executor_tz.md).

---

## 1. Принцип ревью

Оценивать **полезность** тестов (ловят реальные баги) и **актуальность** docstrings, а не только количество строк.

---

## 2. Тесты **6.1**

- [ ] `tests/` и `conftest.py` организованы логично, нет хрупкой зависимости от порядка запуска.
- [ ] Unit-тесты проверяют поведение и граничные случаи, а не «вызвалось без исключения».
- [ ] Интеграционные тесты воспроизводимы в CI; нет хардкода путей разработчика.
- [ ] Фикстуры не маскируют баги (избегать чрезмерного mock всего слоя без assert на контракт).

---

## 3. Docstrings **6.2b**

- [ ] Публичные функции, изменённые или добавленные в рамках работы, документированы.
- [ ] Описание совпадает с сигнатурой (не устаревшие параметры).
- [ ] Нет вводящих в заблуждение формулировок про данные/единицы измерения.

---

## 4. Вердикт

**approve / approve with nits / request changes**; блокеры — флейковые/бессмысленные тесты и неверная документация публичного API.
