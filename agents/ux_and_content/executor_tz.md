# ТЗ для исполнителя: Фаза 7 — UX и контент

**Роль:** инженер-исполнитель.  
**Источник требований:** `plan/engineering/refactoring_plan_2.md`, раздел «Фаза 7» и блок «Рекомендуемый порядок исправлений» (пересечение с Фазой 1/навигацией учитывать при планировании спринта).

---

## 1. Цель фазы

Сделать бот **проходимым в UI**, расширить навигацию и обогащение контента без потери стабильности ядра.

---

## 2. Пакет задач (выполнять итерациями по согласованию, не обязательно одним MR)

### 2.1 Навигация и отсутствие «тупиков»

- **7.1:** вернуть `reply_markup` во всех обработчиках, где пользователь попадает в тупик после статистики.
- **7.2a:** исправить переходы goalie-обработчиков: **`TEAM_STATS` → `CHOOSE_STATS`**.
- **7.2b:** добавить в меню **турнирную таблицу** (функция `team_table()` уже есть).
- **7.2c:** кнопка **«Назад»** на каждом уровне навигации (единый паттерн).
- **7.2d:** выбор даты дайджеста: **Вчера / Сегодня / Выбрать дату**.

### 2.2 Контент и форматирование

- **7.3:** обогатить сообщения (PPG/SHG/EN, периоды, звёзды матча, позиции игроков).
- **7.4:** включить неиспользуемые данные (карточка команды, расширенная стата игроков/вратарей).
- **7.5:** вычисляемые фичи (серии, хет-трики, сравнения).
- **7.6:** push-уведомления (утренний дайджест, подписка на команду).
- **7.7:** переход на **HTML**-форматирование и `<pre>` для таблиц.
- **7.8:** команды `/start`, `/standings`, `/today`, `/team`, `/help`.

---

## 3. Критерии приёмки (общие)

1. Любой счастливый путь из меню завершается осмысленным следующим шагом или выходом; нет мёртвых состояний без клавиатуры.
2. Callback-данные и `dialog_states` согласованы; нет конфликтующих префиксов.
3. Новые сообщения читаемы в Telegram (лимиты длины, экранирование HTML).
4. Для **7.6** — явно описать модель подписок, хранение chat_id, ограничения Telegram Bot API.

---

## 4. Ограничения

- Сложные подпункты (**7.5–7.6**) желательно выносить в отдельные MR с фичефлагами или поэтапной выкладкой.
- Не ломать существующие сценарии без миграции пользовательских состояний (при необходимости — сброс state при `/start`).
