# ТЗ для ревьюера: Фаза 7 — UX и контент

**Роль:** независимый reviewer.  
**Источник:** `plan/engineering/refactoring_plan_2.md`, Фаза 7. Пара ТЗ: [`executor_tz.md`](executor_tz.md).

---

## 1. Принцип ревью

Приоритет: **отсутствие тупиков в UI**, корректность **callback/state machine**, **безопасность** подписок (**7.6**) и читаемость сообщений в Telegram.

---

## 2. Навигация (7.1, 7.2a–7.2d)

- [ ] После любого экрана статистики есть логичный `reply_markup` или явный выход.
- [ ] Переходы вратарей и `TEAM_STATS`/`CHOOSE_STATS` не смешивают сценарии команд/игроков.
- [ ] Турнирная таблица доступна из меню и отображает ожидаемые данные.
- [ ] «Назад» ведёт на **родительский** уровень, а не в случайный корень.
- [ ] Выбор даты дайджеста покрывает три режима; edge cases (полночь, таймзона) задокументированы или обработаны.

---

## 3. Контент (7.3–7.5)

- [ ] Новые поля статистики соответствуют источнику данных (нет путаницы имён колонок).
- [ ] Таблицы не «ломают» layout в клиентах Telegram; HTML экранирован корректно.
- [ ] «Вычисляемые фичи» имеют понятное определение (что считается серией, какой сезон и т.д.).

---

## 4. Уведомления и команды (7.6–7.8)

- [ ] Подписки не шлют спам; есть отписка; хранение предпочтений безопасно.
- [ ] Новые slash-команды не конфликтуют с существующими; `/help` отражает актуальное меню.

---

## 5. Вердикт

**approve / approve with nits / request changes**. Блокеры: тупики в UI, неверные callback, XSS-риски в HTML, утечки данных в уведомлениях.
