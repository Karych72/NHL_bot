# ТЗ для исполнителя: Фаза 3 — качество кода

**Роль:** инженер-исполнитель.  
**Источник требований:** `plan/engineering/refactoring_plan_2.md`, раздел «Фаза 3».

---

## 1. Контекст

В плане **все пункты Фазы 3 отмечены выполненными** (3.1–3.5). Задача исполнителя на этой фазе — **верификация и устранение дрейфа**, если что-то из списка снова появилось в коде.

---

## 2. Что проверить (чеклист)

1. **3.1** — нет «старых» критичных `print()` в перечисленных модулях (`bot.py`, `script_bot.py`, `load_season_modern.py` и др. по плану); используется `logging`.
2. **3.2** — отсутствуют star-imports в перечисленных файлах.
3. **3.3b** — удалён мёртвый закомментированный код (`reply_markup`, `PG_PASSWORD`, `logging`, `argparse` и т.д. — по актуальности).
4. **3.4b** — type hints в обработчиках и ключевых функциях бота согласованы с линтером/тайпчекером проекта.
5. **3.5** — дублирующие обработчики заменены фабрикой/общим паттерном там, где это было целью рефакторинга.

---

## 3. Действия при обнаружении расхождений

- Минимальными правками вернуть соответствие плану **или** зафиксировать в MR, почему пункт закрыт иначе (с обновлением `refactoring_plan_2.md` — только по согласованию с владельцем плана).

---

## 4. Критерии приёмки

- Чеклист Фазы 3 в `plan/engineering/refactoring_plan_2.md` остаётся правдивым после прохода ветки.
- Локально проходят линт и typecheck, если они есть в проекте.

---

## 5. Ограничения

Не раздувать рефакторинг: только закрытие регрессов относительно заявленного «уже сделано».
