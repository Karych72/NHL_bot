## 2. Задача **5.4** — кэширование

1. Выявить участки с частыми повторными запросами к БД/API при типовых сценариях бота (меню, повторный выбор команды, лидеры и т.д. — по профилю или по коду).
2. Внедрить кэширование через **`functools.lru_cache`** (для чистых функций с хешируемыми аргументами) и/или **`cachetools`** (TTL, ограничение размера), **обоснованно** для конкретных кейсов.
3. Документировать в коде **ключ/scope** кэша (что именно инвалидируется сезоном, днём, или сбросом бота).

---

## 3. Критерии приёмки

- Измеримо снижается число одинаковых тяжёлых запросов при повторных действиях пользователя **или** обосновано почему выигрыш минимален (без пустой «декоративной» обёртки).
- Нет утечки памяти: ограничения по размеру/TTL для неограниченных структур.
- Корректность данных: после обновления расписания/статистики пользователь не видит устаревшие данные дольше приемлемого окна (явно выбрать TTL или точку инвалидации).

---

## 4. Ограничения

- Не кэшировать персональные секреты и токены.
- Не менять контракт БД ради кэша.
