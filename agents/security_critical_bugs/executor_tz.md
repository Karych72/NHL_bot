# ТЗ для исполнителя: Фаза 1 — безопасность и критические баги

**Роль:** инженер-исполнитель.  
**Источник требований:** `plan/engineering/refactoring_plan_2.md`, раздел «Фаза 1».  
**Статус в плане:** пункт **1.2c / 5.1** (объединение конфигов) уже отмечен выполненным — не дублировать работу, только убедиться, что текущий код не регрессирует.

---

## 1. Цель фазы

Устранить критические ошибки отображения статистики и шаблонов, без расширения функциональности.

---

## 2. Обязательные задачи

### 2.1 **1.3b** — статистика игроков (неверные поля)

- `bot_player_plus_minus`: выводить **plus_minus**, а не `hits`.
- `bot_player_penalties`: выводить **штрафные минуты (pim)**, а не `plus_minus`.

Найти соответствующие хендлеры/маппинг колонок и SQL (если применимо), исправить единообразно.

### 2.2 **1.3c** — callback вратарей

- В `script_bot.py` (или связанном регистрации callback) исправить обработчик кнопки вратарей: **`PLAYER_GOALS` → `PLAYER_GOALIE`** (как указано в плане).

### 2.3 **1.3d** — шаблон гола

- В `telegram_bot/messages/game_message.txt` заменить плейсхолдер **`{{ time }}` на `{{ goal['time'] }}`** (или эквивалент, согласованный с тем, как в коде передаётся контекст в шаблон).

---

## 3. Критерии приёмки

1. В UI/логах плюс-минус и PIM соответствуют семантике полей БД/API.
2. Навигация к статистике вратарей не уходит в обработчик голов.
3. В сообщениях о голах время отображается корректно, шаблон рендерится без ошибок.
4. Запуск бота и сценарии, затронутые правками, проверены вручную или тестами (если есть).

---

## 4. Ограничения

- Не менять схему БД и публичные контракты API без отдельного согласования.
- Минимальный дифф: только то, что нужно для пунктов 1.3b–1.3d и согласованности шаблона с кодом.
