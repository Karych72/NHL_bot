# Запуск Telegram-бота

Запуск бота на локальной машине после того, как уже подняты PostgreSQL и
загружены данные.

Установка окружения и загрузка данных — отдельный документ:
[`data_loading.md`](data_loading.md).

## Требования

- **Python 3** (в проекте используется venv `.venv`).
- **Токен Telegram-бота** от [@BotFather](https://t.me/BotFather).
- **PostgreSQL** с теми же `PG_*`, что и у лоадера, и **уже загруженными
  данными** (см. `data_loading.md` §4 «Загрузка данных NHL»).
- Сеть для запросов к Telegram.

## Быстрый старт (кратко)

Предполагаем, что окружение и БД уже подняты по `data_loading.md`:

```bash
# В .env должен быть TELEGRAM_BOT_TOKEN
make bot
```

В Telegram отправьте боту `/stats`.

## 1. Переменные окружения (`.env`)

Бот использует следующие переменные:

| Переменная | Назначение |
|------------|------------|
| `TELEGRAM_BOT_TOKEN` | Токен бота от @BotFather; **обязателен** для `make bot`. |
| `ANTHROPIC_API_KEY` | Ключ Claude API для свободного текста (§8); **обязателен** для бота, рассылке не нужен. |
| `PG_HOST` / `PG_PORT` / `PG_USER` / `PG_DATABASE` | Те же `PG_*`, что использует лоадер; для бота тоже **обязательны** (см. §2.1). |
| `SEASON_ID` | Сезон, по которому бот фильтрует ответы (`config.SEASON_ID`); **обязателен**, без дефолта — падение на старте, если не задан. Подпись сезона в сообщениях (`config.CURRENT_SEASON`, например `26/27`) выводится из него, отдельной переменной больше нет (`config.derive_season()`, Задача 33). |
| `ENABLE_PUSH_DIGEST` | `0`/`1` — разрешить скрипт рассылки `push_digest_job.py` (по умолчанию выкл.). |
| `PUSH_SEND_INTERVAL_SEC` | Пауза между сообщениями при массовой отправке (по умолчанию `0.05`). |

Модуль `telegram_bot/config.py` читает эти переменные. `Makefile` подключает
`.env` автоматически.

## 2. Запуск

### 2.1. Базовый

```bash
make bot
```

Выполняется `telegram_bot/bot.py` через интерпретатор из `.venv`; `bot.py::main()`
перед стартом polling вызывает `config.validate_env("ANTHROPIC_API_KEY")` — падает с
сообщением, называющим переменную, если пуст или не задан `TELEGRAM_BOT_TOKEN`,
`ANTHROPIC_API_KEY` или любой из `PG_HOST`/`PG_PORT`/`PG_USER`/`PG_DATABASE`/`SEASON_ID`.

### 2.2. С автоматической подготовкой окружения

```bash
make run-bot    # setup + env-example + bot
make run-local  # синоним run-bot
```

Полезно при первом запуске или после `git pull`, когда могли измениться
зависимости.

### 2.3. Полный цикл «с нуля»

```bash
make setup env-example
# заполнить .env (TELEGRAM_BOT_TOKEN, PG_*, SEASON_ID)
make db-reset-local
make season-load-full
make bot
```

Пересоздаёт venv, пересоздаёт схему БД, прогоняет актуальный NHL-пайплайн
(`load_season_modern.py`) и поднимает бота. Подробности по `season-*`
целям и окнам дат — в [`data_loading.md`](data_loading.md).

## 4. Команды бота

Список команд формируется в `telegram_bot/help_text.py` (`BOT_COMMANDS` — один источник
для `/help` и меню команд Telegram, которое `bot.py` публикует через `set_my_commands`
при старте) и регистрируется в `telegram_bot/bot.py`. Краткий список:

| Команда | Что делает |
|---------|------------|
| `/start`, `/help` | Стартовое сообщение и список команд. |
| `/stats` | Лидеры игроков одним экраном кнопок: полевые (очки, голы, передачи, +/−, хиты, блоки, штраф, игровое время), вратари (победы, % отражённых, сухие); кнопка «Расширенная статистика» открывает подменю: Corsi / Fenwick / GF% / OZ-старт / shootout % и голы по типу броска, с расшифровкой метрик. |
| `/team_stats` | Рейтинги команд: голы и броски за/против в среднем за игру с разницей, большинство, меньшинство, вбрасывания. |
| `/today` | Матчи прошедшей ночи по Москве (игровой день NHL = дата МСК − 1): нумерованная сводка и кнопки матчей с аббревиатурами команд. |
| `/tonight` | Сегодняшние игры (по календарю Москвы); в превью несыгранного матча премиум-чату (Задача 96) может быть строка «Оценка модели» — победа хозяев и тотал больше 5.5 (только когда у обеих команд ≥ 5 игр в сезоне). |
| `/standings` | Турнирная таблица сезона: места в дивизионах, гонка Wild Card с чертой плей-офф. |
| `/team` | Команды сезона по дивизионам; `/BOS`, `/WSH`… — статистика клуба (`team_profile()`), `/BOS_FULL` — все игроки клуба (`team_full_stats()`). |
| `/premium` | Статус премиума («Премиум до ДД.ММ» по МСК или «Премиума нет»), что он даёт и кнопка оплаты подпиской Telegram Stars: 100 ⭐ за 30 дней, продлевается сама (Задача 97). Оплата только в личном чате; в группе — текст без кнопки. При действующей подписке Stars кнопки нет, вместо неё — как отменить автопродление (Настройки Telegram → Stars → Подписки). |
| `/paysupport` | Куда писать по вопросам оплаты и возвратам (@karych_72); команда обязательна по правилам Telegram для Stars. |
| `/subscriptions` | Меню подписок одним сообщением: сводка, переключатели утреннего дайджеста и предстоящих матчей, команды (дивизион → команды), страны рейтинга `/countries`; каждое нажатие сразу пишется в БД (§7). |

Таблицы `/stats` (и его расширенной статистики) и `/team_stats` листаются по 10 строк; «« К списку»
возвращает меню, из которого открыта таблица, «Сохранить» оставляет страницу в чате и продолжает листание в копии ниже.

## 5. Типичные проблемы

| Симптом | Что проверить |
|---------|----------------|
| Бот не стартует | `TELEGRAM_BOT_TOKEN` (не пустой и валиден у @BotFather), доступ к сети, параметры `PG_*`. |
| `ConnectionRefusedError` к Postgres | Что PostgreSQL запущен, `PG_*` совпадают с тем, что использовал лоадер. |
| «Нет данных за сегодня» / пустые таблицы | Сделать загрузку: `make season-sync-month` (или нужное окно дат) — см. [`data_loading.md`](data_loading.md). |
| Лидерборды пустые | Проверить, что `SEASON_ID` в `.env` совпадает с `season_id` загруженных данных (`SELECT DISTINCT season_id FROM games`). |
| `Unknown` вместо имени игрока в карточке гола | Игрок отсутствует в `rosters` для этого `season_id`; будет добавлен на следующей загрузке через дополнение из landing-эндпоинта. |

## 7. Подписки и push (`bot_subscriptions`)

Модель данных и ограничения уникальности — в docstring
[`push_subscriptions.py`](../telegram_bot/push_subscriptions.py).

Создание таблицы (миграция `data_tables/migrations/0001_bot_subscriptions.up.sql`,
см. `DEVELOPMENT.md` § миграции):

```bash
make db-migrate
```

Поля: `chat_id`, `kind` (`morning_digest` | `team_scores` | `country_players` | `upcoming_games`),
`team_id` (для команды), `country` (код страны, только у `country_players`),
`last_sent_night` (игровая дата ночи, уже отправленной чату; пишется только у
`morning_digest`. Итог матча отмечается по паре (чат, матч) в `bot_chat_game_sent` — миграция
0014, Задача 85; превью `upcoming_games` — по паре (подписка, матч) в `bot_game_sent`, миграции
0009 и 0011),
`active`, временные метки (миграции `0005_digest_time`, Задача 60,
`0006_country_subscription`, Задача 61, и `0007_drop_digest_time`, Задача 63: времени
доставки у подписки нет). Согласие —
кнопки меню `/subscriptions` (Задача 63): главный экран показывает сводку и переключает
дайджест и «Предстоящие матчи» (Задача 78, `sub:u`; каждый переключатель в своём ряду, пункт
сводки «Предстоящие матчи» — только у включённой подписки), «Команды» ведут в дивизионы и их команды, «Страны» — в страны рейтинга `/countries`;
экраны меню — rich (Задача 91): подписки — список, когда приходят рассылки и подсказка
к кнопкам — подвал;
повторное нажатие выключает подписку. Каждое сообщение рассылки заканчивается строкой
«Настроить подписки: /subscriptions».

Рассылка: [`push_digest_job.py`](../telegram_bot/push_digest_job.py),
та же логика что `day_digest` / `dispatch_day_digest_messages`, как у `/today`. Включение: `ENABLE_PUSH_DIGEST=1`, паузы
`PUSH_SEND_INTERVAL_SEC`, обработка `429` и блокировки бота — см. исходники скрипта.

**Кэш клипов голов** (Задача 87): клип грузится в Telegram один раз — при первой отправке,
в рассылке итогов матча или по кнопке видео в карточке (`gv:<game_id>:<event_id>`,
`handle_goal_video`); `file_id` и подпись (`goal_caption`) пишутся в `bot_goal_clips` по
`(game_id, event_id)` (миграция 0013, `video_replay.cached_goal_clip` / `save_goal_clip`).
Дальше рассылка и кнопка шлют клип по `file_id`: без скачивания с NHL, ffmpeg и загрузки, кнопка
отвечает сразу. mp4 на VM не хранятся — временный файл удаляется сразу после загрузки. Кнопки
видео — у всех голов карточки: кэш заполняется лениво (решение человека 2026-10-27), и первое
нажатие на гол, которого ещё нет в кэше, ждёт загрузки (~50 с). `file_id` свой у каждого бота:
у dev- и прод-бота разные базы. Telegram отверг `file_id` из кэша — ошибка в логе и одна
повторная загрузка клипа, кэш получает новый `file_id`.

Это отдельный процесс, а не задача внутри бота: запускается сервисом `sync`
(`pipeline/scheduled_sync.py`, Задача 34, `docker-compose.yml`) после каждого ночного
прогона загрузчика (раз в 30 минут, 21:00–11:00 МСК), а днём, с 15:30 МСК, — по той же сетке без
загрузчика, и сам решает, пора ли (Задачи 60, 63, 78):

- **ночь** — игровая дата лиги, `night_of(now)` (момент минус 12 часов, UTC);
- **ночь загружена** — все матчи регулярки этой даты из `score/{date}` NHL API
  (`gameScheduleState = OK`; перенесённые не в счёт) уже есть в `games`. `scheduled_games`
  для этого не годится: идущий матч выпадает из неё раньше, чем попадает в `games`;
- **каждый матч — чату ровно один раз** (правило человека 2026-10-25, Задача 85): сколько бы
  подписок ни вело на матч (команда, страны, дайджест), итог приходит чату одним сообщением.
  Отметка — пара (чат, матч) в `bot_chat_game_sent` (миграция 0014; она же перенесла отметки
  прежнего кода — матчи страны из `bot_game_sent` и ночи команды и дайджеста по
  `last_sent_night`). Полный дайджест со всеми матчами — только по явной команде (`/today`,
  меню `/stats`);
- **итоги по матчу** (`team_scores`, `country_players`; Задачи 61, 64, 75, 76, 85) — строка
  подписки на пару (чат, команда) или (чат, страна); рассылка по матчу на каждом прогоне,
  первой: матч, где играет подписанная команда или игроки подписанной страны, уходит на первом
  прогоне после того, как попал в `games` (статус `OFF`, обычно 30–90 минут после сирены), когда
  NHL выложила клипы всех его голов (`highlightClip` в Replay API,
  `video_replay.goal_clip_published`); в 11:00 МСК — с тем, что есть. Матч, не попавший в
  `games` к 11:00 МСК, не уходит (следующий прогон — уже другая ночь). Первая строка сообщения —
  счёт матча (её видно в уведомлении); подвал — «По подписке: …» (подписки чата, которые ведут
  на матч: полные названия команд, затем страны) и «Настроить подписки: /subscriptions».
  Есть подписанная команда — полная карточка матча с кнопками видео голов, под ней блоки всех
  подписанных стран, чьи игроки играли. Только страны — счёт матча (первая строка карточки) и
  блоки стран с кнопкой «Карточка матча» (`dg:<game_id>`, полная карточка). В обоих случаях
  за сообщением — голы игроков подписанных стран альбомом, каждый клип один раз (у карточки
  команды — вдобавок к кнопкам); матч без таких голов — только текст.
  Альбом — не больше 10 клипов и 45 МБ загружаемых файлов (лимит Bot API — 50 МБ на запрос:
  альбом из 10 клипов по 8–19 МБ Telegram отверг); не влезающие клипы — следующими
  альбомами, одиночный — `send_video`. Клип из кэша клипов (ниже) уходит по `file_id` и
  бюджет не тратит. Отметка ставится после попытки: сбой матча логируется и не повторяется
  (в дайджест он тоже не попадает), остальные матчи уходят. Заблокировавший бота чат теряет
  все подписки. В блоке страны (Задача 64) у игрока две строки —
  фамилия и команда (пометка «ц» у центральных, «защ» у защитников), под ними статистика:
  у полевых голы+передачи, ±, броски, время; у нападающих ещё хиты, у центральных —
  вбрасывания «выигр./всего», у защитников блоки вместо хитов; у вратарей сейвы/броски, % и
  время. Тот же блок подписчик страны видит под полной карточкой матча (`send_game_card_message`:
  кнопки `/today`, `/tonight`, `/start game_<id>`), у остальных его нет;
- **дайджест** (`morning_digest`) — без времени у подписчика: уходит, как только ночь
  загружена; в 11:00 МСК (последний прогон) — в любом случае, с тем, что есть в БД, и без
  запроса к NHL API; если загрузчик на этом прогоне упал, рассылка не запускается и ночь не
  уходит. В нём — только матчи, итог которых чату ещё не ушёл; до 11:00 МСК не берётся и
  матч его подписок, ждущий клипов, — уйдёт своим сообщением, а в 11:00 МСК ждущие уже ушли
  и дайджест берёт остаток. Отфильтрованная сводка называется «Остальные матчи ночи»; все
  матчи уже ушли — дайджеста нет. Ночь без матчей в БД не рассылается. После попытки чату
  ставится `last_sent_night` — повторный прогон (в том числе догоняющий при рестарте
  `sync`) ту же ночь не шлёт;
- **`upcoming_games`** (Задача 78) — строка на чат; на каждом прогоне (днём — только она:
  `push_digest_job.py --upcoming-only`, с 12:30 UTC = 15:30 МСК, через полчаса после публикации прогноза) подписчику одно превью —
  ближайший по началу ещё не начавшийся матч дня, которого он не получал (решение человека
  2026-10-25: бот на виду весь день). Матчей больше, чем слотов до их начала, — начавшиеся
  пропускаются. До 15:30 МСК дня лиги (`UPCOMING_START_MSK`) превью нет: день лиги меняется
  в 03:00 ET, и утренние ночные слоты иначе слали бы матчи нового дня.
  Слейт и время начала — из `score/{день лиги}` NHL API, тем же разбором, что `/tonight`
  (`nhl_scoreboard.parse_start_utc`): в БД времени начала нет; перенесённые матчи не берутся.
  Превью — то же, что в `/tonight` (`matchup_season_preview`: сравнение команд; премиум-чату — и строка
  «Оценка модели (не совет)» в подвале, если прогноз опубликован; публикация — 12:00 UTC) под
  первой строкой «⏰ Начало в HH:MM МСК»; собирается раз на матч в прогоне и без прогноза — его
  строка дописывается при отправке каждому чату (Задача 96). Отметка — по паре
  (подписка, матч) в `bot_game_sent`, ставится после попытки: сбой отправки не повторяется,
  следующий прогон шлёт следующий матч; перенесённый матч с новым `startTimeUTC` второй раз
  не уходит. Прогон без матчей ничего не шлёт. Ночью итоги по матчу, дайджест и превью
  независимы: сбой одной рассылки логируется и не срывает следующие, после всех ошибка
  пробрасывается — прогон красный.

Скрипт поднимает свой `Application` (без polling и без `JobQueue`),
рассылает и завершается, поэтому запускать его можно и при выключенном боте. Поведение
закреплено в `tests/test_push_digest_job.py`.

```bash
cd telegram_bot && ENABLE_PUSH_DIGEST=1 ../.venv/bin/python push_digest_job.py
```

## 8. Свободный текст (Задача 81)

Сообщение в личке, которое не команда и не ввод даты в `/stats`, бот отдаёт модели
`claude-sonnet-5-5` (`telegram_bot/ai_router.py`). Модель выбирает один из уже существующих
экранов — дайджест ночи или даты, матчи сегодня, таблицу, список команд, профиль клуба (игрок →
ответ по статистике, Задача 83), лидеров, игроков страны, расширенную метрику,
подписки, справку — и бот показывает его тем же кодом и с теми же кнопками, что команда.
Цифр модель не пишет. Вопрос вне возможностей — короткий отказ со ссылкой на `/help`,
неоднозначный — одно уточнение. В группах бот на текст не отвечает.

- **Лимит (Задача 96):** премиум-чату — 20 вопросов в сутки по МСК; бесплатному — 3 в
  календарную неделю МСК (пн–вс) и не больше 8 за всё время, включая вопросы до выкатки 96.
  Сбой API вопрос не списывает. Сверх лимита модель не вызывается, ответ — «на сегодня лимит
  вопросов исчерпан» (премиум), «бесплатные вопросы на этой неделе закончились, новые — в
  понедельник» или «бесплатные вопросы закончились» (к оплате до Задачи 97 не зовёт).
- **Премиум** — строка `premium_access` (чат и срок, миграция 0016), проверка —
  `premium.is_premium`; выдаётся вручную SQL-ом (`DEVELOPMENT.md` §«Миграции»), на `chat_id`, как
  подписки: группа с премиумом видит прогноз всем участникам. Премиум даёт и строку прогноза в
  превью (`/tonight` и рассылка).
- **Оплата премиума (Задача 97):** `/premium` создаёт ссылку `createInvoiceLink` (`XTR`, 100 ⭐,
  `subscription_period` 2592000 с, без `provider_token`). `pre_checkout_query` бот подтверждает сразу,
  без БД. `successful_payment` (первый платёж и каждое автопродление) вызывает `premium.extend_premium`:
  в одной транзакции пишет строку журнала `premium_payments` (миграция 0017; `telegram_payment_charge_id`
  уникален — повтор события срок не меняет) и ставит `premium_access.expires_at = max(текущий, now) + 30 дней`.
  Ответ — «Премиум до ДД.ММ». Сбой записи логируется с `charge_id`, `chat_id` и суммой (деньги списаны,
  выдать надо вручную) и пробрасывается. Возврат — CLI `premium.py refund` (`DEVELOPMENT.md`);
  события `refunded_payment` бот не обрабатывает.
- **Журнал:** строка `ai_questions` на каждый вызов модели — вопрос, экран и параметры или
  текст ответа, токены, стоимость, задержка, `request_id`, ошибка. По нему видно, каких
  вопросов бот не покрывает:
  `SELECT question, answer FROM ai_questions WHERE outcome = 'text' ORDER BY asked_at DESC`.
- **Сбой API** (таймаут, 5xx, нет баланса) — «не удалось разобрать вопрос, попробуйте
  командой: /help» и строка журнала с `outcome = 'error'`.
- **Контрольный набор** — `make ai-eval` (настоящий API, стоит денег, нужен ключ): фразы
  `scripts/ai_router_eval.jsonl` с ожидаемым экраном или передачей ответам по статистике. Порог — 90% совпадений.

### Вопросы по статистике (Задача 83)

Вопросы без готового экрана — «сколько Овечкин забил Коламбусу в 2024/25», «как играет
Кучеров» — отвечает `telegram_bot/ai_stats.py`: модель сама пишет SELECT по нашей БД (или
берёт готовый обзор игрока), бот выполняет его ролью только на чтение, отдельный вызов-ревьюер
сверяет черновик с результатом. Прошёл ревью — ответ уходит. Вопрос неоднозначен — пользователю
вопрос ревьюера («Вы про Джека Хьюза или про Люка Хьюза?»). Вопрос однозначен, а черновик ошибочен
— модель получает замечание и один раз переделывает ответ; второй отказ — «Не удалось ответить
точно — попробуйте переформулировать вопрос». Не прошедший ревью черновик пользователю не
показывается. В данных только
регулярка с сезона 2021/22: «за карьеру» бот не считает, а называет рамку.

- **Доступ — всем в пределах лимита** (решение человека 2026-10-29: бесплатный вопрос — весь
  конвейер). Маршрутизатор получает инструмент `stats_question`: вопрос о конкретном игроке
  (цифры, форма, просто имя) идёт сюда, в обзор игрока, а не на экран клуба; таблица всех
  игроков клуба («все игроки Бостона») по-прежнему открывает экран клуба.
- **Продолжение диалога.** Пока с последнего ответа этой функции прошло меньше 30 минут,
  сообщение сразу идёт в неё (без маршрутизатора), в запрос — последние 3 пары «вопрос–SQL–ответ»;
  модель сама решает, продолжение это или новый вопрос. Ответ на уточнение — всегда продолжение.
  Позже 30 минут история не передаётся.
- **Лимит.** Один вопрос — одна единица общего лимита (раздел выше), продолжение диалога
  тоже; сбой не списывает. На вопрос — не больше 4 SQL-попыток, 7 вызовов модели и $0.10; сверх этого —
  «Не удалось ответить, уточните вопрос». Сбой API или БД — «попробуйте командой: /help».
- **Журнал.** `ai_stats_log`: вопрос, исход (`answer` / `clarify` / `no_data` / `off_topic` /
  `ceiling` / `rejected` / `error`), SQL и число строк каждого шага, черновик, вердикт и причина, стоимость
  по вызовам. Непокрытые вопросы:
  `SELECT question, answer FROM ai_stats_log WHERE outcome IN ('no_data', 'ceiling') ORDER BY asked_at DESC`.
- **Контрольный набор** — `make ai-stats-eval` (настоящие API и БД, стоит денег): 40+ вопросов
  `scripts/ai_stats_eval.jsonl`; порог — 90% верных и ни одной неверной цифры в ответе,
  прошедшем ревью.

## 9. Стиль сообщений (Задача 88)

Экраны бота — rich-сообщения (Bot API 10.1+), их собирает `bot_messages.rich_message()` из
построчного HTML. Правила — для любого нового экрана и для доводки старых (Задачи 89–91).
Одна мысль: **содержание — крупно, всё остальное — тише**. Как клиенты рисуют теги, проверено
spike 2026-10-27 на iOS и Desktop (`plan/rich_messages/README.md` §«Spike Задачи 88»).

1. **Один акцент на сообщение.** Заголовок — строка `<b>`. `<h1>`–`<h6>` не используем: клиенты
   рисуют их шрифтом с засечками, крупнее текста и с большим отступом — даже `<h6>`.
2. **Абзац — смысловой блок.** Строки подряд — один абзац (`<br>` между ними), пустая строка —
   граница абзацев с зазором в строку (`<p>&nbsp;</p>`: граница `<p>` сама отступа не даёт,
   пустой `<p></p>` схлопывается). Тег не пересекает пустую строку — иначе Telegram отвергнет
   сообщение.
3. **Вторичное — в подвал.** Ссылки на настройки и соседние экраны, сезон, «данные на …»,
   маркер страницы «Показаны N из M» — последняя строка текста `rich_footer()`: `<footer>`,
   мельче и серее текста. Заголовок экрана — без сезона в скобках.
4. **Справочное — свёрнуто.** Легенды и расшифровки метрик — `rich_details("Обозначения", …)`
   (`<details>`): по умолчанию свёрнут на всех клиентах; `open` не ставим. Перечень команд
   `/help` — список `rich_list()` (`<ul>`).
5. **Эмодзи — только как метка.** Не больше одного — в начале сообщения или строки счёта
   (🏒, ⏰); в теле и в ячейках таблиц — нет. Ревизия Задачи 90: 🔔 и 🤖 сняты, звёзды матча
   нумеруются «1.» вместо «★1», флаги стран — только на кнопках и в заголовке экрана страны;
   ▶ на кнопках видео остаётся (кнопки не rich, правило 8).
6. **Таблицы спокойные.** `_table()`: `compact`, без `bordered`; полосы (`striped`) — только у
   таблиц длиннее 10 строк. Жирным в таблице — только то, на что экран отвечает, не больше
   одного на строку (`_table(..., bold=…)`; в превью матча — лучшее значение метрики).
   Прокрутки внутри сообщения у таблицы нет: длинная растягивает сообщение.
7. **Без линий и украшений.** `<hr/>` не используем; разделы делит заголовок или пустая строка.
   Кнопки в тексте (`<tg-button>`) — вне стиля, клавиатура остаётся под сообщением.
8. **Rich там, где он есть.** Всплывающие ответы на нажатие (`callback.answer`), подписи к видео
   и альбомам, меню команд Telegram rich не поддерживают — остаются обычным текстом, это не долг.
   Всё остальное — rich, включая служебные ответы (ошибки, «Видео пока недоступно», ссылка на
   уже открытую карточку `/tonight`) и ответы ИИ (Задача 91): служебный ответ — одна строка без
   заголовка и акцента, текст модели экранируется (`html.escape`). Клиент без rich не покажет
   и экраны, поэтому обычный текст ошибки его не спасает.
9. **Команда — полным названием.** В тексте экранов, `/standings`, превью матча и подписи к
   видео — `teams.name` («Minnesota Wild»), не код и не прозвище `short_name` (Задача 98,
   решения человека 2026-10-29 и 2026-10-31). Коды остаются в таблицах лидеров (`/stats`,
   `/team_stats`, `/countries`), звёздах матча, кнопках (подписка, `/today`, `/tonight`),
   всплывающих ответах и командах `/BOS`, `/BOS_FULL`.
