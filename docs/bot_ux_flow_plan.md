# План UX и пользовательского потока NHL Telegram-бота

Документ фиксирует рекомендации по приоритету данных, сценариям входа в бота и подаче текста. **Изменения в коде не предполагаются** — это ориентир для следующих итераций.

---

## 1. Контекст и боль

Сейчас доминирует один вход — команда `/stats` — и длинные цепочки **inline-кнопок**. Побочные эффекты:

- **«В главное меню»** вызывает `edit_message_text`: последнее сообщение **перезаписывается**, пользователь теряет уже показанный результат (неудобно для сверки и пересылки).
- Текст **«Нет, с меня хватит ...»** звучит раздражённо; для выхода из сценария лучше нейтральные формулировки («Закрыть», «Готово», «В начало»).
- Сообщение «Запустите обработчик, выберите маршрут» — техническое; не объясняет, **что** пользователь получит.
- Лидерборды рендерятся в одном блоке кода (шаблон `season_leaders_players.txt`): в Telegram это **моноширинный блок**, который на телефоне часто выглядит громоздко и нечитабельно по сравнению с обычным текстом и короткими строками.

В БД уже есть богатый слой: игры, голы (в т.ч. для видео), бокскор по игрокам/вратарям/командам, сезонная статистика скейтеров и вратарей, advanced (`players_advanced_stats`), типы бросков (`players_shot_types`), турнирная картина (`teams_stats`). В UI бота явно не задействованы, например, **таблица лиги целиком** (`team_table()` в коде) и **shot types**.

## 2. Какие данные наиболее и наименее интересны пользователям

Оценка — для **типичного** пользователя спортивного бота (болельщик, не аналитик). «Интерес» = частота желания открыть + ширина аудитории.

### 2.1. Высокий интерес (ядро продукта)

| Актив | Почему |
|--------|--------|
| **Итоги недавних игр / «день хоккея»** | Естественный ежедневный триггер: счёт, голы, кто забил, вратари. Уже близко к текущему «статистика дня». |
| **Турнирная таблица / место команды** | Вопрос №1 в сезоне: «кто где в стендингах». Данные есть (`team_table()`), в текущем меню не выведены. |
| **Топ бомбардиров и снайперов** | Узнаваемые имена, простая метрика (очки, голы). |
| **Топ вратарей по победам и % сейвов** (в разумных оговорках по игровому времени) | Популярные разговоры вокруг лиги. |

### 2.2. Средний интерес (полезно, но реже)

| Актив | Почему |
|--------|--------|
| **Ассистенты, +/-** | Интересно фанатам и тем, кто уже смотрит статистику игроков. |
| **Спецбригады команд (PP%, PK%)** | Важно для понимания силы команды, но не каждый день. |
| **Детальный разбор одной игры** (броски, ПИМ, события) | После просмотра матча или спора «кто как отыграл». |

### 2.3. Ниже среднего / нишевый интерес

| Актив | Почему |
|--------|--------|
| **SAT% / USAT% / GF% / OZ Start%** | Сильные метрики для аналитиков; для массового пользователя нужны пояснения и фильтры (например, минимум игр), иначе шум. |
| **Лидеры по хитам, блокам, среднему времени на льду** | Полезно узким группам (фантази-лиги, хардкор); не «первый экран». |
| **Shootout %** | Мало событий, нестабильная метрика, слабый storytelling для большинства. |
| **Типы бросков по игрокам** (`players_shot_types`) | Интересно скаутам и любителям стиля игры; требует аккуратной визуализации и контекста. |

### 2.4. Итог по приоритизации контента

1. **Сначала** — дайджест дня / последние результаты и **стендинги**.  
2. **Затем** — простые лидерборды (очки, голы, ключевые вратарские показатели).  
3. **Командные спецпоказатели и детализация матча** — второй уровень.  
4. **Advanced и второстепенные лидерборды** — отдельный режим («Ещё статистика» / команда `/advanced` или ссылка внизу), без обязательного прохождения через десяток кнопок.

## 3. Рекомендуемый пользовательский flow

Идея: **меньше обязательных кликов на старте**, больше **прямых команд** и **короткого текста-подсказки** при `/start`. Кнопки оставить там, где выбор действительно вариативен (дата, команда, тип лидерборда).

### 3.1. Точки входа (вместо одной `/stats`)

| Вход | Назначение |
|------|------------|
| `/start` или `/help` | 5–7 строк: что умеет бот + **список команд** (не одна кнопка «статистика»). |
| `/today` или `/day` | Сразу дайджест за последний день с данными в БД (текущая логика «статистика дня»). |
| `/standings` или `/table` | Турнирная таблица по дивизионам (уже есть генерация текста). |
| `/leaders` | Краткое меню или один экран с **топ-3** по очкам и голам + кнопка «полный топ-10». |
| `/game <id>` или ответ на сообщение с матчем | Если позже появится привязка к `game_id` из дайджеста — быстрый повтор деталей. |
| `/stats` (опционально) | Сводное меню для тех, кто привык к кнопкам — не единственный путь. |

Так пользователь, который хочет «что было вчера», делает **один шаг**, а не три уровня кнопок.

### 3.2. Иерархия после входа

1. **Первый ответ** — компактный текст (см. раздел 4), при необходимости **одна** строка кнопок (например: «Другой день», «Таблица», «Лидеры»).  
2. **Углубление** — либо команда, либо inline-кнопки, но без перезаписи полезного сообщения при возврате «назад» (новое сообщение или отдельное «меню»).  
3. **Выход** — нейтральная кнопка или команда `/cancel`; не стирать историю диалога смыслом «с меня хватит».

### 3.3. Поведение «назад» и «главное меню»

- **Не использовать** `edit_message_text` для возврата в корень, если текущее сообщение — ценный контент (статистика матча, топ игроков). Предпочтительно: **новое сообщение** с меню или **reply-клавиатура** с постоянными пунктами (по желанию продукта).  
- Если редактирование оставляют только для «чистого» навигационного сообщения — явно отделить **карточку результата** от **панели навигации** (два сообщения).

### 3.4. Дайджест дня и видео голов

- Сохранить ценность «гол + кнопка видео», но сгруппировать: заголовок дня одной строкой, затем **короткие блоки по матчам** без избыточного дублирования.  
- Для многих матчей — подумать о **сводке в одном сообщении** + «развернуть матч» кнопкой, чтобы не заспамить чат (ограничение Telegram на длину сообщения — учитывать).

## 4. Рекомендации по подаче текста

### 4.1. Формат

- **Избегать** больших блоков ` ``` ` для табличных данных, если цель — читабельность в мобильном клиенте. Предпочтительно: обычный текст, **фиксированные короткие колонки** через пробелы/табличные символы умеренно, или **нумерованный список**:  
  `1. Имя Фамилия — 42 очка (TOR)`  
- Заголовок секции — одна строка с **жирным** или капсом умеренно; не дублировать одно и то же в названии кнопки и в первой строке текста без добавления смысла.  
- Для игр: шапка (`Команда А — Команда Б, 4:2 (ОТ)`), затем голы списком, затем одна строка «броски / ПИМ / вратари».

### 4.2. Длина и структура

- **Лидерборды:** топ **5** в основном сообщении, «ещё 5» — вторым сообщением или по кнопке.  
- **Таблица лиги:** уже разбита по дивизионам в шаблоне — сохранить; в начале — одна строка сезона и даты актуальности данных.  
- Язык интерфейса — единый (сейчас смесь RU/EN в `end()`); для RU-аудитории лучше **везде русский**, английские аббревиатуры команд NHL оставить как есть.

### 4.3. Markdown

- Экранировать спецсимволы или перейти на ограниченный набор разметки, чтобы не ломать `parse_mode`.  
- Не полагаться на моноширинный шрифт как на «таблицу» — в разных клиентах ширина разная.

### 4.4. Микрокопирайтинг

- Вместо «Нет, с меня хватит»: «**Готово**», «**Закрыть меню**», «**В начало**».  
- Вместо «Запустите обработчик»: «**Что посмотреть?** Ниже кнопки или команды: …».  
- Подсказка внизу: «Быстрый ввод: `/today` — матчи дня, `/table` — таблица».

## 5. Сводная матрица: данные → рекомендуемая позиция в flow

| Данные / функция | Где в flow | Примечание |
|------------------|------------|------------|
| Игры за день + голы + видео | Первый экран (`/today`) | Ядро |
| `team_table()` | Первый или второй экран (`/table`) | Уже в коде, не в меню |
| Очки / голы топ-10 | `/leaders` или после одной кнопки | Упростить шаблон |
| Вратари: победы, SV% | Рядом с лидерами полевых | Меньше кликов |
| PP%, PK%, % очков | «Команды» / `/teams` | После таблицы логично |
| Хиты, блоки, ПИМ, TOI | «Дополнительно» | Свернуто |
| Advanced метрики | `/advanced` или подменю | С пояснением в одну строку |
| `players_shot_types` | Опционально, позже | Нужен UX-концепт |
| Поиск игрока / команды | Идея на будущее | Сильно снижает трение |

## 6. Следующие шаги (когда будете внедрять)

1. Зафиксировать **список команд** и их тексты в `help`.  
2. Подключить **турнирную таблицу** к отдельной команде и решить, остаётся ли глубокое дерево `/stats`.  
3. Пересмотреть **шаблоны лидеров** (убрать зависимость от code-block как основного вида).  
4. Заменить навигацию «назад» так, чтобы **не затирать** контентные сообщения.  
5. Пройтись по **копирайту** кнопок и сообщениям об ошибках на одном тоне (дружелюбный нейтральный).

Этого достаточно, чтобы направить рефакторинг бота без расширения объёма данных: значимая часть улучшений — **композиция уже загруженных таблиц** и **смена паттернов Telegram UI**.
