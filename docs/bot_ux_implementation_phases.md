# Фазы внедрения UX-флоу бота

Документ фиксирует план реализации по [`bot_ux_flow_plan.md`](bot_ux_flow_plan.md), согласованный с текущим кодом (`telegram_bot/`). Исходная валидация: единый вход `/stats`, `team_table()` без меню, лидеры в code-block шаблонах, навигация через `edit_message_text`, копирайт и отсутствие `/start`, `/help`, `/today`, `/table`, `/leaders`.

---

## Фаза 1 — Команды и help

Низкий риск, высокий эффект.

| Шаг | Действие | Где |
|-----|----------|-----|
| 1.1 | Добавить `CommandHandler` для `/start` и `/help`: короткий текст + список команд (`/today`, `/table`, `/leaders`, `/stats`, при необходимости `/cancel`). | `bot.py` + константы строк или маленький модуль |
| 1.2 | Реализовать `/today` (и при желании алиас `/day`): вызов `day_digest()` и рассылка сообщений по той же логике, что в `bot_day_digest`, без обязательного входа через `/stats`. | `bot.py` + вынести общую функцию из логики `bot_day_digest` в `stats_handlers` или `script_bot`, чтобы не дублировать цикл по играм |
| 1.3 | Реализовать `/standings` или `/table`: `team_table()` → `reply_text` / `send_message` с нужным `parse_mode`. | `bot.py`; при необходимости — первая строка `league_table.txt` (сезон, дата актуальности из `config` / `max(day)`). |
| 1.4 | Реализовать `/leaders`: компактный экран (например топ-5 по очкам и голам) + опционально кнопка «Топ-10» отдельным сообщением. | `bot_messages.py` (обёртка) + `bot.py` / handler |

**Зависимость:** `ConversationHandler` не должен «съедать» эти команды — регистрировать обработчики выше conv или в другом `group`, либо расширить `entry_points` / `fallbacks` по правилам python-telegram-bot.

## Фаза 2 — Навигация без потери контента

| Шаг | Действие | Где |
|-----|----------|-----|
| 2.1 | «В главное меню» / «Назад»: на контентных сообщениях вместо `edit_message_text` — `send_message` с меню (как в `stats()`), состояние conv → `FIRST`. | `stats_handlers.py` (`_make_stats_handler`, `bot_day_digest`), `script_bot.stats_over` |
| 2.2 | Первое сообщение дайджеста: сейчас первый матч заменяет сообщение с кнопками меню; либо всегда слать дайджест новыми сообщениями, либо явно разделить «панель навигации» и «карточку результата» (два сообщения). | `bot_day_digest` |
| 2.3 | `CommandHandler('cancel', ...)` в `fallbacks` с `ConversationHandler.END` и текстом на русском. | `bot.py` |

## Фаза 3 — Шаблоны и копирайт

| Шаг | Действие | Где |
|-----|----------|-----|
| 3.1 | Лидерборды: уйти от основного вида в моноширинном code-block к списку строк (обновить `season_leaders_players.txt`; по желанию `team_stats.txt`). | `telegram_bot/messages/*.txt`, форматирование в `player_stats` / `team_stats` в `bot_messages.py` |
| 3.2 | Подписи кнопок: «Готово» / «В начало» / «Закрыть меню»; `end()` на русский; убрать «Нет, с меня хватит». | `stats_handlers.py`, `script_bot.py` |
| 3.3 | Заменить «Запустите обработчик…» на пользовательскую формулировку из UX-плана. | `script_bot.stats` |

## Фаза 4 — Углубление продукта (после ядра)

| Шаг | Действие | Где |
|-----|----------|-----|
| 4.1 | Много матчей в день: сводка в одном сообщении + кнопка «развернуть матч» (лимит 4096 символов Telegram). | `bot_messages.day_digest` / новый шаблон + callback с `game_id` |
| 4.2 | `/game <id>` или deep-link с `game_id` из дайджеста. | `bot.py`, разбор аргументов, `game_message` |
| 4.3 | «Ещё статистика» / `/advanced`: SAT/USAT/GF% и т.д. в подменю или отдельная команда. | `script_bot.py`, `dialog_states`, `bot.py` |
| 4.4 | `players_shot_types` в UI — отдельный мини-проект (шаблон + handler); в `bot_messages.py` уже есть задел под SQL. | новые шаблоны + handlers |

## Тесты

Расширить `tests/test_skater_reports_bot.py` или добавить тесты на текст help, регистрацию команд и моки для `team_table` / `day_digest` по существующему паттерну работы с БД.

## Порядок по продукту

Фазы **1–3** закрывают композицию уже загруженных данных и смену паттернов Telegram UI. Фаза **4** — сжатый дайджест, детальный матч, advanced и shot types (как в матрице UX-документа).
