### Задача 33. Переход на сезон 2026/27 ✅ 🔴
Идентификатор сезона сейчас задаётся в четырёх независимых местах, и три из них — зашитые
дефолты прошлого сезона: `.env` (`SEASON_ID`/`SEASON`/`CURRENT_SEASON`),
`telegram_bot/config.py:69-70` (`20252026`, `"25/26"`), `Makefile:50`
(`SEASON_START ?= 2025-10-01`). В БД пять сезонов, последний день — `2026-04-16`;
за 2026/27 нет ничего.

Область: `.env.example`, `telegram_bot/config.py`, `Makefile`.
Приёмка: сезон задаётся в одном месте, остальные читают оттуда; сезон 2026/27 загружен
в БД после первых игр; `make ci-local` зелёный. Старые дефолты удалить, а не оставить
рядом с новыми (Global Constraint 3).

Кодовая часть выполнена в ветке `sdd-task-33-season` (PR #36): сезон сведён к одному
источнику `SEASON_ID` — подпись сезона и дата старта полной перезагрузки выводятся из
него в `telegram_bot/config.py` (`derive_season()`), дефолтов в коде не осталось,
отсутствие `SEASON_ID` валит старт и бота, и лоадера явной проверкой. Задача остаётся
открытой до шага 6: после первых игр регулярки 2026/27 — `SEASON_ID=20262027` в `.env`,
`make season-load-full`, проверка `SELECT season_id, count(*) FROM games GROUP BY 1`.

Шаг 6 выполнен 2026-09-30 (ветка `sdd-task-33-season-load`, PR #51): `make season-load-full`
с `SEASON_ID=20262027` загрузил окно 2026-09-01…09-30 — `games` по сезону 20262027: 5 строк,
все за 2026-09-29 (сверено с расписанием NHL API: 2026020001–0005, `OFF`); прошлые пять
сезонов не тронуты (по 1312). Первый прогон упал на `relation "scheduled_games" does not
exist` и откатился целиком: на живую БД не были накатаны миграции 0003/0004 (Задача 22) —
применены `make db-migrate`, после чего прогон прошёл. Экраны проверены вызовом тех же
функций на живой БД: `/table` — «сезон 26/27, данные на 2026-09-29», 10 сыгравших команд;
дайджест по умолчанию — 2026-09-29, 5 матчей; `/tonight` — 3 игры 2026-09-30 сезона
20262027, превью кнопок для ещё не игравших команд отвечает «нет в базе бота для этого
сезона». `teams` сезона содержит только сыгравшие команды (10 из 32), поэтому
`scheduled_games` (окно сегодня+завтра UTC) получил 1 игру — 2026020015 на 2026-10-01;
остальные, включая все 3 игры 2026-09-30, пропущены с warning, как задумано в
`replace_scheduled_games`; дополнится по мере первых игр каждой команды.

### Задача 35. Площадка, живучесть, бэкап ✅ 🔴
В `docker-compose.yml` нет `restart:`; бэкапа тома `pgdata` нет, а данные в этом проекте
уже терялись однажды. Контейнер `nhl_bot-db-1` поднят до Задачи 20 и по-прежнему публикует
`0.0.0.0:5432` — правка loopback есть в файле, но не в работающем контейнере.

Область: `docker-compose.yml`, `DEVELOPMENT.md`.
Приёмка: `restart: unless-stopped` у сервисов; `pg_dump` по расписанию, восстановление
проверено один раз на одноразовой БД; контейнер `db` пересоздан и слушает только
`127.0.0.1:5432` (доказательство — вывод `docker ps`); процедура развёртывания описана
в `DEVELOPMENT.md`.

Выполнена в ветке `sdd-task-35-backup` (PR #39, 2026-09-28), живая проверка: `docker ps` —
`nhl_bot-db-1` и `nhl_bot-backup-1` оба `Up (healthy)`, `db` на `127.0.0.1:5432`,
`docker inspect` — у обоих `RestartPolicy.Name: unless-stopped`. `db` пересоздан
(`--force-recreate`), том `nhl_bot_pgdata` сохранён: `games` 6560 / `rosters` 5380 /
`game_player_stats` 236101 до и после совпали. Первый дамп `nhl_20260928T173757Z.dump`
(5.1 МБ) в `BACKUP_DIR`; восстановление на одноразовой `nhl_check` по командам
`DEVELOPMENT.md` — `pg_restore` rc=0, `COUNT_QUERY` по 15 таблицам идентичен источнику,
`nhl_check` удалена. Не проверено: перезапуск Docker Desktop/хоста и ответ бота — живьём
подняты только `db`+`backup`, `bot`/`sync` не запускались.

### Задача 36. Поведение на пустом и частичном сезоне ✅ 🔴
Сценарий «сезон начался, сыграно 0–3 тура» не проверялся ни разу: все пять загруженных
сезонов в БД полные.

Область: `telegram_bot/`, `tests/`.
Приёмка: тесты на сезон с 0 и с 1–3 игровыми днями для `/table`, `/leaders`, `/day_games`,
`/game`, `/advanced`; ни одного необработанного исключения; пустой ответ несёт текст
с причиной, а не пустую таблицу.

Выполнена в ветке `sdd-task-36-empty-season` (PR #44, 2026-09-28). Шаг 1
карточки (что пишет загрузчик в пустой сезон) прогнан по-настоящему: `season-load-full`
для `SEASON_ID=20262027` на скретч-БД (`nhl_task36_scratch`, тот же контейнер `nhl_bot-db-1`,
удалена после прогона) при 0 сыгранных играх лиги (2026-09-28, до старта регулярки) пишет
**0 строк во все таблицы без исключения** — не только `games`, но и `teams`/`teams_stats`/
`rosters`/`players_season_stats`: `build_teams_and_stats()` строит их из агрегата
`team/summary` по уже сыгранным играм, а `build_rosters()` идёт только по командам из этого
же списка (`pipeline/load_season_modern.py:263-338`). Фикстуры «0 игровых дней» в тестах —
пустой ответ на любой запрос, это и есть факт, а не гипотеза. «1–3 игровых дня» на живом
API получить нельзя (сезон 2026/27 на дату работы ещё не начался) — фикстура построена по
тому же факту: команда без единой игры отсутствует в `teams_stats`/`rosters` целиком, а не
приходит строкой с нулями. Найден и исправлен реальный дефект: `team_table()` (`/table`) на
пустом `teams_stats` рендерила таблицу-скелет (заголовки конференций/дивизионов без единой
строки, без текста-причины) — добавлена явная ветка с текстом «Сезон ещё не начался: в базе
нет статистики команд.». Тот же дефект на уровне одного дивизиона (частичный сезон: у
дивизиона нет ни одной сыгравшей команды) нашло финальное ревью — правка того же рода:
дивизион без строк несёт «(в дивизионе ещё никто не сыграл)» вместо заголовков пустой
таблицы (`_build_standings_table_body`). Остальные четыре команды уже несли текст-причину до этой задачи
(`bot_messages.py:975/1354` — лидеры, `:1388/1400` — дайджест, `send_game_card_message` —
матч не найден) — для них добавлены тесты, подтверждающие поведение на обоих состояниях,
без правок кода. 10 новых тестов (5 команд × 2 состояния) в `tests/test_bot_integration.py`
по той же схеме, что и остальные сценарии файла (`fake_db_router`). `make ci-local`: 576
passed + 39 subtests (было 566 до задачи). `make all-tests` — на живой БД `nhl_bot-db-1`
(вне scope задачи, не тронута): зелёный, 10/10 (7 пропущены — нет `RUN_DB_DATA_TESTS=1`).

### Задача 62. Национальность у игроков, добранных из сводных отчётов ✅ 🟡
Найдено в Задаче 61. `supplement_rosters_from_reports` (`pipeline/load_season_modern.py`)
добавляет в `rosters` игроков из сводных отчётов `skater/summary` и `goalie/summary`,

отчётов). **Решение человека 2026-10-08:** страна — `nationalityCode` из отчётов
`skater/bios` и `goalie/bios` у всех игроков (не только у добранных), `birthCountry` больше
не читается; прошлые сезоны перезаписать. Меняется у ~2% игроков (24 из 1038 в 2025/26).

**Найдено по ходу, чинится здесь по решению человека:** stats REST API режет страницу ниже
`limit` (100 строк у отчётов полевых, 1000 у `game`), а без явного `sort` порядок между

2021/22–2026/27 (`--season-id`, окно в один день: агрегаты и `rosters` пишутся целиком). У
