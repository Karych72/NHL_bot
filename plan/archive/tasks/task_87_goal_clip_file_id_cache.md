# Задача 87. Видео голов: кэш `file_id` в БД вместо скачивания на каждое нажатие

**Блок:** продукт · **Надобность:** 🟡
**Область:** `telegram_bot/push_digest_job.py` (`_ClipCache`, `_prepare_goal_clips`,
`_send_country_game`), `telegram_bot/stats_handlers.py` (`handle_goal_video`, `goal_video_markup`),
`telegram_bot/video_replay.py`, новая миграция в `data_tables/`, тесты видео и рассылок,
`docs/telegram_bot.md`.
**Зависит от:** — . Задача 85 идёт после этой (рекомендуемый порядок: обе правят
`push_digest_job.py`).
**Источник:** решения человека 2026-10-25 по видео голов, принятые при разборе Задачи 85
(PR #110); вынесены из её карточки в отдельную задачу 2026-10-27 по просьбе человека.
Реестр — [`../open_tasks.md`](../closed_tasks.md).

## Кратко

Клип гола загружается в Telegram один раз; его `file_id` и подпись хранятся в БД, а рассылки
и кнопка видео в карточке шлют клип по `file_id` — без повторного скачивания с NHL, ffmpeg
и загрузки.

## Зачем и на что влияет

- Кнопка видео в карточке (`handle_goal_video`) сейчас на каждое нажатие качает клип с NHL,
  прогоняет через ffmpeg и заливает в Telegram (~13 МБ, замер 2026-10-25: 720p, 43–57 с,
  11.7–15.1 МБ на гол) — пользователь ждёт, VM гоняет трафик.
- В рассылке `file_id` кэшируется только на один прогон (`_ClipCache`): следующий прогон и
  кнопки в карточке грузят тот же клип заново.
- После Задачи 85 одно сообщение о матче несёт клипы для нескольких подписок — общий кэш
  делает это дёшево.

## Степень важности

🟡: качество и стоимость; дефекта, который видно в продукте, нет — кроме ожидания на кнопке.

## Подробно

**Решения человека 2026-10-25:**
1. **Кэш `file_id`, а не mp4 на диске.** Ключ — `(game_id, event_id)`, хранится `file_id`
   и подпись (`goal_caption`). mp4 на VM не хранятся: временный файл удаляется сразу после
   загрузки. Почему не диск: файл с диска всё равно заливается в Telegram при каждой отправке
   (ночь — ~0.7–1.2 ГБ), а `file_id` отправляется мгновенно и живёт дольше дня. `file_id`
   у dev- и прод-бота свои — каждый грузит клипы сам (у ботов разные базы, Задача 80).
2. **Оба пути на общий кэш:** рассылки (`_ClipCache` удаляется, GC3) и `handle_goal_video`.
3. **`/today` и меню `/stats` показывают матч сразу после конца**, не дожидаясь клипов;
   кнопки видео — только у голов, клип которых уже в кэше.
4. **Крайний срок 11:00 МСК** (Задача 85): матч уходит в рассылку с тем, что есть; у гола без
   клипа кнопки видео нет.

**Решить в начале задачи:**
- Кто заполняет кэш: прогон рассылки по ходу отправки или отдельный шаг sync «загрузить клипы
  закончившихся матчей» (тогда кнопки в `/today` появятся и у тех, кто не подписан).
- Куда загружать клип, чтобы получить `file_id` до первой отправки пользователю: служебный чат
  бота или первая реальная отправка. Служебный чат — новый параметр `.env`, нужен только если
  кэш заполняется заранее.

**Подводные камни.**
- `file_id` протух (Telegram отверг) — громкая ошибка в логе и перезагрузка клипа один раз,
  а не тихий пропуск (GC4: реакция осмысленная — клип есть у NHL).
- Миграция сначала на `nhl_dev`, на прод — мержем в `master`.
- Бюджет GC6: оценка ~100–150 строк с тестами.

**Критерии приёмки.**
- Тесты на БД: второй запрос того же гола не скачивает клип и шлёт `file_id`; кнопка видео есть
  только у голов с клипом в кэше; рассылка и кнопка берут один и тот же `file_id`.
- `_ClipCache` удалён; `docs/telegram_bot.md` описывает кэш.
- Живая проверка на dev-боте: кнопка видео в карточке из `/today` отвечает без ожидания
  загрузки, если клип уже уходил в рассылке.
- `make ci-local` зелёный.
