## Кратко

Инференс-контур готов (Задача 15: `python -m modeling.cli predict`,
`modeling/predict_runner.py`), но выводить в боте нечего: ни одна пара не прошла
acceptance-gate. Задача — строка модельной вероятности в карточке матча **только** для
пары, прошедшей гейт; гейт не пройден — строки нет.

## Зачем и на что влияет

- **Зачем.** Единственная пользовательская отдача трека B. Датасет, обучение, калибровка
  существуют ради этой строки.
- **На что влияет.** Превью матча из `/tonight` (`matchup_season_preview`,
  `bot_messages.py:611`) — прогноз имеет смысл до матча, а карточка `/game` строится по
  завершённой игре; обработчики в `stats_handlers.py`; появляется канал доставки
  предсказаний из predict-контура в бота; загрузчик — если решено хранить будущие игры в БД.
- **Если не делать.** Трек B не виден пользователю.

## Степень важности

🟡 **Качество продукта, после 40.** В релиз статистического бота не входит и входить
не должна (реестр). Как только 40 пройдёт гейт — следующая по ценности.

## Подробно

### Текущее состояние (сверено 2026-09-22)

- `predict` читает `artifacts/models/<task>/<model>/latest` → `final/`, сверяет
  `features_hash`, применяет калибратор, пишет
  `artifacts/predictions/<task>_<model>_predictions.csv` (`docs/modeling_training.md` §7).
  Нет `latest` — `FileNotFoundError`; расхождение хэша — `ValueError`.
- `latest` ставится `train` только при `status: ok` — это и есть гейт; ручной `latest`
  из демонстрации Задачи 15 снимает Задача 40.
- **В БД нет будущих игр:** загрузчик берёт только `gameStateId=7`
  (`load_season_modern.py:781`). Predict-датасет в Задаче 15 собирали на скретч-БД
  с обнулённым `winner_id` — в рабочей базе строк для предсказания не будет, пока
  расписание не загружено.
- **Стек моделирования не входит в образ бота:** `Dockerfile` ставит только
  `requirements.txt`, `requirements-modeling.txt` исключён `.dockerignore`. Инференс
  в процессе бота невозможен и не нужен.
- Predict-режим: первые игры сезона (и после паузы — Задача 21) дают NaN-фичи;
  `--cold-start-policy-predict drop` или явная обработка (Задача 15).

### Что нужно сделать

1. **Решить канал доставки** (при заведении): predict-прогон по расписанию
   (Задачи 26/34) пишет вероятности в таблицу PostgreSQL
   (`game_id, task, model, run_id, probability, computed_at`) — бот читает её обычным
   `fetch_all`, без импорта `modeling`. CSV в `artifacts/` бот в контейнере не видит.
2. **Будущие игры.** Либо загрузчик пишет запланированные игры в `games` (с NULL
   `winner_id`) и predict-датасет собирается штатно, либо predict-джоб берёт расписание
   из API (`/tonight` уже так делает через `nhl_scoreboard.py`) и строит фичи из истории
   в БД. Первый вариант ближе к контракту (§13 плана классификатора: фичи из уже
   загруженной истории в PG).
3. **Гейт в боте:** строка выводится только если для пары есть запись с `status: ok`,
   проставленная механизмом, и предсказание относится к ещё не сыгранному матчу.
   Нет записи — нет строки, без заглушек и «н/д».
4. **Текст:** «модельная оценка, не совет» (§13 плана классификатора), вероятность
   одним числом, задача (`home_win`/`over_5_5`) названа словами.
5. **Тесты:** превью с предсказанием и без; гейт не пройден → строки нет; устаревшее
   предсказание (другой сезон, сыгранный матч) не показывается.
6. `/help` дополнить описанием строки прогноза; `docs/architecture.md` — новая таблица
   и поток данных.

### Критерии приёмки (карточка в плане 08-08)

- Строка прогноза в карточке игры **только** после прохождения acceptance-gate.
- Гейт не пройден — строка не выводится.
- Прогноз, неотличимый от base-rate, не выпускается.

### Проверка

- `make ci-local`; живой бот на матче дня: строка есть для пары с `status: ok`,
  отсутствует после подмены `latest` на проваленный прогон.

### Подводные камни

- Новая таблица = миграция `data_tables/migrations/0003_…` + парный DDL (правило
  Задачи 19) + `make all-tests`.
- Не дублировать гейт: источник истины — `metadata.json`/`latest` в артефактах; бот
  доверяет записи, которую пишет predict-джоб, а не пересчитывает статус.
- Запланированные игры в `games` меняют инварианты (`winner_id IS NULL` у будущих) —
  проверить `day_digest`, таблицу и подписки, которые считают завершённые матчи.
