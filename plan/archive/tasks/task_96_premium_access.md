# Задача 96. Премиум-доступ: ИИ и прогноз модели — только платным

**Блок:** продукт · **Надобность:** 🟡
**Область:** миграция `0016` (таблица `premium_access`, удаление `ai_existing_users`), новый модуль
`telegram_bot/premium.py`, `telegram_bot/ai_router.py` (лимит), `telegram_bot/bot.py` (`on_free_text`),
`telegram_bot/config.py` (уходит `AI_STATS_CHAT_IDS`), `telegram_bot/bot_messages.py` (строка
прогноза), `telegram_bot/stats_handlers.py`, `telegram_bot/push_digest_job.py`, `.env.example`,
`docs/telegram_bot.md`, `docs/architecture.md`, `DEVELOPMENT.md`.
**Зависит от:** Задачи 83 — её белый список `AI_STATS_CHAT_IDS` эта задача заменяет; начинать после
живой проверки 83 на dev-боте.
**Источник:** просьба человека 2026-10-29; реестр — [`../closed_tasks.md`](../closed_tasks.md).
Продолжение — оплата Telegram Stars, [Задача 97](../../tasks/task_97_premium_stars_payment.md).

## Кратко

Завести признак «премиум у чата до даты» в отдельной таблице и одну функцию проверки. Бесплатным —
3 вопроса ИИ в неделю и не больше 8 за всё время, прогноз модели не показывается. Премиуму — ИИ
целиком (маршрутизатор 81 и ответы по БД 83, 20 вопросов в сутки) и прогноз. Пока премиум один и
выдаётся вручную строкой SQL; оплата — Задача 97.

## Зачем и на что влияет

- ИИ и прогноз — то, за что будут платить; без разделения продавать нечего (97 пишет в эту же
  таблицу).
- Сейчас «кому сколько ИИ» решают **два** механизма: `ai_existing_users` (20 или 5 вопросов в сутки)
  и белый список `AI_STATS_CHAT_IDS` (ответы по БД, Задача 83). Премиум их заменяет — третьего рядом
  не будет (GC3).
- Бесплатный пользователь теряет: 5–20 вопросов в сутки → 3 в неделю и 8 всего; строку прогноза
  в превью матча — по кнопке и в пуше.

## Степень важности

🟡: монетизация, ничего в релизе не блокирует; блокирует 97.

**Состояние на 2026-10-29** (`origin/develop` = `0b6c1c2`).
- Лимит ИИ — `ai_router.questions_left()` (`ai_router.py:179`): `DAILY_LIMIT_EXISTING = 20` для
  чатов из `ai_existing_users` (миграция 0012), иначе `DAILY_LIMIT_NEW = 5`, считается по строкам
  `ai_questions` за сутки МСК.
- Ответы по БД (83) — только чатам из `config.AI_STATS_CHAT_IDS` (`config.py:167`, `bot.py:495`);
  продолжение диалога (`ai_stats.recent_pairs`) идёт в `ai_stats` сразу, мимо маршрутизатора.
- Прогноз — `_model_prediction_line()` (`bot_messages.py:847`) вызывается внутри
  `matchup_season_preview()` (`bot_messages.py:1053`). Потребители: превью по кнопке
  (`stats_handlers.py:497`) и пуш «Предстоящие матчи» (`push_digest_job.py:638`), где превью
  считается **один раз на матч и одно на все чаты** (`previews[game_id]`).

**Что делать.**
1. **Миграция 0016.** `premium_access(chat_id bigint PRIMARY KEY, expires_at timestamptz NOT NULL,
   granted_at timestamptz NOT NULL DEFAULT now())`; `DROP TABLE ai_existing_users`. Только миграция,
   без `data_tables/t.*.sql` — как у `bot_subscriptions`: повторной загрузкой не восстановить.
   Бессрочного премиума нет: при ручной выдаче дату ставит человек, 97 её продлевает.
2. **`telegram_bot/premium.py`** (шапка модуля, docstring): `is_premium(chat_id) -> bool` —
   `expires_at > now()`. Отдельный модуль, потому что у функции три потребителя (ИИ, превью, пуш),
   и 97 добавит сюда выдачу по оплате. Запись в `docs/architecture.md`.
3. **Лимит ИИ** в `questions_left()`: премиум — 20 за сутки МСК; иначе
   `min(3 − за календарную неделю МСК (пн–вс), 8 − за всё время)`. `DAILY_LIMIT_NEW` и
   `ai_existing_users` удаляются. Тексты отказа — свои для «неделя кончилась» (когда снова: «в
   понедельник») и «бесплатные вопросы кончились совсем». **До 97 купить нечего** — текст не зовёт
   к оплате.
4. **Ответы по БД (83)** открыты тем же признаком: `stats_allowed = premium.is_premium(chat_id)`
   **или** бесплатный вопрос в пределах лимита (см. «Решить в начале», п. 2). `AI_STATS_CHAT_IDS`
   удаляется из `config.py`, `.env.example`, `.env` обоих стеков, `DEVELOPMENT.md`,
   `docs/telegram_bot.md` §83, `docs/architecture.md`.
5. **Каждый бесплатный вопрос считается ровно один раз** — включая продолжение диалога 83, которое
   сейчас идёт мимо `questions_left` и мимо строки `ai_questions`. Источник счёта — один (строки
   `ai_questions` или их объединение с `ai_stats_log`), выбрать по коду и описать в docstring.
6. **Прогноз.** `matchup_season_preview()` перестаёт вставлять строку прогноза; её добавляет
   вызывающий, если чат премиум: в `stats_handlers` — по `chat_id` запроса, в пуше — при отправке
   каждому чату, общий кэш `previews[game_id]` остаётся без прогноза. Бесплатному строка просто не
   выводится; тизер «🔒 в премиуме» — в 97, когда появится кнопка покупки.
7. **Выдача вручную.** В `DEVELOPMENT.md` — SQL выдачи и продления
   (`INSERT … ON CONFLICT (chat_id) DO UPDATE SET expires_at = …`) и как узнать `chat_id`.
   Миграцию сначала на `nhl_dev`, затем мержем в `master` — на прод; строку премиума человек
   вставляет на каждой базе сам.

**Решить в начале (человек).**
1. **Чем считать «8 за всё время»:** вся история `ai_questions`, включая вопросы до выкатки
   (рекомендую: проще, без даты отсечки; кто уже спросил 8+ — пробник исчерпал), или только с даты
   выкатки 96.
2. **Бесплатный вопрос — с ответами по БД (83) или только выбор экрана (81)?** Рекомендую весь
   конвейер: пробник показывает лучшее, а потолок расхода — 8 × $0.10 = $0.80 на пользователя за
   всё время.
3. Групповые чаты: премиум выдаётся на `chat_id`, как подписки, — группа с премиумом видит прогноз
   всем участникам. Рекомендую оставить так (YAGNI), отметить в доке.

**Критерии приёмки.**
- Тесты: `is_premium` — действующий, истёкший, отсутствующий; лимит — премиум 20 в сутки,
  бесплатный 3 в неделю (граница недели по МСК), потолок 8 за всё время раньше недельного;
  продолжение диалога 83 тратит бесплатный вопрос; превью без прогноза для бесплатного и с ним
  для премиума — и по кнопке, и в пуше (один матч, два чата: премиум и нет).
- `ai_existing_users` и `AI_STATS_CHAT_IDS` в коде и доках не встречаются.
- Миграция 0016 вверх и вниз на БД (`make all-tests`, `tests/test_db_nhl.py` прогнать самому — CI
  гоняет его отдельно).
- Живая проверка на dev-боте: премиум-чат (вставлен SQL-ом) видит прогноз и получает ответ по БД;
  второй, бесплатный, — без прогноза, четвёртый вопрос за неделю получает отказ.
- `make ci-local` зелёный; прогон pytest с `PG_PORT=1`, как в CI.

**Подводные камни.**
- Прогноз нельзя проверять внутри общего кэша превью пуша — иначе бесплатный получит строку
  премиума или наоборот, в зависимости от того, кто первым в рассылке.
- Сбой БД при проверке премиума не превращать в «бесплатный» молча (GC4): падать громко, как
  остальные запросы бота.
- Бюджет GC6: оценка 200–300 строк с тестами; больше — разбить (ИИ-лимит / прогноз).
