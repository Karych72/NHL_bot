# Задача 86. Переезд на aiogram 3.31 и rich-сообщения с компактными таблицами

**Блок:** продукт · **Надобность:** 🟠
**Область:** весь `telegram_bot/` (`bot.py`, `script_bot.py`, `stats_handlers.py`,
`dialog_states.py`, `throttle.py`, `push_digest_job.py`, `bot_messages.py`), `requirements*.in/.txt`,
тесты бота (`tests/conftest.py`, `tests/test_bot_*.py`, `tests/test_push_digest_job.py`,
`tests/test_skater_reports_bot.py`), `docs/architecture.md`.
**Зависит от:** —
**Источник:** запрос человека 2026-10-26 («трансформация сообщений обновлённым API, чтобы
сообщения круто смотрелись»), план — [`../rich_messages/README.md`](../../rich_messages/README.md);
решение человека — полный переезд на aiogram одной сессией. Реестр — [`../open_tasks.md`](../closed_tasks.md).

## Кратко

Перевести бота с python-telegram-bot 21.11.1 на aiogram 3.31 (Bot API 10.3) и отдавать экраны
Rich Messages (Bot API 10.1) с компактными таблицами (`is_compact`, Bot API 10.3) вместо
моноширинных `<pre>`-таблиц.

## Зачем и на что влияет

- `<pre>`-таблицы на телефоне разваливаются: строка шире ~36 символов переносится
  ([`../rich_messages/img_35.png`](../../rich_messages/img_35.png) — превью SEA @ DET), а подгонка под ширину стоила обрезанных
  фамилий и выброшенных колонок. Rich-таблицу Telegram раскладывает сам.
- python-telegram-bot отстал: последняя версия 22.8 — Bot API 10.0, поддержка 10.1 приостановлена
  до рефакторинга библиотеки (issue #5261). aiogram 3.31 вышел через два дня после Bot API 10.3 и
  даёт rich-сообщения типизированно; дальше — стриминг ответов ИИ (`sendRichMessageDraft`),
  кнопки внутри текста.
- Затрагивает каждый экран бота и все рассылки — отсюда 🟠 и обязательная живая проверка.

## Степень важности

🟠: смена фреймворка и формата всех экранов; данных не меняет, миграций нет.

## Подробно

**Было** (снимок 2026-10-26): PTB `Application` с группами хендлеров (троттлинг −2, standalone −1,
`ConversationHandler` `/stats` и свободный текст в группе 0), `CallbackContext` в хендлерах и
рассылке; таблицы — `_pre_table`/`_pre_table_fit` в `<pre>` с `|` и выбрасыванием колонок,
лимит 4096.

**Сделано:**
1. Зависимости: `aiogram==3.31.0` вместо `python-telegram-bot==21.11.1` (GC 5, разрешение человека).
2. `bot.py`: `Dispatcher` из роутеров standalone → `stats` (FSM `StatsMenu`, карта
   `STATS_DIALOG`) → `tail` (`/cancel` вне диалога, свободный текст); троттлинг — outer-middleware;
   DI `bot`/`state`/`match`/`command`; `SimpleEventIsolation` — апдейты пользователя по одному.
3. `bot_messages`: `_table()` (`<table compact striped>`, шапка, выравнивание, «линия
   плей-офф»), `rich_message()` (строка — абзац, таблица — блок), лимит 32 768 и обрезка целыми строками.
4. Все экраны — rich (`send_rich_message`, `answer_rich`, `edit_text(rich_message=…)`); служебные
   ответы, `/subscriptions`, подписи к видео — обычные; «Сохранить» — `copy_message`.
5. Тесты на настоящих объектах aiogram и записывающей HTTP-сессии, маршрутизация через
   `Dispatcher.feed_update`.

**Критерии приёмки:** `make ci-local` зелёный; ревью Opus пройдено; живая проверка на dev-боте по
чек-листу [`../rich_messages/README.md`](../../rich_messages/README.md) (таблицы на трёх клиентах, меню
`/stats` rich → rich, «Сохранить», плотность абзацев, ночные рассылки, пустые ячейки шапки).

**Подводные камни:** старые клиенты Telegram могут не показать rich-сообщения; в rich-HTML
перевод строки — пробел (поэтому абзац на строку); лимит 500 блоков обрезкой не охраняется
(самый длинный экран ~70 блоков); отличия от PTB — ответы в группах без цитаты, команда в подписи
к фото срабатывает, нажатия ждут собственный запрос пользователя к ИИ.
