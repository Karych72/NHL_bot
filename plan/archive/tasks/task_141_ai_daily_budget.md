# Задача 141. Общий суточный потолок расходов на ИИ

**Блок:** продукт · **Надобность:** 🟠
**Область:** `telegram_bot/ai_router.py` (`limit_refusal`, тексты отказа), `telegram_bot/bot.py`
(журнал `ai_limit`), `telegram_bot/ai_stats.py`, `tests/test_bot_ai_*.py`, `docs/premium.md`,
`docs/telegram_bot.md`, `docs/ai_capabilities.md`.
**Зависит от:** ничего. Связана с Задачей 124: снятие пожизненного потолка увеличивает расход
на бесплатных, и общий предохранитель становится нужнее.
**Источник:** ревизия качества кода 2026-11-16, просьба человека завести задачу; реестр —
[`../closed_tasks.md`](../closed_tasks.md).

## Кратко

Появляется один предохранитель на весь бот: когда суммарный расход на ИИ за сутки превышает
заданную сумму, неплатящие чаты получают отказ до следующих суток.

## Зачем и на что влияет

- Сейчас лимиты считаются только на чат. Пробный период выдаётся любой новой личке: 3 дня по
  20 вопросов с потолком $0.10 на вопрос — до ~$6 на аккаунт.
- Число аккаунтов ничем не ограничено, поэтому общий расход ограничен только балансом ключа
  API. Достаточно одной ссылки на бота в большом чате или простого скрипта.
- Расход на каждый вызов уже пишется в журналы (`cost_usd`), так что считать нечего — нужна
  одна проверка.

## Степень важности

🟠: подтверждённый финансовый риск без верхней границы. Задача маленькая.

## Подробно

**Текущее состояние (снимок 2026-11-16, `origin/develop` = `5a97128`; строки сверять).**
- `ai_router.limit_refusal` проверяет лимиты чата (сутки для премиума, неделя и «всего» для
  бесплатного); вызывается из `bot.py` (около строки 1031) до обращения к модели.
- `premium.grant_trial` (`premium.py:77`) — пробник чату без следов в журналах.
- `ai_stats.COST_CEILING = 0.10` (`ai_stats.py:47`) — потолок одного вопроса.
- Расход пишется в `ai_questions.cost_usd` (маршрутизатор, миграция 0012) и в журнал
  `ai_stats` (миграция 0015).

**Что делать.**
1. Константа суточного бюджета в `ai_router.py` рядом с лимитами чата (значение — вопрос 1).
2. В `limit_refusal` — проверка до лимитов чата: сумма `cost_usd` по обоим журналам за текущие
   сутки (те же границы суток, что у суточного лимита премиума). Превышена — отказ с отдельным
   текстом: «сегодня ИИ перегружен, вернитесь завтра», без призыва платить.
3. Платящие чаты проверку не проходят (вопрос 2): они уже ограничены 20 вопросами в сутки.
4. Отказ пишется в `bot_actions` как `ai_limit` с `data = 'budget'`.
5. Тесты: бюджет не превышен — `None`; превышен — отказ бесплатному и пробному чату; платящий
   чат отвечает; расход прошлых суток не учитывается.
6. Документация: `docs/premium.md`, §8 и §10 `docs/telegram_bot.md`.

**Критерии приёмки.**
- При расходе выше бюджета (подставить строки в журнал на dev-базе) бесплатный и пробный чат
  получают новый текст отказа, обращения к API нет, в `bot_actions` — `ai_limit` / `budget`.
- Платящий чат в той же ситуации получает ответ.
- Наутро по времени суток лимита отказ снимается сам.
- `make ci-local` зелёный.

**Подводные камни.**
- Проверка выполняется на каждый текстовый вопрос: запрос суммы за сутки должен идти по
  индексу по времени в обоих журналах — проверить план запроса, при необходимости добавить
  индекс миграцией.
- Вопрос, начатый до превышения, доходит до конца: бюджет может быть превышен на стоимость
  параллельных вопросов. Это допустимо, точная граница не нужна.
- Не вводить настройку через `.env` или таблицу (Global Constraint 1): константа в коде.
- Задача 123 убирает прогноз из перков премиума, Задача 124 меняет тексты отказов — сверить
  формулировки, если они уже в коде.
- Отдельная находка ревизии — нет общего дедлайна на один вопрос (до 7 вызовов по 60 секунд) —
  в эту задачу не входит.
