# План: статистика по командам и по странам

**Статус:** не выполнено. Детали — [`README.md`](./README.md).

Документ описывает реализацию расширений бота: **командные срезы** (поверх `teams`, `teams_stats`, игр) и **агрегаты по странам** (поверх `rosters.nationality` + статистика игроков/вратарей). Согласован с текущей архитектурой: `bot_messages.py` + SQL + Jinja2, `stats_handlers.py` + `dialog_states.py`, whitelist в `database.py`, сезон из `config.SEASON_ID` / `config.CURRENT_SEASON`.

**Связанные документы:** [`architecture.md`](../docs/architecture.md), [`bot_ux_implementation_phases.md`](deprecated_plan/bot_ux_implementation_phases.md), [`data_loading.md`](../docs/data_loading.md), [`telegram_bot.md`](../docs/telegram_bot.md).

---

## 1. Цели и границы

| Цель | Описание |
|------|----------|
| Команды | Дать пользователю больше контекста, чем одна таблица очков: лидеры лиги по командным метрикам, срезы по конференции/дивизиону, сравнение двух команд, опционально «профиль команды». |
| Страны | Показать вклад национальностей в сезон: число игроков, суммарные/средние очки и голы, топ игроков выбранной страны, при необходимости голы по странам бомбардиров. |

**Вне первой версии (бэклог):** домашние/гостевые сплиты команд (если нет готовых колонок в `teams_stats`), `birthCountry` как отдельная ось (сейчас в DDL `rosters` есть только `nationality`; поле из API можно добавить колонкой и загрузкой в pipeline).

**Ограничение Telegram:** сообщения до ~4096 символов; длинные топы — пагинация, «топ-15 стран» + кнопка «ещё», или несколько сообщений, по аналогии с `leaders_top10_messages()`.

## 2. Исходные данные (уже в БД)

| Таблица | Использование |
|---------|----------------|
| `teams` | `conference_name`, `division_name`, `short_name`, `abbreviation`, join к `teams_stats`. |
| `teams_stats` | Командные метрики сезона: PP%, PK%, голы/игра, броски, вбрасывания, очки и т.д. |
| `rosters` | `nationality`, `position`, `rookie`, `current_team_id`, `player_id`, `season_id`. |
| `players_season_stats` | Очки, голы, игры и др.; join с `rosters` по `player_id`, `season_id`. |
| `goalies_season_stats` | Победы, %, GAA; та же связка с `rosters` для страны вратаря. |
| `games`, `game_team_stats` | Сравнение команд по последним матчам, форме (если решите считать из фактических игр). |
| `all_goals` | `goal_player_id` → `rosters` для «голов по странам среди забивших» (не путать с очками). |

**Правило учёта игрока для стран:** одна строка на (`player_id`, `season_id`) в `rosters` с актуальной `nationality` на сезон. Игрок без ростера на сезон исключается или попадает в «Unknown» — зафиксировать в коде/шаблоне.

**Минимум игр для лидеров страны:** параметр (например `games >= 5` или как в существующих лидербордах игроков), единый для всех страновых топов.

## 3. Фаза A — Командные лидерборды (низкий риск)

Паттерн как у `team_stats(name_stats, column_name)`: whitelist колонки, `ORDER BY`, шаблон `messages/team_stats.txt` или узкий новый шаблон при другом формате строки.

| Шаг | Задача | Детали |
|-----|--------|--------|
| A.1 | Расширить whitelist | В `database.py` убедиться, что все нужные колонки из `teams_stats` для сортировки уже в `ALLOWED_COLUMNS` (при необходимости добавить недостающие, если появятся новые поля в DDL). |
| A.2 | Новые пункты меню / колбэки | В `dialog_states.py` — новые константы состояний (или префикс callback, как у `adv:` / `shot:`), в `script_bot.py` — кнопки под раздел «Команды» или расширение существующего блока командной статистики. |
| A.3 | Обработчики | В `stats_handlers.py` — фабрики по образцу `_make_stats_handler(partial(team_stats, ...))` для метрик: например лучший PP%, PK%, goals_per_game, goals_against_per_game, shots_per_game, face_off_win_percentage. Не дублировать то, что уже есть (`TEAM_POWER_PLAY` и т.д. — сверить с текущими кнопками и либо переиспользовать, либо заменить на единый подменю «Топ команд»). |
| A.4 | Копирайт кнопок | Короткие подписи на русском, единый «Назад» / «Готово». |

**Критерий готовности:** пользователь видит топ команд по выбранной метрике за `SEASON_ID` с корректной сортировкой (для «худших» метрик — отдельная функция или параметр `order_asc` с белым списком колонок).

## 4. Фаза B — Конференции и дивизионы

| Шаг | Задача | Детали |
|-----|--------|--------|
| B.1 | SQL-представления или запросы | Запросы с `GROUP BY t.conference_name` / `t.division_name`: средние `goals_per_game`, суммарные очки (или средние очки на команду), количество команд. Источник: `teams_stats` ⋈ `teams` на `team_id`, `season_id`. |
| B.2 | Функции в `bot_messages.py` | Например `conference_summary()`, `division_summary()` → строка или список для нескольких сообщений. |
| B.3 | Шаблоны | Новые файлы в `telegram_bot/messages/` (например `conference_stats.txt`, `division_stats.txt`) с Jinja2. |
| B.4 | UI | Одна кнопка «По конференциям» / «По дивизионам» или вложенное меню выбора среза. |

**Критерий готовности:** одно сообщение с таблицей или списком метрик по каждой конференции/дивизиону без ручного ввода ID.

## 5. Фаза C — Сравнение двух команд

| Шаг | Задача | Детали |
|-----|--------|--------|
| C.1 | UX выбора команд | Варианты: (1) два шага FSM — сначала команда A, потом B из inline-кнопок с `callback_data` `cmp:<abbr>`; (2) команда `/compare WSH TOR` с парсингом аббревиатур. Рекомендация: начать с FSM + кнопки из списка `abbreviation` из `teams` для текущего сезона. |
| C.2 | SQL | Одна строка на команду из `teams_stats` ⋈ `teams`; опционально последние 5–10 `game_id` из `games` где участвовала команда, с кратким W/L из уже загруженных данных (уточнить наличие итогового счёта в `games` или считать через `game_team_stats`). |
| C.3 | `bot_messages.py` | `compare_teams(abbr_a, abbr_b) -> str`, валидация: обе команды существуют в сезоне. |
| C.4 | Безопасность | Идентификаторы команд не из произвольного текста пользователя в SQL — только маппинг `abbreviation` → `team_id` из результата заранее загруженного списка или параметризованный запрос с двумя `team_id`. |

**Критерий готовности:** после выбора двух команд одно сообщение с ключевыми полями из `teams_stats` рядом (таблица из двух строк или колонки).

## 6. Фаза D — Профиль команды (состав + вклад позиций)

| Шаг | Задача | Детали |
|-----|--------|--------|
| D.1 | Выбор команды | Аналогично C.1: список команд сезона. |
| D.2 | SQL | `rosters` ⋈ `players_season_stats` для `current_team_id = :team_id` и `season_id`: агрегаты по `position` (очки, голы, количество игроков), топ-3 бомбардира клуба. |
| D.3 | Шаблон | `team_profile.txt` с секциями: таблица сезона из `teams_stats` (кратко), блок позиций, топ игроков. |
| D.4 | Лимит размера | Если строк много — обрезка топа или второе сообщение. |

**Критерий готовности:** одна команда → один согласованный отчёт без ручного SQL со стороны пользователя.

## 7. Фаза E — Статистика по странам (игроки)

| Шаг | Задача | Детали |
|-----|--------|--------|
| E.1 | Справочник отображения | Маппинг ISO-кода → флаг emoji или русское имя страны (статический dict в коде или маленький JSON; не тянуть внешний API в рантайме бота без необходимости). |
| E.2 | Агрегат «топ стран» | Запрос: из `players_season_stats` p ⋈ `rosters` r на `player_id`, `season_id`, фильтр `position <> 'G'` (или учитывать только полевых — зафиксировать). Метрики: `COUNT(*)`, `SUM(points)`, `SUM(goals)`, опционально `SUM(points)::float / NULLIF(SUM(games),0)` как очки на игрока-матч (интерпретацию описать в подписи). Минимум игроков на страну для попадания в топ (например ≥ 3). |
| E.3 | Экран «страна → топ игроков» | Callback `cntr:<ISO>` или выбор из топ-20 стран кнопками. Запрос: игроки с `nationality = %s`, сортировка по `points DESC`, лимит 15, join для имени из `rosters.name` / `lastname`. |
| E.4 | Вратари | Отдельный запрос к `goalies_season_stats` ⋈ `rosters` с тем же `nationality`, метрики wins / save% / GAA — либо отдельное подменю «Страны: вратари». |
| E.5 | Функции и шаблоны | `country_leaderboard_skaters()`, `country_top_players(iso)`, шаблоны `country_rankings.txt`, `country_players.txt`. |
| E.6 | Whitelist | Если появятся динамические части запроса — не добавлять произвольный `nationality` в идентификаторы SQL; только параметр `%s` после проверки, что строка входит в набор из последнего запроса топа или в фиксированный ISO-список. |

**Критерий готовности:** два уровня — «топ стран по очкам» и «детализация по одной стране».

## 8. Фаза F — Голы по странам (опционально)

| Шаг | Задача | Детали |
|-----|--------|--------|
| F.1 | SQL | `all_goals` → join `goal_player_id` с `rosters` (`player_id`, `season_id`) → `nationality`, `COUNT(*)` за сезон (фильтр игр по `season_id` через `games` если в `all_goals` нет `season_id` — проверить фактическую схему и join по `game_id`). |
| F.2 | UI | Кнопка «Голы по странам (снайперы)» с пояснением, что это забитые голы, не очки. |
| F.3 | Согласованность | Не смешивать в одной таблице с суммой очков без подписи — разные смыслы. |

**Зависимость:** корректный join `all_goals` ↔ сезон; при отсутствии `season_id` в целях — только через `games.season_id`.

## 11. Порядок внедрения (рекомендуемый)

1. **A** — быстрый выигрыш, переиспользование `team_stats`.  
2. **E** — высокая новизна для пользователя, данные готовы.  
3. **B** — усиливает командную аналитику без FSM.  
4. **C** — сравнение команд (средняя сложность UX).  
5. **D** — профиль команды.  
6. **F** — после проверки join с `games` / сезоном.  

Параллельно: унификация подписей и лимитов длины текста (`truncate_telegram_text`).

## 12. Риски и открытые вопросы

| Риск | Митигация |
|------|-----------|
| Расхождение имён колонок `rosters` (API vs DDL) | Проверить фактические имена в БД после загрузки (`currentage` vs `currentAge` в whitelist). |
| Двойное гражданство | В данных NHL одна `nationality`; в тексте бота кратко указать источник. |
| Мало игроков у экзотических стран | Порог `COUNT` и фраза «мало данных» в шаблоне. |
| Размер меню | Подменю или команды `/countries` вместо 30 кнопок на экране. |

## 13. Критерии приёмки (общие)

- Все новые SQL-запросы через существующий слой `fetch_all` / параметризация; динамические идентификаторы только через whitelist как в текущем `team_stats` / `player_stats`.  
- Сезон везде из `config`, без захардкоженного `season_id` в шаблонах.  
- Падение БД / пустой результат даёт понятное сообщение пользователю, а не traceback в чат.  

После реализации — краткое обновление раздела «Дерево проекта» в [`architecture.md`](architecture.md) (новые шаблоны, функции, тесты), без дублирования всего содержания этого плана.
