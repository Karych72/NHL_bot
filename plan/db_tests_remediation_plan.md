# План устранения пропусков тестов БД (`tests/test_db_nhl.py`)

**Статус:** частично выполнено (этап A и цели Makefile/README закрыты; CI и прочее — по чеклисту ниже). Детали — [`README.md`](./README.md).

## 1. Контекст

При запуске `pytest tests/` или `python -m pytest tests/` **девять** тестов из `tests/test_db_nhl.py` помечаются как **skipped**. Это ожидаемое поведение: классы защищены декораторами `@unittest.skipUnless` и не требуют БД при обычном прогоне.

| Класс | Кол-во тестов | Условие запуска |
|--------|----------------|-----------------|
| `TestNhlSchema` | 2 | `RUN_DB_SCHEMA_TESTS` ∈ `1`, `true`, `yes` + доступный PostgreSQL |
| `TestNhlLoadedData` | 7 | `RUN_DB_DATA_TESTS` ∈ `1`, `true`, `yes` + PostgreSQL + загруженные данные |

Дополнительно внутри тестов схемы возможен `skipTest`, если нет таблиц (`public.teams`, `public.games`) — после миграции DDL нужен `make db-reset-local` (или эквивалент).

**Проблема для разработки:** один и тот же набор команд даёт разный смысл: «все зелёные» без БД не гарантируют целостность схемы и данных.

## 2. Цели

1. Явно задокументировать и при необходимости **унифицировать** способ запуска unit-тестов бота и DB-тестов.
2. Свести к минимуму ситуацию «все тесты зелёные, но DB-тесты никто не включал».
3. Опционально: **CI** с PostgreSQL сервисом для схемы (и при желании — для smoke-проверки данных).

## 3. Этапы плана

### Этап A — Документация и единая точка входа (низкая сложность)

**Сделано:** в `Makefile` цели `test-fast` (pytest с `--ignore=tests/test_db_nhl.py`) и `all-tests` (`test-fast` + `test-db`); в корневом `README.md` — раздел **Tests**.

- Дополнительно при необходимости: ссылка из [`docs/data_loading.md`](../docs/data_loading.md) на README или этот файл (`plan/db_tests_remediation_plan.md`).
- В `tests/test_db_nhl.py` модульный докстринг уже хорош; при желании дублировать ссылку на этот документ.

**Критерий:** новый разработчик за один проход находит, как включить оба класса DB-тестов.

### Этап B — Согласование `pytest` и `make test-db` (средняя сложность)

**Принятое решение:** прагматичный минимум — `test_db_nhl` остаётся на `unittest` + env; `make test-fast` не подхватывает этот файл (`pytest --ignore`), затем `make all-tests` вызывает `test-db` с `RUN_DB_SCHEMA_TESTS=1` из `Makefile`.

Альтернативы на будущее: маркеры pytest, единый `pyproject.toml` — только если появится мотивация унифицировать стиль тестов.

### Этап C — Локальная среда (обязательные шаги для «зелёных» DB-тестов)

1. Файл `.env` (или переменные окружения) с `PG_HOST`, `PG_PORT`, `PG_USER`, `PG_DATABASE`, согласованными с лоадером и `telegram_bot/config`.
2. Запущенный PostgreSQL.
3. Для **схемы:** `make db-reset-local` (или `db-reset`) — создание таблиц из `data_tables/t.*.sql` и функций.
4. Прогон: `make test-db` (уже выставляет `RUN_DB_SCHEMA_TESTS=1`).
5. Для **данных:** загрузка сезона (например `make season-sync-month` или принятый в проекте сценарий), затем:
   ```bash
   export RUN_DB_DATA_TESTS=1
   make test-db
   ```
   либо расширить `Makefile` целью `test-db-data`, экспортирующей оба флага и вызывающей `unittest tests.test_db_nhl`.

**Критерий:** на машине с БД и DDL после `make test-db` — 0 skips для `TestNhlSchema`; после загрузки данных и `RUN_DB_DATA_TESTS=1` — 0 skips для обоих классов.

### Этап D — CI (опционально)

1. Job с сервисом `postgres` (образ и версию согласовать с локальной).
2. Шаги: установка зависимостей, `make db-reset` (или `psql` + DDL-скрипты), `make test-db` с `RUN_DB_SCHEMA_TESTS=1`.
3. Job для **данных** — отдельный, реже: либо артефакт дампа, либо упрощённый smoke после минимальной загрузки; иначе оставить только схему в CI.

**Критерий:** merge request не проходит, если сломаны PK/колонки, которые проверяет `TestNhlSchema`.

### Этап E — Предупреждение `imghdr` (python-telegram-bot)

Не блокирует тесты. При обновлении до Python 3.13+ может проявиться сильнее.

- Отслеживать обновления `python-telegram-bot` или зафиксировать верхнюю поддерживаемую версию Python в README.
- При появлении падений — обновить зависимость или изолировать импорты в тестах.
