# Rich Messages: таблицы и структура сообщений бота средствами Bot API 10.1+

**Статус: план** (заведён 2026-10-26). План, развилки и разбивка — в этой папке; задачи
после разбивки получат номера в [`../open_tasks.md`](../open_tasks.md).

## Запрос (со слов владельца)

Сообщения бота должны хорошо смотреться, прежде всего на телефоне. Проверить, можно ли
перевести их на Rich Messages (Bot API 10.1) и компактные таблицы (`is_compact`, Bot API 10.3).

## Проблема сейчас

Каждая таблица бота — моноширинный блок `<pre>`, колонки выровнены пробелами
(`_aligned_columns`, `_pre_table`, `_pre_table_fit` в `telegram_bot/bot_messages.py:173-245`).
Строка шире ~36 символов на телефоне переносится, и таблица разваливается: превью матча
SEA @ DET в [`../img_35.png`](../img_35.png), запись в [`../bot_UI_problem.md`](../bot_UI_problem.md).
Обходим это вручную: подрезаем фамилии (`_LEADER_NAME_WIDTH`), выкидываем колонки по
`drop_order`, держим ширины в `leaderboard_specs.py`. Кроме того, в моноширинном блоке не бывает
жирного шрифта, ссылок и заголовков.

## Что даёт API

Сверено с core.telegram.org/bots/api 2026-10-26.

| Версия | Дата | Что нужно нам |
|---|---|---|
| 10.1 | 2026-06-11 | `sendRichMessage`: содержимое в `rich_message.html` / `.markdown` / массиве блоков. Заголовки `<h1-6>`, `<table>`, списки, `<details>`, `<blockquote>`, `<footer>`, `<hr/>`, медиа по URL. Лимит — 32 768 символов вместо 4096. `editMessageText` получил параметр `rich_message`, `reply_markup` в нём остался |
| 10.2 | 2026-07-14 | `InputRichMessageMedia`: свои файлы внутри rich-сообщения (`tg://photo?id=…`) |
| 10.3 | 2026-08-24 | `<table compact>` / `is_compact`: в ячейках меньше отступов. `<details>`-цитата сворачивается. Кнопки внутри текста (`<tg-button>`) |

- У таблицы есть `bordered`, `striped`, `compact`, `<caption>`, `colspan/rowspan`, `align`.
  В ячейке допустима **только инлайн-разметка**: жирный, ссылки, эмодзи.
- `sendRichMessage` принимает `reply_markup`, поэтому клавиатуры меню сохраняются.
- `sendRichMessageDraft` стримит ответ по мере генерации; это пригодится ИИ-ответам
  (Задачи 81, 83), но не входит в этот план.

## Ограничения и решения

1. **Библиотека.** python-telegram-bot 21.11.1 поддерживает Bot API 8.3. В PTB работа над 10.1
   приостановлена до окончания их рефакторинга (issue #5261, состояние на 2026-10-21).
   **Решение:** вызывать сырые методы через встроенный `Bot.do_api_request("sendRichMessage", api_kwargs=…)`,
   он в 21.11.1 есть. Новых зависимостей не нужно (GC 5). Обновление PTB — отдельный
   вопрос, этот план его не включает.
2. **Без запасного пути (GC 4).** Если Telegram отклонил rich-сообщение, это ошибка. Тихо
   откатываться на `<pre>` нельзя.
3. **Без двух рендеров (GC 3).** Переведённый экран теряет свою `<pre>`-версию сразу.
   Общие хелперы `<pre>` удаляет задача, которая переводит последний экран.
4. **Медиа.** Альбомы с голами (`video_replay.py`) и подписи к фото остаются как есть:
   у подписи rich-формата нет.
