# Задача 113. Ротация токенов ботов и чистка версий секретов

**Блок:** релиз · **Надобность:** 🟠
**Область:** BotFather и консоль Anthropic (шаги человека), Secret Manager `nhl-bot-prod`,
VM (`fetch-secrets.sh`, перезапуск bot/sync); код не меняется.
**Зависит от:** ничего. Если 111 заводит отдельный ключ dev — согласовать порядок.
**Источник:** аудит Задачи 82, кандидаты 1, 5 и находка N7 в [`../../docs/security.md`](../../docs/security.md);
реестр — [`../open_tasks.md`](../open_tasks.md).

## Кратко

Оба действующих токена побывали в открытом виде: продовый — в логах docker на VM (Задача 80,
2026-10-25), dev-бота (до Задачи 79 — продовый, версия v1 секрета прода) — там же и в
транскриптах Claude Code (8 вхождений). Ни один не менялся. В Secret Manager включены старые
версии: отозванные токены dev и неизвестно, отозваны ли две старые версии ключа Anthropic.

## Зачем и на что влияет

Токен = полный контроль над ботом: рассылка всем подписчикам от его имени, чтение входящих.
Логи с токеном удалены, но копии (снапшоты, транскрипты) могли остаться.

## Степень важности

🟠 — утечка подтверждена, следов использования нет.

## Подробно

Для каждого бота по очереди (сначала dev, потом прод — в окно без рассылок):
1. Человек: `/revoke` в BotFather → новый токен; `gcloud secrets versions add … --data-file=-`
   (Ctrl-D дважды, без Enter — `DEVELOPMENT.md` §«Боты и секреты»).
2. На VM: `fetch-secrets.sh` нужной строкой юнита, затем `docker compose up -d --force-recreate
   bot sync` от `deploy` в каталоге стека. Проверка: бот отвечает, `getMe` старого токена → 401
   (проверять счётчиком, не печатая токен).
3. Старые версии секрета — `gcloud secrets versions disable`.
4. Ключ Anthropic: человек проверяет в консоли, что ключи старых версий отозваны, ставит лимит
   расходов; старые версии — `disable`.
5. `docs/security.md` — пункты 1, 5, N7 → исправлено.

**Приёмка:** у каждого секрета включена одна версия; `getMe` по всем выключенным версиям
токенов → 401; оба бота работают.
