# Задача 133. Разрезать `bot_messages.py` по экранам

**Блок:** инженерия · **Надобность:** 🟡
**Область:** `telegram_bot/bot_messages.py` и все его импортёры, `telegram_bot/push_digest_job.py`
(`throttled`), `tests/test_bot_messages.py`, `docs/architecture.md`.
**Зависит от:** Задача 123 (убирает прогноз из превью — меньше переносить). Удобнее после 132.
**Источник:** ревизия качества кода 2026-11-16, просьба человека завести задачи; реестр —
[`../open_tasks.md`](../open_tasks.md).

## Кратко

Модуль на 2823 строки делится на модули по экранам и общий модуль примитивов разметки.
Поведение не меняется: это перенос кода.

## Зачем и на что влияет

- Это самый большой и самый часто меняемый файл проекта: 95 коммитов из 797. Правка одного
  экрана требует прочитать весь файл — около 35 тысяч токенов, плюс около 25 тысяч на его тест.
- В файле вперемешку SQL-запросы, вёрстка, константы (`MSK`, `COUNTRY_LABELS`) и примитивы
  (`rich_footer`). Ради констант и примитивов его импортируют почти все модули бота, включая
  `ai_router`, `nhl_scoreboard`, `video_replay`, `help_text`.
- `bot.py:44` импортирует `throttled` из CLI-скрипта `push_digest_job`, и процесс бота при
  импорте выполняет его `logging.basicConfig` и правку `sys.path`.

## Степень важности

🟡: удобство правки и расход контекста. Риск для поведения низкий при переносе без правок.

**Что делать.** По одному PR на шаг; каждый шаг — перенос без изменения логики:
1. **Удалить мёртвое** из списка выше — до переноса, чтобы не переносить лишнее.
2. **Примитивы и константы** — в нейтральный модуль (`rich_footer`, форматтеры, `MSK`,
   `COUNTRY_LABELS`). `throttled` — туда же или в `throttle.py`; `bot.py` перестаёт
   импортировать `push_digest_job`.
3. **Экран матча и превью** (`game_message`, `matchup_*`, карточка).
4. **Экраны игрока и лидерборды** (`player_stats_with_count`, `_player_group_table`).
5. **Экраны команды и таблицы** (`_team_games_context`, `team_list_text`, турнирная таблица).
6. Что останется (дайджест) — либо остаётся в `bot_messages.py`, либо тоже получает имя.

Границы и имена модулей уточнить по фактическим зависимостям функций перед шагом 2: одна
схема разреза на всю задачу, записанная в первом PR.

**Критерии приёмки.**
- Ни один модуль `telegram_bot/` не длиннее 800 строк.
- `grep -n "push_digest_job" telegram_bot/bot.py` пуст.
- Тесты проходят без изменения утверждений — меняются только импорты.
- Живая проверка на dev-боте: карточка матча, `/tonight`, `/stats`, профиль игрока и команды,
  рассылка.
- `docs/architecture.md` обновлён в каждом PR; `make ci-local` зелёный.

**Подводные камни.**
- Global Constraint 2 разрешает новые модули, только если задача их требует — эта требует;
  число новых файлов держать минимальным (ориентир — четыре-пять).
- Тесты подменяют имена через `monkeypatch` по старому пути модуля: после переноса подмена
  молча перестаёт действовать. Каждую подмену `bot_messages.<имя>` проверить.
- Импорты в пакете плоские (`from bot_messages import …`), циклы проявятся при импорте — после
  каждого шага запускать бота, не только тесты.
- Бюджет в 300 строк считается по чистому приросту; перенос его не расходует, но PR на
  1000 строк диффа ревьюить трудно — отсюда дробление.
- `tests/test_bot_messages.py` (2062 строки) делится по тем же границам отдельным шагом, если
  останется смысл.
