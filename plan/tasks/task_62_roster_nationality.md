# Задача 62. Национальность у игроков, добранных из сводных отчётов

**Блок:** данные · **Надобность:** 🟡
**Область:** `pipeline/load_season_modern.py` (`supplement_rosters_from_reports`, строка ростера
из `/v1/roster` и из landing), их тесты, дозагрузка `rosters.nationality` за прошлые сезоны,
`docs/architecture.md` (раздел о `rosters` и странах).
**Зависит от:** решения человека, что считать страной игрока (см. «Решение до начала»).
**Источник:** найдено в Задаче 61; реестр — [`../open_tasks.md`](../open_tasks.md).

## Кратко

Загрузчик собирает игроков сезона из двух мест. Основное — ростер команды `/v1/roster`:
оттуда в `rosters.nationality` пишется страна (`birthCountry`, страна рождения). Остальных
(вызовы из фарма, короткие отрезки, обмены) `supplement_rosters_from_reports` дописывает из
сводных отчётов `skater/summary` и `goalie/summary`, а в этих отчётах страны нет, и строка
уходит в БД с `nationality = NULL`. Таких игроков не видят подписка на страну, `/countries`
и карточка гола. Нужно заполнять страну у всех и дописать её за прошлые сезоны.

## Зачем и на что влияет

- Подписка «Страна X» (Задачи 61, 64) молча пропускает игроков страны: если такой игрок забил,
  его нет ни в сообщении, ни в видео.
- Рейтинг стран `/countries` недосчитывает игроков и очки, а такие игроки попадают в сноску
  «страна не указана».
- Карточка гола пишет фамилии российских игроков капсом по `*_nationality`
  (`get_goals_game.sql`), а у игрока без страны капса нет.

## Степень важности

🟡. Продукт не ломается, но подписка на страну неполная, а это видно пользователю: в 2025/26
пропущена примерно треть строк ростера.

## Подробно

### Текущее состояние (снимок на 2026-10-08)

Строки `rosters` с `nationality IS NULL` по сезонам. Все они — строки, добранные из сводных
отчётов: у всех `jersey_number IS NULL`, а у строк из `/v1/roster` номер есть. Все эти игроки
сыграли в сезоне (есть строка `players_season_stats` с `games > 0`).

| Сезон | NULL | Всего строк | NULL среди игроков, которые в каком-то сезоне `RUS` |
|---|---|---|---|
| 2021/22 | 0 | 1125 | 0 из 56 |
| 2022/23 | 0 | 1060 | 0 из 59 |
| 2023/24 | 412 | 1072 | 20 из 64 |
| 2024/25 | 209 | 1062 | 8 из 62 |
| 2025/26 | 359 | 1061 | 10 из 64 |
| 2026/27 | 0 | 239 | 0 из 15 |

Последний столбец — нижняя оценка: игрок, у которого страны нет ни в одном сезоне, в нём не
виден. В записи реестра для 2025/26 стоит «15 из 69 русских», это другой способ подсчёта
из Задачи 61. Почему 2021–2023 без пропусков, при заведении карточки не выяснялось.
2026/27 пока чист, потому что в начале сезона почти все игроки есть в `/v1/roster`.

Откуда страна сейчас:
- `/v1/roster/{tri}/{season}` → `birthCountry` (`load_season_modern.py`, строка ростера);
- landing игрока `/v1/player/{id}/landing` → `birthCountry` (`_roster_tuple_from_landing`,
  редкие игроки, которых нет ни в ростере, ни в отчётах);
- `skater/summary`, `goalie/summary` → страны нет (`supplement_rosters_from_reports`).

Что отдаёт NHL API (проверено 2026-10-08):
- Отчёты `stats/rest/en/skater/bios` и `goalie/bios` за сезон содержат обе страны сразу:
  `birthCountryCode` и `nationalityCode`. Это один постраничный запрос на сезон для всех
  игроков: за 2025/26 — 1038 строк, пустых значений нет ни в одном из двух полей.
- Страна рождения и `nationalityCode` за 2025/26 расходятся у 24 из 1038 игроков (2,3%),
  например: Zhilkin `RUS` → `CAN`, Nylander `CAN` → `SWE`, Kaliyev `UZB` → `USA`,
  Chychrun `USA` → `CAN`.
- Клепов (ANA, 8486052): в landing `birthCountry = USA`, `nationality` пустое. В `bios` за
  2025/26 и 2026/27 (на 2026-10-08) его нет, так что `nationalityCode` для него проверить
  не удалось.

### Решение до начала (человек)

Что такое «страна» игрока в боте:
- **(а) Страна рождения** (`birthCountryCode`). Смысл тот же, что у уже заполненных строк:
  меняется только источник для добранных игроков. Родившиеся за границей остаются в стране
  рождения.
- **(б) Национальность** (`nationalityCode`) — ближе к «за какую сборную играет». Меняет смысл
  поля для всех игроков, поэтому переводится на `bios` вся колонка, а не только добранные
  строки: два смысла в одном поле запрещает Global Constraint 3. Затрагивает ~2% игроков, а
  среди уже подписанных стран это видно, например, у `RUS` (Zhilkin уходит в `CAN`).

Карточку переписывать по решению не нужно: решение записывается в реестр, вариант — в итог.

### Что делать

1. Брать страну из отчётов `skater/bios` и `goalie/bios` сезона (поле — по решению выше),
   словарём `playerId → страна`, и заполнять ею строки, добранные из сводных отчётов. При
   варианте (б) тот же словарь заполняет и строки из `/v1/roster` и landing, а `birthCountry`
   там больше не читается.
2. Игрок есть в ростере или отчёте, но нет в `bios` — `NULL` и запись в лог, без догадок
   (Global Constraint 4 — не выдумывать значение; падать здесь не нужно, `NULL` — штатное
   «неизвестно», см. `docs/pipeline_nulls_and_explicit_null_tz.md`).
3. Дописать страну за 2023/24–2025/26 (при варианте (б) — за все пять сезонов) штатной
   перезагрузкой сезона (`make season-load-full` с нужным `SEASON_ID`; сверить, что она
   перезаписывает `rosters`). Отдельный скрипт дозабора — только если штатный путь не
   подходит, и тогда он удаляется после прогона (Global Constraint 1).
4. Обновить описание `rosters.nationality` в `docs/architecture.md`.

### Критерии приёмки

- Тест загрузчика на фикстуре: игрок из `skater/summary` без строки в `/v1/roster` получает
  страну из `bios`; вратарь — из `goalie/bios`; игрок без строки в `bios` остаётся `NULL`.
- На БД после дозагрузки: `SELECT season_id, count(*) FROM rosters WHERE nationality IS NULL
  GROUP BY 1` — ноль или единицы с объяснением, по каждому сезону.
- `/countries` и рассылка «Страна X» за прошлую ночь показывают ранее пропущенных игроков
  (проверить на конкретной ночи 2025/26, где играл игрок, бывший `NULL`).
- `make ci-local` и `make all-tests` зелёные.

### Подводные камни

- `bios` за сезон — постраничный отчёт; брать тем же `fetch_paginated`, что и `summary`.
- После дозагрузки меняются агрегаты по странам: рейтинг `/countries` кэшируется
  (`cached_fetch_all`), проверять после сброса кэша или рестарта бота.
- Номер строки ростера `nationality` — восьмое поле кортежа; при правке трёх мест сборки
  кортежа (ростер, summary, landing) не сдвинуть порядок.
- Ручной список «считать страной X» (случай Клепова) — вне задачи, отдельное решение человека.
