# Задача 78. Подписка «Предстоящие матчи»: превью перед началом

**Блок:** продукт · **Надобность:** 🟡
**Область:** `telegram_bot/push_digest_job.py` (новая рассылка), `telegram_bot/subscription_repo.py`,
меню `/subscriptions` (`telegram_bot/bot.py`), `telegram_bot/bot_messages.py`
(`matchup_season_preview`), `telegram_bot/nhl_scoreboard.py` (время начала), миграция
(новый `kind` в CHECK `bot_subscriptions` и отметка «превью ушло»), расписание
(`pipeline/scheduled_sync.py`), `docs/telegram_bot.md` §7. Часть B — ИИ-текст
(новая зависимость, см. ниже).
**Зависит от:** Задачи 63 (меню `/subscriptions`) и 73 (строка прогноза в превью).
**Источник:** просьба человека 2026-10-23; реестр — [`../open_tasks.md`](../open_tasks.md).

## Кратко

Новая подписка в `/subscriptions` — «Предстоящие матчи». Раз в полчаса подписчик получает
превью матчей, которые скоро начнутся: время начала (МСК), сравнение команд, как в превью
`/tonight`, и строку «🤖 Оценка модели» (73). Каждое превью приходит один раз. Часть B:
короткий текст «на что смотреть в матче», который пишет ИИ по нашим данным.

## Зачем и на что влияет

- Сейчас превью доступно только тому, кто сам открыл `/tonight` и нажал на матч. Подписка
  приносит его к началу игры — так, как подписка на страну приносит итоги.
- Это первая рассылка, которая показывает прогноз модели (73), а не только итоги.

## Степень важности

🟡: новая функция удобства, ничего не блокирует.

## Подробно

**Состояние на 2026-10-23.**
- Подписки: `bot_subscriptions.kind` ∈ {`morning_digest`, `team_scores`, `country_players`}
  (CHECK — миграция 0006). Меню — `/subscriptions` (63).
- Рассылки шлёт `push_digest_job.py` после каждого прогона sync: каждые 30 минут, только в
  ночном окне 18:00–08:00 UTC.
- Время начала матча в БД не хранится: в `scheduled_games` только `day`. `/tonight` берёт
  `startTimeUTC` из NHL API на запрос (`nhl_scoreboard.py`).

**Часть A — превью без ИИ.**
1. Новый `kind` (например, `upcoming_games`) и переключатель в меню `/subscriptions`.
2. Слот раз в 30 минут: матчи, начинающиеся в ближайшие 30–60 минут и ещё не отправленные
   этому подписчику. Время начала берётся из NHL API — тем же разбором, что в `/tonight`.
   Отметка по паре (подписка, матч), как `bot_country_game_sent` в 76.
3. Содержимое — то же, что превью матча в `/tonight` (`matchup_season_preview`): шапка с
   временем МСК, таблица сравнения, строка прогноза, если она опубликована. Слот без матчей
   ничего не шлёт.
4. **Расписание.** Ночное окно sync не покрывает ранние матчи: дневные игры выходных
   начинаются в 16:00–17:30 UTC, раньше 18:00. Варианты — решение человека:
   - **(а)** расширить окно цикла sync для этой рассылки;
   - **(б)** отдельный цикл раз в 30 минут круглосуточно.

**Часть B — ИИ-текст (по решению человека).**
- 2–3 предложения о матче строго по нашим данным: форма, серии, личные встречи, прогноз
  модели. Без выдумок — только факты, переданные в промпт.
- Текст генерируется **один раз на матч**, а не на подписчика, кэшируется и вставляется
  всем. Оценка: ~15 матчей в день × один короткий вызов — центы в день.
- Нужен SDK провайдера — новая зависимость (Global Constraint 5). Для премиум-ИИ
  ([`../premium_ai/`](../premium_ai/)) пакет `anthropic` уже предложен; здесь — то же решение.
  Ключ — только в `.env` и Secret Manager на проде, как токен бота (раздел «Секреты» в
  `CLAUDE.md`).
- Сбой или таймаут ИИ не должен задерживать превью. Превью уходит без текста, сбой виден в
  логе: это осмысленная реакция, а не глушение ошибки (GC4).

**Решения человека, нужные до старта.**
1. Какие матчи: все матчи дня или только матчи команд, на которые подписан пользователь
   (`team_scores`)? Предложение — все, одним сообщением на слот, если в слоте несколько матчей.
2. За сколько до начала: предложение — ближайший слот, в котором до начала ≤ 60 минут.
3. Расписание: (а) или (б) из п. 4.
4. Часть B: делать ли сразу, бесплатно для всех или только для платных подписчиков
   ([`../premium_payments/`](../premium_payments/)); разрешение на зависимость `anthropic`.

**Критерии приёмки.**
- Тесты: переключатель в меню; превью уходит один раз на пару (подписчик, матч); пустой
  слот ничего не шлёт; матч без прогноза — превью без строки модели; сбой ИИ (часть B) не
  мешает отправке.
- Тесты SQL отметки — на БД (`make all-tests`, миграция).
- `docs/telegram_bot.md` §7, `docs/architecture.md` (миграция, модули), `/help`.
- Живая проверка: превью приходит перед ближайшим матчем.
- `make ci-local` зелёный.

**Подводные камни.**
- Перенесённый матч (новое `startTimeUTC`) не должен уйти дважды: отметка — по `game_id`.
- Лимиты Telegram на массовую рассылку — как в существующих рассылках `push_digest_job.py`.
- Превью собирается из БД на момент отправки: прогноз — последняя публикация 12:00 UTC.
