# Задача 158Д. История: итоги сезонов 1917/18–2008/09 в базе

**Блок:** продукт · **Надобность:** 🟡
**Область:** `pipeline/load_season_modern.py` (режим «только сезонные отчёты», NULL вместо
нулей, `franchise_id`, игроки из `bios`), `data_tables/t.teams.sql` и миграция
(`teams.franchise_id`), скрипт загрузки по образцу `scripts/dev_history_load.sh`,
`docs/data_loading.md`, `CLAUDE.md` (ограничение 8).
**Зависит от:** 121 (справочник команд по дате сезона, история 2009/10–2020/21 в базе).
**Открывает:** 156 (ИИ поверх этих данных), 157 (матчи: им нужны строки `teams` и `rosters`
старых сезонов).
**Источник:** разговор с человеком 2026-11-17 — 2026-11-18 «как загрузить историю, чтобы ИИ
отвечал как можно полнее»; исследование —
[`../../docs/history_depth_research.md`](../../docs/history_depth_research.md); реестр —
[`../open_tasks.md`](../open_tasks.md). Разрезана 2026-11-18: часть про ИИ ушла в 156.

## Кратко

Загрузить официальные итоги сезонов (игроки, вратари, команды, составы) за всю историю лиги.
Метрика, которую в сезоне не считали, — NULL, а не ноль. Только данные: что видит ИИ,
меняет 156.

## Зачем и на что влияет

- **Основа для ИИ-ответов** о карьерах, рекордах и лидерах сезонов (156). Классика (голы,
  передачи, очки, игры, штраф) заполнена с 1917/18 полностью — сверено в исследовании.
- **Цена.** 15–20 запросов на сезон и тип игр плюс составы клубов: вся история — часы, матчи
  не нужны.
- **Экраны бота** читают `rosters` и сезонные таблицы с фильтром по `season_id` (проверено
  2026-11-18: `player_display_name`, поиск игрока в `ai_stats.py`, лидеры) — не меняются.
- **Модель.** Датасет закрыт нижней границей (121) и не меняется.
- **ИИ до 156** продолжает говорить «данные с 2009/10», хотя в базе уже больше, — недосказ,
  а не ошибка; обратный порядок (рамка раньше данных) дал бы ложные ответы.

## Степень важности

🟡: качество ответов ИИ; релиз и рассылки от задачи не зависят.

## Подробно

### Текущее состояние (снимок 2026-11-18, перед работой сверять)

- **Что есть на какой глубине** — таблица «Метрики по важности и первый сезон»
  в `docs/history_depth_research.md`.
- **Нули вместо «не считали».** Отчёт `skater/realtime` до 2005/06 отдаёт хиты, блоки, потери
  и отборы как `0`; загрузчик пишет их как есть (`load_season_modern.py:806–810`). Остальные
  отсутствующие метрики API отдаёт null.
- **Режима «только отчёты» нет.** `run()` всегда грузит матчи окна дат
  (`load_season_modern.py:1741`); окно по умолчанию — с начала сезона, то есть для старого
  сезона это все его матчи.
- **Переезды клубов меняют `team_id`** («Квебек» 32 → «Колорадо»). В `stats/rest/en/team`
  есть `franchiseId` (у «Квебека» — 27), в `teams` его нет.
- **Составы.** `/v1/roster/{tri}/{season}` и `/v1/standings/{дата}` отвечают на всей глубине
  (проверено на MTL и 1 марта сезона); до 1967/68 дивизионов нет.
- **Строка сезона игрока — без клуба.** Ключ `players_season_stats` —
  `(player_id, season_id, game_type)`; клуб — только `rosters.current_team_id`, один на сезон.

### Что сделать

1. **Режим «только сезонные отчёты»** — явный флаг загрузчика: `teams`, `teams_stats`,
   `rosters`, `players_season_stats`, `goalies_season_stats`, без матчей и без
   `scheduled_games`. Пустое окно дат как способ не использовать: неявно.
2. **NULL вместо нулей — по факту отчёта, а не по таблице границ.** Для метрик `realtime`
   (хиты, блоки, потери, отборы) и времени на льду: если значение нулевое или пустое
   у большинства игроков отчёта сезона — NULL пишется всем (решение человека 2026-11-18).
   Границы из исследования служат проверкой в приёмке, в код не переносятся: точный сезон
   перелома исследование не гарантирует.
3. **`teams.franchise_id`** — из `stats/rest/en/team`; миграция сначала на `nhl_dev`.
4. **Игроки вне составов** — имя, позиция, страна из отчётов `skater/bios` и `goalie/bios`,
   а не по одному запросу `/v1/player/{id}/landing` на игрока.
5. **Загрузка 1917/18–2008/09 на `nhl_dev`**, регулярка и плей-офф, одной командой для
   человека. Сверка каждого сезона: сумма голов игроков и вратарей = сумма счетов матчей
   (с 2005/06 — минус матчи с буллитами). Счета — из `stats/rest/en/game` (запрос
   `fetch_final_games`), в базу матчи не пишутся.
6. **Прод** — после выкатки кода в `master`, тем же скриптом.
7. **Документация:** `docs/data_loading.md` (режим и загрузка истории), `CLAUDE.md`,
   ограничение 8 (объёмы).

### Критерии приёмки

- В `nhl_dev` итоги всех сезонов 1917/18–2008/09 (кроме 2004/05); сверка голов сходится
  по каждому сезону, расхождения названы поимённо (1917/18 — 2 гола).
- У игрока 1980-х хиты, блоки, время на льду — NULL, а не 0 и не `00:00`; первый сезон
  с ненулевыми хитами — 2005/06, со временем на льду — 1997/98 (как в исследовании).
- Правило «у большинства» не обнуляет ни одну метрику ни в одном сезоне 2009/10+ уже
  загруженной базы (проверка запросом до загрузки истории).
- Сумма сезонных строк Гретцки (регулярка): 1487 игр, 894 гола, 1963 передачи, 2857 очков.
- У «Квебека» и «Колорадо» один `franchise_id`; у нынешней и исторической «Оттавы» — разные.
- `make ci-local` зелёный; `make all-tests` прогнан на базе с историей; экраны текущего
  сезона на dev-боте не изменились.

### Подводные камни

- **Обмен внутри сезона** — в отчёте одна строка с `teamAbbrevs` вида `PHX,PHI`; решить
  и записать, к какому клубу её относит `rosters` (последний). Разбивки «игрок × клуб»
  из сезонных отчётов нет — см. 156.
- **`rosters.currentage`** — возраст на момент загрузки; для прошлых сезонов писать NULL,
  а не сегодняшний возраст.
- **Исчезнувшие клубы** (Montreal Maroons, Ottawa Senators 1917–1934) — свои `team_id`
  и `franchise_id`.
- **Сезон 2004/05 не игрался** — пустой ответ API не ошибка.
- **Ничьи** до 2003/04: у вратарей и команд `ties`, а `otLosses` — null; после — наоборот.
- **Официальные «игры» ≠ сумма по протоколам** (расходится на 1–3 у трети игроков, MTL
  1929/30 и 1975/76) — итоги сезона только из отчётов, из матчей не пересчитывать.
- **Бюджет.** Если флаг, NULL и `bios` вместе выходят за 300 строк — `franchise_id`
  с миграцией вынести отдельным PR.
