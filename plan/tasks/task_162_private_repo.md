# Задача 162. Закрыть репозиторий: private на Free-плане GitHub

**Блок:** релиз · **Надобность:** 🟠
**Область:** `.github/workflows/ci.yml`, `.github/workflows/release.yml` (job `deploy`),
`CLAUDE.md` («Ветки и выкатка»), `DEVELOPMENT.md` (§«Прод-деплой», §«Dev-стенд», разовая
установка VM); настройки GitHub — видимость репозитория и пакета GHCR (делает человек).
**Зависит от:** ничего. С **82** (безопасность) пересекается только проверкой секретов в истории
git: 82 её не покрывает, здесь она — шаг до переключения.
**Источник:** разговор с человеком 2026-11-21 — 2026-11-22; реестр — [`../open_tasks.md`](../open_tasks.md).

## Кратко

Сделать репозиторий и Docker-образы приватными, чтобы код видели только приглашённые и он не
находился поиском, — без покупки GitHub Pro: CI и автодеплой обоих ботов работают как раньше.

## Зачем и на что влияет

- **Код закрыт.** Сейчас `Karych72/NHL_bot` публичный, а образ `ghcr.io/karych72/nhl_bot`
  (весь код внутри) VM тянет без логина — это вторая открытая копия.
- **Поиск.** Приватный репозиторий отдаёт 404 всем, кроме соавторов; поисковики выкидывают его
  из индекса (ускорить — Google Search Console, «Удаление устаревшего контента»).
- **Чем платим (решение человека — без Pro):**
  - защита веток на приватном репозитории Free-плана не применяется: мерж с красным CI и
    force-push в `master` GitHub больше не запрещает — правило переходит в `CLAUDE.md`;
    сами правила в настройках не удалять, с Pro они заработают снова;
  - лимит Actions 2000 мин/мес вместо безлимита. Расход за 2026-10-21 — 11-21 ≈ 2260 мин
    (CI на PR ~970, CI на пуш ~580, Release ~710, по job с округлением вверх); после правок ниже
    ≈ 1680. Исчерпание без карты не списывает деньги — Actions стоят до нового месяца.

## Степень важности

🟠: решение человека закрыть код; пока репозиторий публичный, код и история открыты всем.

## Подробно

### Текущее состояние (снимок 2026-11-21, перед работой сверять)

- `visibility: public`, форков 0, Pages выключены, соавторов нет (только владелец, admin).
- Защита `develop` и `master`: обязательные проверки `quality`, `db-tests`, обязательный PR,
  force-push запрещён.
- `ci.yml` — триггеры `push: [master, develop]`, `pull_request`, `workflow_call`; `release.yml`
  вызывает `ci.yml` перед сборкой образа, так что CI на пуш при выкатке кода — дубль.
- Job `deploy` по SSH на VM делает `git fetch --tags --force origin` — `origin` в `/opt/nhl_bot` и
  `/opt/nhl_bot_dev` склонирован по https без авторизации (`DEVELOPMENT.md` строки 108, 182), —
  и `docker compose pull` из GHCR без `docker login`.
- Других мест, где VM сама ходит в GitHub (скрипты с `git pull`, `compose pull`), нет.

### Что сделать

**Код (одна ветка, PR в `develop`, ~30 строк):**

1. `ci.yml`: убрать триггер `push`; добавить `concurrency` с `cancel-in-progress: true` по ссылке
   PR — новый пуш в ветку отменяет устаревший прогон. Группа не должна совпасть у вызова из
   `release.yml`, иначе CI отменит сам себя.
2. `release.yml`, job `deploy`: `permissions: contents: read, packages: read`; на VM —
   `git fetch` по https-адресу с временным `GITHUB_TOKEN` прогона (токен не записывается в
   `.git/config`), `docker login ghcr.io` тем же токеном перед `pull`, `docker logout` после
   `up`. На VM не остаётся ни ключей, ни долгоживущих токенов; «Re-run jobs» для отката получает
   свежий токен. Токен не должен попасть в лог и в `argv` удалённых процессов.
3. `CLAUDE.md`, «Ветки и выкатка»: «обе ветки защищены (мерж только PR с зелёным CI)» →
   защита на Free не применяется, агент мержит только после `gh pr checks <N> --watch` с зелёным
   итогом.
4. `DEVELOPMENT.md`: как деплой получает доступ к приватному репозиторию и GHCR; разовая
   установка новой VM — первый `git clone` с личным токеном; лимит минут и где смотреть расход.
5. До переключения — поиск секретов в истории git (токен Telegram, ключи GCP, пароли из `.env`,
   `DEPLOY_SSH_KEY`) без новых зависимостей. Найденное — в отчёт без значений и человеку на
   перевыпуск: закрытие репозитория утечку не отзывает.

**Человек (после мержа и зелёного деплоя dev-бота; порядок важен — закрытый до мержа пакет
уронит деплой на `docker pull`):**

6. Пакет GHCR `nhl_bot` → Package settings → Change visibility → Private (только веб-интерфейс).
7. Репозиторий → private: Settings → Danger Zone или
   `gh repo edit Karych72/NHL_bot --visibility private --accept-visibility-change-consequences`.
8. Ручной запуск Release на `develop` — dev-бот выкатился зелёным; инкогнито: репозиторий и
   `docker pull ghcr.io/karych72/nhl_bot:<тег>` без логина недоступны.
9. По желанию — Google Search Console, удаление устаревшего контента.

### Критерии приёмки

- PR задачи смерджен, следующий деплой dev-бота зелёный уже с токеном.
- Репозиторий и пакет приватные; анонимно репозиторий отдаёт 404, `docker pull` без логина
  отказывает.
- Деплой прода (первый релиз `develop → master` после переключения) зелёный.
- CI на PR работает, на пуш в `develop`/`master` отдельно не запускается; Release по-прежнему
  гоняет CI перед образом.
- Отчёт о поиске секретов в истории: что проверено, найдено ли (без значений).

### Подводные камни

- `${{ secrets.GITHUB_TOKEN }}` внутри heredoc на VM подставляется Actions до запуска shell —
  передавать через `env` job и stdin, а не командной строкой.
- `docker image prune -af` в конце деплоя не трогает используемые образы, но ручной
  `docker compose pull` на VM после деплоя без логина уже не сработает — описать в `DEVELOPMENT.md`.
- Расход минут проверить через месяц после переключения (Settings → Billing); при упоре в
  лимит — self-hosted runner на VM (отдельной задачей, e2-small делит ресурсы с ботами) или Pro.
