# Задача 58. `/tonight`: live-карточка идущего матча

**Блок:** продукт · **Надобность:** 🟡 (после 57)
**Область:** `telegram_bot/stats_handlers.py` (`callback_tonight_game`),
`telegram_bot/nhl_scoreboard.py`, `telegram_bot/bot_messages.py`, `tests/`.
**Источник:** просьба человека 2026-10-05; реестр — [`../open_tasks.md`](../open_tasks.md).

## Кратко

Нажатие на матч в `/tonight` сейчас даёт полную карточку, если игра есть в БД, иначе — превью
сезонных встреч. Идущий матч в БД не попадает до `OFF` (Задача 56), поэтому по нему видно только
превью. Нужна короткая live-карточка из NHL API: счёт, период и время, голы с авторами.

## Подробно

- Источник — `gamecenter/{id}/landing` (`summary.scoring` — голы по периодам, `clock`,
  `periodDescriptor`), запрос на нажатие, без записи в БД и без диск-кэша загрузчика.
- Ветвление в `callback_tonight_game`: в БД → полная карточка (как сейчас); `LIVE`/`CRIT`/
  `FINAL` по API → live-карточка с пометкой «идёт» / «финал, статистика появится после
  утверждения»; `FUT`/`PRE` → превью (как сейчас).
- Кнопка «Обновить» на live-карточке редактирует то же сообщение; повторные нажатия не плодят
  сообщения (как Задача 53). Частоту запросов к API ограничить коротким TTL (30–60 с) на
  `game_id` — переиспользовать `ttl_cache`-подход `database.py`, если ложится без копии.
- Формат голов — тот же, что в карточке матча (Задача 48), без дублирования рендера.

**Критерии приёмки.** Тесты на ветвление по состоянию и рендер на реальной фикстуре `landing`
живого матча; ручная проверка в Telegram во время игры.
