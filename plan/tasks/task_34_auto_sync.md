## Кратко

Все цели `season-sync-*` — ручные. Ни в `.github/workflows/` (там только `ci.yml` на
push/PR), ни в `docker-compose.yml` (сервисы `db` и `bot`) загрузчик по расписанию не
запускается. Нужно, чтобы данные обновлялись минимум раз в сутки без человека, неуспех
был виден, а повторный прогон по уже загруженным дням был безопасен.

## Зачем и на что влияет

- **Зачем.** Всё, что показывает бот — `/day_games`, `/today`, `/table`, `/leaders`,
  `/game`, рассылки по подпискам — читается из PostgreSQL. Без расписания выпущенный бот
  протухает за сутки: последний игровой день в базе перестаёт двигаться.
- **На что влияет.** Появляется первый фоновый процесс рядом с ботом: сервис в compose
  либо запись cron/launchd на хосте. Утренняя рассылка `telegram_bot/push_digest_job.py`
  уже спроектирована как cron-скрипт «после загрузки данных» (шапка модуля) — её запуск
  встаёт в ту же цепочку. Задача 26 (retrain) позже сядет в тот же планировщик.
- **Если не делать.** Релиз превращается в ежедневную ручную обязанность
  `make season-sync-today`; пропущенный день — пропущенный дайджест.

## Подробно

### Текущее состояние (сверено 2026-09-22)

- `Makefile:220-238`: `season-load-full` (от `SEASON_START` до сегодня); `season-sync-week`
  — `date -v-7d` (`Makefile:228`), синтаксис BSD/macOS, в Linux-cron команда упадёт;
  `season-sync-month` уже переносим — `MONTH_AGO` считается Python-ом (`Makefile:52`);
  `season-sync-today` — один календарный день.
- Загрузчик пишет игры одной транзакцией DELETE→INSERT («Снято по итогам валидации»
  в плане 08-08) — повторная загрузка того же окна идемпотентна по построению; финальные
  ответы API лежат в диск-кэше (Задача 31), повторный прогон по завершённым играм не
  ходит в сеть.
- Загружаются только завершённые игры (`gameStateId=7`, `load_season_modern.py:781`).
- `push_digest_job.py`: одноразовый скрипт, поднимает `Application` без polling,
  рассылает и выходит; требует `ENABLE_PUSH_DIGEST=1` и загруженную БД.

### Что нужно сделать

1. **Выбрать площадку расписания** — согласованно с Задачей 35:
   - хостовый `cron`/`launchd`, вызывающий `make season-sync-…` и затем
     `push_digest_job.py` — минимум кода, совпадает с тем, как задуман push-скрипт;
   - сервис в `docker-compose.yml` (загрузчик с планировщиком внутри) — самодостаточный
     стек, но новый образ и цикл.
   GitHub Actions не подходит, пока БД слушает loopback хоста: из облака она недоступна.
2. **Переносимое окно дат.** Заменить `date -v-7d` в `season-sync-week` на вычисление
   через Python по образцу `MONTH_AGO`. Суточному прогону брать окно «вчера + сегодня»
   (лучше 2–3 дня назад): матчи заканчиваются поздно вечером по Северной Америке, и запуск
   «за сегодня» пропускает вчерашние финалы, если случился до их завершения.
3. **Видимость отказа** (Global Constraint 4). Ненулевой код выхода загрузчика не глотать:
   лог прогона с датой и итогом, статус последнего запуска в согласованном месте
   (файл, таблица или `docker compose ps`). Молчаливый отказ cron равен протухшим данным.
4. **Идемпотентность — проверить, а не предположить:** прогнать одно окно дважды,
   сравнить `count(*)` по `games`, `all_goals`, `game_player_stats`.
5. **Документировать** в `DEVELOPMENT.md`: где живёт расписание, как запустить руками,
   где смотреть последний результат.

### Критерии приёмки (из реестра)

- Загрузчик идёт по расписанию без участия человека, минимум раз в сутки.
- Окно дат вычисляется переносимо (`date -v-7d` убран).
- Неуспешный прогон виден.
- Повторный прогон по уже загруженным дням идемпотентен.

### Проверка

- Через сутки после включения `SELECT max(day) FROM games WHERE season_id = <текущий>`
  сдвинулся без ручного запуска.
- Намеренно сломанный прогон (например, неверный `PG_HOST`) заметен там, куда
  договорились смотреть.
- `make season-sync-week` отрабатывает в Linux-контейнере.

### Подводные камни

- Загрузчику нужны `.env` и сеть к NHL API; в compose-варианте — тот же `env_file`,
  что у бота, и `PG_HOST=db`.
- Наложение двух копий (cron поверх ручного запуска): транзакция переживёт, но lock-файл
  или `flock` дешевле разбирательств.
- Не смешивать с Задачей 26: здесь только загрузка и рассылка; retrain сядет в этот
  планировщик позже.
