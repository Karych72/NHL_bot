# Задача 67. Голевая модель v1

**Блок:** трек B · **Надобность:** 🔴 (для трека B) · **Зависит от:** 66
**Область:** `modeling/` (новое семейство модели, таргеты голов), `modeling/dataset_builder/`

разделы «Модель голов…» и «Признаки…»). Реестр — [`../../open_tasks.md`](../../open_tasks.md).

## Кратко

Модель предсказывает ожидаемые голы **основного времени** хозяев и гостей (λ_h, λ_a), из них —
сетку счёта и вероятности: P(победа хозяев с OT/SO) и P(тотал > L) для любой линии L.
Заменяет бинарные классификаторы `home_win`/`over_5_5`.

## Зачем и на что влияет

- Бинарный `over_5_5` хуже константы (Задача 40): счёт 3:2 и 7:5 для него одинаковы,
  а правило «+1 при ничьей» ему приходится выучивать. Голевая модель задаёт его формулой.
- Одна модель даёт обе вероятности согласованно и тотал на любой линии — нужно, чтобы
  сравнивать с реально выставленной линией (букмекеры чаще двигают цену, чем число).

## Степень важности

🔴 для трека B: ядро всего трека.

## Подробно

### Модель

- Poisson GLM на «сложенных» командо-играх (по две строки на игру):
  log E[G] = β0 + β_home + атака_i − оборона_j + ковариаты; ridge (`alpha`) и веса по давности
  w = exp(−ξ·Δt), ξ и α — по walk-forward (Задача 66). Реализация — `sklearn.linear_model.PoissonRegressor`
  + `scipy.stats.poisson`; новых пакетов нет.
- Сетка P(i, j), i, j = 0…14; однопараметрическое раздувание диагонали (ничьи), перенормировка.
- P(home win) = Σ_{i>j} P(i,j) + p_tie · q_home; q_home — константа (+ наклон по разнице сил)
  на ~1 460 играх с OT/SO из БД.
- **Тотал по правилу букмекеров:** ничья после 60 минут даёт ровно +1 гол (OT до первой шайбы
  или +1 за буллиты). P(Over L) = Σ_{i≠j, i+j>L} P(i,j) + Σ_{2i+1>L} P(i,i).
- Ковариаты v1: силы команд (сам GLM), отдых/back-to-back, дом; Elo — как ковариата, если
  улучшает walk-forward. Априор на старте сезона: прошлогодняя сила со сжатием ~30% к среднему,
  без выброса первых игр (нынешний `min_prior_games=5` теряет ~10% сезона).
- Голы в пустые ворота в v1 остаются в таргете; если калибровка по корзинам λ_h+λ_a покажет
  перекос — двухстадийная схема (карточка не расширяется, отдельная задача).

### Данные — ловушки

- Таргет — `fst_period_goals + snd_period_goals + trd_period_goals` (`game_team_stats`), не `goals`:
  `goals` хранит финальный счёт с +1 победителю буллитов.
- `is_overtime` истинен и для буллитов: REG = `NOT is_overtime`, OT = `is_overtime AND NOT is_shootouts`,
  SO = `is_shootouts`.
- `all_goals` содержит голы серии буллитов (`period = 5`) — в любых выборках фильтровать.
- Инвариант «Σ `goals` = Σ голов периодов + `is_overtime`» — тест на настоящей БД.

### Критерии приёмки

- На walk-forward (66): `home_win` log-loss не хуже Elo-baseline; тотал 5.5 — log-loss ниже
  константы с ДИ, не включающим 0, на объединённой выборке.
- Калибровка p_tie по сезонам в пределах ±2 п.п.
- `make ci-local` зелёный; `make all-tests` — если тронуты SQL/загрузчик.

### Подводные камни

- Чистый прирост, скорее всего, > 300 строк — разбить при заведении (модель+сетка / признаки /
  перевод publish и retrain).
- Нельзя учить на фактическом стартере вратаря из boxscore — это Задача 70 и утечка.
