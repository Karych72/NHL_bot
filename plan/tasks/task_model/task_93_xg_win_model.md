# Задача 93. Модель победы: доля xG вместо доли бросков

**Блок:** трек B · **Надобность:** 🟡 · **Зависит от:** 68 ✅, 69 ✅; после 74 (обе меняют модель победы)
**Область:** `modeling/dataset_builder/` (признак), `modeling/xg_model.py` (переиспользование),
`deploy/models/home_win/` (если признак принят), `docs/modeling_training.md` §2c.
**Источник:** разговор с человеком 2026-10-28 «можно ли поднять качество модели»;
[`research/notes/goal_models.md`](research/notes/goal_models.md) (xG — лучший предиктор будущих
голов, чем прошлые голы), [`research/notes/features_and_benchmarks.md`](research/notes/features_and_benchmarks.md) §1
(моменты — 54% веса MoneyPuck). Реестр — [`../../open_tasks.md`](../../open_tasks.md).

## Кратко

Проверить в модели победы (68) долю xG команды (EWMA `xGF / (xGF + xGA)`) вместо или вместе с
долей бросков `diff_shot_share_ewm`. Свой xG и броски за пять сезонов уже есть (69), в модель
победы xG ещё не пробовали — только ковариатами голевой модели, где тотал он не сдвинул.

## Зачем и на что влияет

- Доля бросков — второй по силе признак модели победы (стандартизованный коэффициент +0.235,
  у `diff_elo` +0.243), но все броски в ней равны: бросок от синей линии весит как добивание.
  xG взвешивает их по качеству (наш AUC 0.74–0.75, корреляция с MoneyPuck 0.89–0.97).
- Отрицательный итог 69 касается тотала, где силы команд упёрлись в общий потолок; про победу
  он ничего не говорит.
- Данные и инструменты готовы: `shot_attempts` грузится вместе с игрой, `prepare_shots` /
  `fit_xg` / `predict_xg` и схема EWMA доли бросков — в репозитории. Ни миграции, ни нового
  источника не нужно — самый дешёвый из оставшихся кандидатов на прирост.

## Степень важности

🟡: качество модели, бот и рассылки не меняются.

## Подробно

### Что сделать

1. **xG бросков без утечки.** Для признаков сезона `S` xG-модель обучается на сезонах `< S` —
   как в `evaluate_xg_model`; первый сезон данных — разогрев, в проверку 66 он не входит. Для
   прогноза — модель на всех сыгранных сезонах. Где хранить обученную xG-модель для `predict`
   (обучать в `build-dataset` или класть артефакт рядом с `home_win`) — решить в начале задачи
   по замеру времени обучения; новый артефакт — только если обучение заметно тормозит сборку.
2. **Признак.** xGF и xGA команды за игру → доля `xGF / (xGF + xGA)` → EWMA той же схемой, что
   `shot_share_ewm` (полураспад, сжатие к 0.5 на границе сезона, состояние на начало дня).
   Схему EWMA не копировать, а обобщить существующую функцию по входной колонке (GC1, мандат
   ревьюера о дублировании).
3. **Кандидаты — ровно два**, чтобы не подбирать под шум: (а) `diff_xg_share_ewm` вместо
   `diff_shot_share_ewm`; (б) оба признака. Полураспад — тот же, что у доли бросков.
4. **Проверка** — схема 66 против текущей модели победы (после 74 — против её итога).
5. **Если принят** — новый набор `model_features`, retrain, модель в `deploy/models/home_win/`;
   не принят — признак и обобщение удаляются из кода (GC3), остаётся запись итога в §2c.

### Критерии приёмки

- ДИ разности log-loss «кандидат − текущая модель» целиком ниже 0 на схеме 66, ECE не хуже
  текущей; иначе признак не включается.
- Итог обоих кандидатов (log-loss по сезонам, ДИ, ECE) записан в `docs/modeling_training.md` §2c,
  включая отрицательный.
- xG признака сезона `S` посчитан моделью, не видевшей бросков сезона `S` (тест).
- `make ci-local` зелёный.
