## Кратко

Загрузчик уже разбирает play-by-play для `all_goals`. Расширить разбор: все попытки бросков
пишутся в таблицу БД; по ним — собственная xG-модель и командные xGF/xGA как ковариаты
голевой модели. Сырой JSON в БД не хранится — только нужные поля.

## Зачем и на что влияет

- xG — самый весомый признак у лучшей публичной модели (MoneyPuck: 54% веса). У нас его нет.
- Готовый xG MoneyPuck — только для некоммерческого использования; для платного бота нужен свой.

## Степень важности

🟡: следующий по ценности прирост после голевой модели; без него модель работает.

## Подробно

### Что сделать

1. Таблица бросков (~110 на игру, ~700 тыс. строк за 5 сезонов): `game_id`, период, время,
   команда, тип события (shot-on-goal / missed-shot / blocked-shot / goal), `x`, `y`,
   тип броска, `situationCode`, бросающий, `goalieInNetId`. Миграция + парный DDL.
2. Разбор в существующем проходе PBP загрузчика, не отдельным механизмом (GC2). Бэкфилл
   5 сезонов — из дискового кэша, где он есть, иначе из NHL API (~6 560 запросов).
3. Fenwick-xG (незаблокированные попытки; у заблокированных нет `shotType`): логистическая
   регрессия на расстоянии, угле, типе броска, составе, признаке подбора — sklearn.
4. Командные xGF/xGA с весами по давности — ковариаты GLM Задачи 67.

### Критерии приёмки

- xG-модель: AUC и log-loss на отложенном сезоне; сверка сумм xG за сезон с MoneyPuck
  (только как проверка, их данные не попадают в продукт).
- xG-ковариаты улучшают log-loss голевой модели на walk-forward (66); не улучшают — не включаются.
- `make all-tests` зелёный (новая таблица, загрузчик).

### Подводные камни

- Доля бросков без координат не измерена — проверить до обучения.
- Нормировка сторон: `homeTeamDefendingSide` меняется по периодам.
- Бюджет: таблица+загрузчик и xG-модель — две подзадачи.
