## Кратко

Добавить в модель победы (68), а затем в голевую (67) качество вратарей команды: рейтинг
каждого вратаря as-of (сейвы сверх ожидаемых по нашему xG, сжатый к среднему), а в признак игры —
смесь вратарей команды по доле стартов до игры. Фактический стартер матча в прогноз не идёт.

## Зачем и на что влияет

- Вратари — второй по весу блок у MoneyPuck (29%, моменты — 54%, «умение выигрывать» — 17%).
  У нас вратарей в моделях нет вовсе: это самый крупный пропущенный сигнал.
- Для победы прирост вероятнее, чем для тотала: в тотале силы команд упёрлись в потолок около
  −0.001 (67), а модель победы ещё отстаёт от публичных (0.6688 против 0.648–0.661 у MoneyPuck).
- MoneyPuck годами прогнозировал без подтверждённого стартера, смесью по доле игр, — режим,
  который нам доступен без внешнего источника.

## Степень важности

🟡: самый вероятный прирост качества, но с честным ограничением — без стартера модель уступает
рынку в играх со сменой вратаря.

## Подробно

### Что сделать

1. **Флаг стартера.** Колонка `starter` в `game_goalie_stats` (миграция) из boxscore; бэкфилл
   пяти сезонов — из дискового кэша `all_data/raw/` без запросов к API; нет флага — вратарь с
   наибольшим TOI. Флаг нужен только для истории: считать долю стартов.
2. **Рейтинг вратаря as-of.** Сейвы сверх ожидаемых (GSAx) на xG Задачи 69: ожидаемые голы по
   броскам в створ против вратаря минус пропущенные, на 1 бросок; многосезонный, с затуханием и
   сжатием к среднему лиги (у запасных мало бросков). Состояние на начало игрового дня, как у Elo.
3. **Признак команды.** Смесь рейтингов вратарей команды, взвешенная по доле стартов за окно до
   игры, — одинаково в обучении и в прогнозе. Фактический стартер матча в признак **не** входит
   ни там, ни там: в прогнозе он неизвестен, а признак обучения, построенный на нём, — утечка.
4. **Модель победы (68).** Кандидат — `diff_goalie` (разница смесей хозяев и гостей) пятым
   признаком логрега. Не больше двух вариантов формы (окно доли стартов, сила сжатия), чтобы
   не подбирать под шум.
5. **Голевая модель (67).** Ковариата вратаря соперника в Poisson GLM; проверка той же командой
   `evaluate-goals` — это последняя проверка, которой ждёт приёмка 67.
6. Итоги обеих проверок — в `docs/modeling_training.md` §2b и §2c, включая отрицательные.

### Решения человека

- 2026-10-14: внешний источник стартеров (DailyFaceoff и т.п.) не подключаем; NHL API стартера
  до игры не отдаёт — режим «смесь по доле стартов». Предлагать заново не нужно.

### Критерии приёмки

- Модель победы: ДИ разности log-loss «с вратарями − текущая модель» целиком ниже 0 на схеме 66,
  ECE не хуже текущей; иначе признак не включается, итог записан в §2c.
- Голевая модель: результат `evaluate-goals` с ковариатой вратаря записан в §2b; если тотал бьёт
  константу с ДИ без 0 — снова приёмка 67.
- Фактический стартер не используется ни в обучающих, ни в прогнозных признаках (тест на
  признак: он не меняется, если поменять `starter` в игре, для которой он считается).
- `make ci-local` зелёный; `make all-tests` зелёный (миграция, загрузчик).
