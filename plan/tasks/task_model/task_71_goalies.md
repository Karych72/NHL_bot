# Задача 71. Вратари

**Блок:** трек B · **Надобность:** 🟡 · **Зависит от:** 67
**Область:** `pipeline/` (флаг стартера), `game_goalie_stats` (миграция), `modeling/dataset_builder/`.
**Источник:** исследование 2026-10-09 ([`research/report_model_vs_bookmaker.md`](research/report_model_vs_bookmaker.md),
раздел «Признаки…», абзац о вратарях). Реестр — [`../../open_tasks.md`](../../open_tasks.md).

## Кратко

Добавить в голевую модель качество вратарей: исторический стартер (флаг `starter` из boxscore),
регрессированный многосезонный рейтинг вратаря (GSAx-подобный), в прогнозе — смесь вратарей
команды по доле игр.

## Зачем и на что влияет

- Вратари — второй по весу блок у MoneyPuck (29%); отраслевые оценки разницы «основной/запасной» —
  3–10 п.п. победы и ~0.5 гола тотала (методология не раскрыта).
- Рынок учитывает подтверждённого стартера; NHL API его до игры не отдаёт. Без внешнего
  источника модель структурно отстаёт от закрытия в играх со сменой вратаря.

## Степень важности

🟡: заметный прирост, но с честным ограничением без источника стартеров.

## Подробно

### Что сделать

1. Флаг `starter` в `game_goalie_stats` из boxscore (кэш/API); при отсутствии — max TOI.
2. Рейтинг вратаря as-of: сейвы сверх ожидаемых (на xG Задачи 69, если она сделана; иначе
   на средний % сейвов), многосезонный, сжатый к среднему.
3. Ковариата команды в прогнозе — смесь вратарей по доле стартов за окно, **не** фактический
   стартер матча (утечка: стартер известен только после игры).
4. Модель победы (68) — та же ковариата, по тому же правилу: включается, только если улучшает.

### Решение человека

Подключать ли источник подтверждённых стартеров (DailyFaceoff и т.п.; условия использования
неясны, коммерческого разрешения не найдено). Без него — режим «смесь по доле игр».

### Критерии приёмки

- Улучшение log-loss на walk-forward (66) без использования фактического стартера в прогнозе;
  нет улучшения — признак не включается.
- `make all-tests` зелёный (миграция, загрузчик).
