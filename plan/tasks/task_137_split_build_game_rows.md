# Задача 137. Разбить `build_game_rows` и `run()` загрузчика

**Блок:** инженерия · **Надобность:** 🟡 (после 135, 136)
**Область:** `pipeline/load_season_modern.py`, `tests/test_pipeline_game_rows.py`,
`docs/data_loading.md`.
**Зависит от:** Задачи 135 (страховка) и 136 (именованные строки — иначе делить придётся
дважды).
**Источник:** ревизия качества кода 2026-11-16, просьба человека завести задачи; реестр —
[`../open_tasks.md`](../open_tasks.md).

## Кратко

Функция на 489 строк, которая в одном цикле строит строки семи таблиц, делится на функции по
таблицам. `run()` на 425 строк — на шаги «скачать», «построить», «записать».

## Зачем и на что влияет

- `build_game_rows` — самая сложная функция проекта: цикломатическая сложность 95 при пороге
  10, вложенность 5. Правка статистики одной таблицы требует удержать в голове остальные шесть.
- Шесть одинаковых блоков «счётчик по команде» повторяются дословно.
- Файл целиком — 2210 строк, около 27 тысяч токенов на каждую правку загрузчика.

## Степень важности

🟡: удобство правки и расход контекста. Работает корректно, поэтому не срочно.

## Подробно

**Текущее состояние (снимок 2026-11-16, `origin/develop` = `5a97128`; строки сверять).**
- `build_game_rows` — `:1108-1596`: игры, командная статистика, статистика игроков и вратарей,
  голы, броски, три звезды.
- Счётчики по команде — `:1322-1353`, шесть одинаковых блоков.
- `add_skater` / `add_goalie` (`:578-627`) и хвосты трёх построителей строк ростера отличаются
  одной-двумя константами.
- `run()` — `:1712-2136`: сложность 5, то есть это длинная линейная последовательность записей
  по таблицам.
- Мёртвое: `team_abbrev_by_id` (`:254`, `:324`) нигде не читается; ветка `DO NOTHING`
  (`:1643-1644`) недостижима; отладочные `logger.debug("… sample keys")` (`:773`, `:788`,
  `:860`).

**Что делать.** По PR на шаг, каждый — без изменения результата:
1. Удалить мёртвое из списка выше.
2. Выделить из `build_game_rows` разбор play-by-play (счётчики по команде одной функцией
   вместо шести блоков, голы, броски).
3. Выделить строки игроков и вратарей, затем три звезды. В `build_game_rows` остаётся цикл по
   играм, вызывающий построители.
4. `run()` разделить на шаги с понятными именами; транзакция остаётся одна.

**Критерии приёмки.**
- Ни одна функция в `pipeline/` не длиннее 100 строк и не сложнее 15
  (`ruff check pipeline --select C901 --config 'lint.mccabe.max-complexity=15'`).
- Тесты построителей и DB-тест Задачи 135 зелёные без изменения утверждений.
- Загрузка одного игрового дня на `nhl_dev` даёт те же строки, что до задачи.
- `make ci-local` и `make all-tests` зелёные.

**Подводные камни.**
- Новый модуль не заводить (Global Constraint 2): функции остаются в `load_season_modern.py`.
  Делить файл — отдельное решение, если после задачи он останется неудобным.
- Сеть в `run()` выполняется целиком до открытия соединения с БД, запись — в одной транзакции
  с `rollback` и повторным `raise`. Оба свойства сохранить.
- Порядок DELETE и INSERT согласован с внешними ключами — при разделении `run()` не менять.
- Находки ревизии о корректности (`to_int` с нулём по умолчанию, повтор любой ошибки в
  `get_json`, подсчёт большинства по всем штрафам, затирание номера и возраста в `rosters`)
  в эту задачу не входят: рефакторинг и исправление поведения не смешивать.
