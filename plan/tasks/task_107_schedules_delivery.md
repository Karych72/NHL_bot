# Задача 107. Расписания: хранение, доставка экранов по времени, список в `/subscriptions`

**Блок:** продукт · **Надобность:** 🟡
**Область:** `data_tables/migrations/0020_bot_schedules.{up,down}.sql` (номер сверить с
`origin/develop` перед PR), новый `telegram_bot/schedule_repo.py` (таблица и расчёт времени),
`telegram_bot/bot.py` (тикер в `main()`, блок «⏰ Расписания» в `/subscriptions`, рендер экранов
по `chat_id`), `telegram_bot/subscription_repo.py` (`deactivate_chat`), тесты
`tests/test_bot_schedules.py`, `tests/test_db_nhl.py`, `docs/architecture.md`, `docs/telegram_bot.md`.
**Зависит от:** ни от чего. Создание расписаний из текста — Задача 108 (после этой).
**Источник:** обсуждение с человеком 2026-11-01; реестр — [`../open_tasks.md`](../open_tasks.md).

## Кратко

Пользователь получает выбранный экран бота (профиль клуба, лидеров по голам, процент отражённых,
страну, `/standings` …) регулярно: раз в день, раз в неделю в выбранный день или раз в месяц в
выбранное число, в своё время и в своём часовом поясе. Эта задача — фундамент: таблица
расписаний, расчёт следующей отправки, «будильник» в процессе бота, который шлёт экран, и список
с удалением в `/subscriptions`. Форма создания (ИИ разбирает текст → карточка с кнопками) — 108.

## Зачем и на что влияет

- **Подписки сейчас без времени.** Задача 63 убрала время доставки: всё уходит одной рассылкой
  после загрузки ночи. Рассылки запускает сервис `sync` по своей сетке (ночью 18:00–08:00 UTC и
  днём с 12:30 UTC), поэтому в 9 утра или в полночь он ничего отправить не может. Расписаниям
  нужно любое время суток — для остальных подписок решение 63 не меняется.
- **Регулярный экран — то, что пользователь и так открывает руками.** Отчёт — не новый текст ИИ, а
  ровно тот экран, который пользователь получил бы командой (решение человека 2026-11-01).
- **Премиум получает понятную фичу:** бесплатным — одно расписание, премиуму — без лимита.

## Степень важности

🟡: качество и удобство, ничего не блокирует. Расширяет премиум (96 ✅), не зависит от 97.

## Подробно

**Состояние на 2026-11-01** (`origin/develop` = `af7e561`).
- Экраны, которые умеет открывать ИИ, — `bot.AI_SCREENS` (`bot.py:564`): `open_command`
  (`AI_COMMANDS`: today, tonight, standings, team, stats, team_stats, countries, subscriptions,
  help), `digest_for_date`, `team_profile`, `leaders`, `country_players`, `advanced_metric`. Все
  принимают `Message` и отвечают в его чат; часть — уже чистые функции «параметры → (текст,
  кнопки)» (`stat_page_reply`, `country_page_reply`, `team_profile_text`).
- Рассылка без `Message` уже есть в `push_digest_job.py`: `dispatch_day_digest_messages(bot,
  chat_id, …)`, `_throttled`, `TelegramForbiddenError` → `subscription_repo.deactivate_chat`.
- Бот — один долгоживущий контейнер `bot` (`restart: unless-stopped`), `main()` —
  `start_polling()` (`bot.py:781`). Dev-бот и прод — каждый со своей базой.
- Последняя миграция на `origin/develop` — `0019_games_game_type`.

**Решения человека 2026-11-01.**
- Расписание — пара «экран + параметры» из `AI_SCREENS` плюс время. Новых отчётов нет.
- Частота: день / неделя (день недели) / месяц (число 1–28 или «последний день»).
- Время — шаг 30 минут (10:00, 10:30 …); пояс — IANA-зона, по умолчанию `Europe/Moscow`.
- «Будильник» — в процессе бота, не отдельный сервис: без нового контейнера, деплой тот же.
  Если рассылки начнут тормозить ответы, вынести в сервис по образцу `sync` без смены таблицы.
- Изменение расписания — удалить и создать заново; кнопки «изменить» нет.
- Лимит: бесплатным — 1 активное расписание, премиуму — без лимита.

**Что делать.**

1. **Миграция `bot_schedules`** (только миграция, без `t.*.sql` — как `bot_subscriptions`):
   `id`, `chat_id`, `screen text` (ключ `AI_SCREENS` либо `digest_last_night`), `params jsonb`,
   `freq text CHECK (freq IN ('day','week','month'))`, `weekday smallint` (1–7, только `week`),
   `month_day smallint` (1–28 или 0 = последний день, только `month`), `local_time time`
   (CHECK: минуты 0 или 30), `timezone text`, `next_run_at timestamptz NOT NULL`, `active`,
   `created_at`. CHECK на согласованность `freq` ↔ `weekday`/`month_day`. Индекс
   `(next_run_at) WHERE active`. Триггер истории `bot_subscription_events` (99) не трогать.
2. **`schedule_repo.py`:** `next_run_at(freq, weekday, month_day, local_time, tz, after)` — чистая
   функция на `zoneinfo` (stdlib): ближайший момент строго после `after`; несуществующее
   локальное время при переходе на летнее время — сдвиг вперёд, неоднозначное — первое
   вхождение. Плюс `create`, `list_for_chat`, `delete`, `due(now)`, `advance(id, now)`,
   `count_active(chat_id)`. Неизвестная зона — `ValueError` при создании (громко, GC4).
3. **Рендер по `chat_id`.** Для каждого допустимого экрана — функция `(bot, chat_id, params)`:
   чистые экраны — через существующие функции «параметры → (текст, кнопки)»; `today`, `tonight`,
   `standings` и прочие `cmd_*` — вынести тело в функцию от `(bot, chat_id)`, команда зовёт её
   (без второй копии, Мандат ревьюера). Не ставятся на расписание: `subscriptions`, `help`;
   `digest_for_date` с фиксированной датой заменяет `digest_last_night` (ночь по
   `push_digest_job.night_of`). Набор допустимых экранов — один словарь рядом с `AI_SCREENS`.
4. **Тикер.** В `main()` рядом с `start_polling()` — asyncio-задача: раз в минуту `due(now)` →
   отправка → `advance` (следующая отправка от `now`, поэтому после простоя бота уходит одна
   пропущенная отправка, а не все). Блокирующие запросы БД — `asyncio.to_thread`. Отправка — через
   `_throttled` из `push_digest_job` (вынести в общий модуль, если импорт тянет лишнее).
   `TelegramForbiddenError` → `deactivate_chat`, который теперь гасит и расписания. Любая другая
   ошибка одного расписания логируется с `id` и не останавливает тикер — осмысленная реакция:
   остальные чаты должны получить своё (GC4); `next_run_at` при этом всё равно сдвигается.
5. **Лимит и премиум.** `premium.is_premium(chat_id)` проверяется в момент отправки: без премиума
   уходит только самое старое активное расписание чата, остальные пропускают слот (не удаляются).
   Премиум-содержимое экранов (прогноз) рисуется так же, как по команде у этого чата.
6. **`/subscriptions`.** Строка «⏰ Расписания (N)» на главном экране → список: «Лидеры · голы —
   по пятницам 10:00 (МСК)» и кнопка 🗑 на каждом; `sub:s` — список, `sub:s:<id>` — удалить.
   Подсказка «создать — напишите боту, например: присылай лидеров по голам по пятницам в 10».
   Удаление чужого `id` невозможно: запрос с `chat_id`.
7. **Журнал (99).** `bot_actions`: `schedule_sent` (id, экран), `schedule_deleted`.
8. **Документация.** `docs/architecture.md`: миграция 0020, `schedule_repo.py`, тикер в разделе
   `bot.py` (почему в процессе бота, а не в `sync`); `docs/telegram_bot.md` — расписания.

**Не входит:** создание расписания (108); правка существующего; время с точностью до минуты;
отдельный сервис-планировщик; новые отчёты и тексты ИИ.

**Критерии приёмки.**
- `next_run_at`: день/неделя/месяц, «последний день» в феврале и в 30-дневном месяце, пояс с
  переходом на летнее время (`America/New_York`, 8 марта и 1 ноября 2026), `Europe/Moscow`,
  граница «ровно сейчас» — следующий слот, а не текущий.
- Тикер: просроченное на 3 дня расписание отправляется один раз; `TelegramForbiddenError`
  выключает расписания и подписки чата; сбой одного расписания не мешает второму.
- Лимит: чат без премиума с двумя активными получает только старейшее.
- `/subscriptions`: список и удаление проходят через `Dispatcher.feed_update` (как в
  `tests/test_bot_integration.py`); чужой `id` не удаляется.
- `tests/test_db_nhl.py`: миграция применяется и откатывается, CHECK-и отвергают `week` без дня
  и `local_time` 10:15.
- Живая проверка на dev-боте: расписание, созданное SQL-ом на ближайшие полчаса, приходит
  вовремя по МСК и по второму поясу; удаление из `/subscriptions`.
- `make ci-local` зелёный; pytest с `PG_PORT=1`, как в CI; `test_db_nhl` прогнан на БД.

**Подводные камни.**
- Номер миграции: параллельные задачи берут один номер, `db-migrate` молча пропустит вторую —
  сверить с `origin/develop` перед PR.
- Двойная отправка при двух процессах бота на одну базу — сейчас такого нет; при появлении —
  `SELECT … FOR UPDATE SKIP LOCKED` в `due`. Не делать заранее (GC1).
- Ранние слоты: ночь догружается до 11:00 МСК, расписание на 8:00 может прийти без последних
  матчей — экран тот же, что по команде в это время; оговорка — в подсказке карточки 108.
- Тикер не должен держать event loop: отправка в `to_thread` только для БД, Bot API — `await`.
- Бюджет GC6: оценка ~280 строк с тестами; если рендер по `chat_id` раздувает дифф —
  вынести его отдельным коммитом той же ветки.
