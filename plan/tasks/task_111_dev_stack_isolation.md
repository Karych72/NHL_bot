# Задача 111. Dev-стек: без доступа к продовой базе, без root и своим ключом Claude

**Блок:** релиз · **Надобность:** 🟠
**Область:** `docker-compose.yml`, `deploy/compose.dev.yml`, `deploy/systemd/nhl-bot-secrets.service`,
`deploy/fetch-secrets.sh`, роли Postgres (миграция или init-скрипт), Secret Manager,
`DEVELOPMENT.md` §«Dev-стенд».
**Зависит от:** ничего; удобнее после 110 (тот же визит на VM).
**Источник:** аудит Задачи 82, кандидаты 8, 9, 10 в [`../../docs/security.md`](../../docs/security.md);
реестр — [`../open_tasks.md`](../open_tasks.md).

## Кратко

Код ветки `develop` проходит меньше проверок, чем прод, но сегодня имеет три продовых доступа:
1. Postgres с `host all all all trust` — dev-контейнеры в сети прода входят в продовую базу
   `postgres` суперпользователем без пароля;
2. юнит `nhl-bot-secrets` при загрузке VM запускает от root `fetch-secrets.sh` из чекаута dev;
3. dev получает тот же ключ Anthropic, что и прод (общий бюджет, общий отзыв).

## Зачем и на что влияет

- Ошибка в миграции или коде `develop` может испортить продовые данные и подписки — ровно то,
  от чего Задача 80 разделила базы.
- Скрипт из dev-чекаута — код непроверенной ветки с правами root на хосте прода.
- Перерасход или утечка ключа на dev бьёт по проду.

## Степень важности

🟠 — подтверждённый риск: граница «dev не трогает прод» сейчас держится на дисциплине.

## Подробно

1. **БД.** Роль `nhl_dev_app` (LOGIN, пароль из Secret Manager через тот же механизм
   `/run` + compose secret), владелец базы `nhl_dev`, `CONNECT` к `postgres` отозван у `PUBLIC`.
   В `pg_hba` вместо `host all all all trust`: суперпользователь `postgres` — `trust` только из
   подсети прод-стека или по паролю, `nhl_dev_app` — `scram-sha-256` только к `nhl_dev`.
   `nhl_ai_reader` в dev — тоже только к `nhl_dev`. Учесть: `pg_hba` живёт в томе `pgdata`, а не
   в репозитории — правка вручную на VM или init-скрипт; описать в `DEVELOPMENT.md`.
2. **Root при загрузке.** Обе строки dev в юните запускать скриптом из прод-чекаута
   (`/opt/nhl_bot/deploy/fetch-secrets.sh`): аргументы те же, код — проверенный.
3. **Ключ Claude.** Отдельный ключ (`nhl-bot-anthropic-key-dev`) с лимитом расходов в консоли
   Anthropic — шаг человека; в юните dev читает его.
4. `docs/security.md` — пункты 8, 9, 10 → исправлено.

**Приёмка:** из `nhl_bot_dev-bot-1` подключение к базе `postgres` любой ролью отклоняется;
dev-бот работает на `nhl_dev`; после перезагрузки VM оба бота поднимаются; `systemctl cat
nhl-bot-secrets` не ссылается на `/opt/nhl_bot_dev`.
