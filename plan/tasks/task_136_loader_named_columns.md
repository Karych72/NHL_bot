# Задача 136. Загрузчик: именованные колонки вместо позиционных кортежей

**Блок:** инженерия · **Надобность:** 🟠 (после 135)
**Область:** `pipeline/load_season_modern.py`, `tests/_pipeline_fixtures.py`,
`tests/test_pipeline_*.py`, `telegram_bot/database.py` (`ALLOWED_TABLES`, `ALLOWED_COLUMNS`).
**Зависит от:** Задача 135 (DB-тест на `run()`).
**Источник:** ревизия качества кода 2026-11-16, просьба человека завести задачи; реестр —
[`../open_tasks.md`](../open_tasks.md).

## Кратко

Список колонок каждой таблицы задаётся один раз, рядом с функцией, которая строит её строки.
Запись в БД и тестовые фикстуры берут его оттуда; обращения вида `row[7]` исчезают.

## Зачем и на что влияет

- Новая колонка сейчас — правка в пяти-шести местах: DDL, миграция, кортеж в `build_*`, список
  колонок в `run()` (за тысячу строк от кортежа), копия списка в тестах, `ALLOWED_COLUMNS`.
- Порядок полей держится на дисциплине: перепутанные местами два поля одного типа не ловит ни
  типизация, ни существующие тесты.
- После задачи новая колонка — это DDL с миграцией, одна строка в списке и одно поле в
  построителе.

## Степень важности

🟠: главный источник трудозатрат при правке схемы и подтверждённый риск тихой ошибки данных.

## Подробно

**Текущее состояние (снимок 2026-11-16, `origin/develop` = `5a97128`; строки сверять).**
- Построители возвращают кортежи; списки колонок перечислены в `run()` (`:1772-2122`).
- Магические индексы: `team[6]`, `row[7]`, `row[8]`, `row[10]`, `row[:7] + … + row[8:]`
  (`:675`).
- `build_game_rows` возвращает семь списков одинакового типа — перепутать их при распаковке

- `tests/_pipeline_fixtures.py:45-48` — `TABLE_COLUMNS`, копия списков из `run()` с пометкой
  «keep in sync manually».
- `telegram_bot/database.py:34, 49` — `ALLOWED_TABLES` и `ALLOWED_COLUMNS` заметно шире
  фактически используемого ботом.

**Что делать.** По PR на шаг:
1. **Списки колонок — константами** на уровне модуля, рядом с соответствующим `build_*`.
   `run()` и `execute_upsert` берут их оттуда; `tests/_pipeline_fixtures.TABLE_COLUMNS`
   удаляется, тесты импортируют константы.
2. **Строки — по именам.** Построители возвращают `dict` или `NamedTuple` (один способ на весь
   модуль); индексы заменить именами. Результат `build_game_rows` — именованная структура, а
   не кортеж из семи списков.
3. **Сузить `ALLOWED_TABLES` и `ALLOWED_COLUMNS`** до используемого ботом.
