# Задача 134. Тесты бота: не привязываться к текстам интерфейса

**Блок:** инженерия · **Надобность:** 🟡
**Область:** `tests/test_bot_*.py`, `tests/test_push_digest_job.py`, `tests/conftest.py`,
константы текстов в `telegram_bot/`.
**Зависит от:** ничего. Удобнее после Задачи 133, когда тексты экранов разойдутся по модулям.
**Источник:** ревизия качества кода 2026-11-16, просьба человека завести задачи; реестр —
[`../open_tasks.md`](../open_tasks.md).

## Кратко

Тесты проверяют структуру сообщения и ссылаются на константы из рабочего кода, а не повторяют
русские строки интерфейса.

## Зачем и на что влияет

- Около 340 утверждений в тестах содержат русские строки интерфейса. Одна и та же строка
  повторяется в нескольких файлах: «Ещё: » — в пяти, «/subscriptions» — в шести.
- Правка формулировки ломает тесты в нескольких файлах сразу; на правку текста уходит больше
  работы и контекста, чем на сам текст.
- Для продуктовых задач (123–126 — почти целиком тексты) это прямой множитель трудозатрат.

## Степень важности

🟡: удобство правки. Поведение бота не затрагивается.

## Подробно

**Текущее состояние (снимок 2026-11-16, `origin/develop` = `5a97128`).**
- Правильный образец уже есть: `_tables()` в `tests/test_bot_messages.py:25` сравнивает
  структуру таблиц, а не текст.
- Самые привязанные файлы: `tests/test_bot_messages.py`, `test_bot_integration.py`,
  `test_push_digest_job.py`, `test_bot_stats_handlers.py`, `test_bot_application.py`.

**Что делать.**
1. Посчитать строки интерфейса, которые встречаются в утверждениях более чем в одном файле, —
   это список для работы; одиночные не трогать.
2. Для каждой: если строка — константа в рабочем коде, импортировать её в тест; если собрана
   f-строкой — вынести неизменную часть в константу рядом с кодом.
3. Там, где тест проверяет состав экрана (кнопки, таблицы, порядок блоков), перейти на
   структурные проверки по образцу `_tables()`.
4. Оставить буквальные строки там, где тест проверяет именно формулировку (тексты отказов
   ИИ, оплаты) — по одной проверке на формулировку.

Делить на PR по тестовым файлам.

**Критерии приёмки.**
- Ни одна русская строка интерфейса не повторяется в утверждениях более чем в двух тестовых
  файлах (скрипт подсчёта приложить к PR).
- Пробная правка: изменить подпись «Ещё: » в коде — падает не больше одного теста.
- Число тестов не уменьшилось; `make ci-local` зелёный.

**Подводные камни.**
- Тест, который импортирует константу и сравнивает её с ней же, ничего не утверждает
  («Мандат ревьюера» — Critical). Константа годится, чтобы найти блок в сообщении; утверждение
  должно быть о данных вокруг неё.
- Не вводить слой «локализации» или каталог строк (Global Constraint 1): константы лежат рядом
  с кодом, который их использует.
- Объём большой; задача не блокирует ничего и может идти по файлу за раз, попутно с
  продуктовыми задачами, которые эти тесты всё равно трогают.
