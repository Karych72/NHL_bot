# Задача 38. Образ и переносимость

**Статус:** не начата · **Блок:** релиз+ · **Надобность:** 🟠 подтверждённый долг
**Область:** `Dockerfile`, `.dockerignore`, `requirements.in` (+ `requirements-dev.in`, `make lock`), `docs/architecture.md`.
**Порядок:** после релиза, в любом порядке с 37, 41, 42.
**Реестр:** [`../open_tasks.md`](../open_tasks.md), раздел «Релизный блок».

## Кратко

Три независимых дефекта образа. (1) `Dockerfile` не ставит `ffmpeg`, а
`telegram_bot/video_replay.py` ищет его через `shutil.which` и при отсутствии молча
пропускает faststart-ремукс и превью — в контейнере фича видео деградирует без единой
строки в логе. (2) `all_data/` нет в `.dockerignore`, каталог попадает в контекст сборки
(`COPY . .`). (3) `pytest>=8.0` живёт в `requirements.in`, то есть в рантайм-образе
(`pytest==9.1.1` в lock-файле).

## Зачем и на что влияет

- **Зачем.** Global Constraint 4 запрещает молчаливую деградацию: в контейнере кнопка
  «видео гола» отдаёт MP4 без faststart (белый пузырь в Telegram) и без превью, и никто
  не узнает, что причина — отсутствие бинаря. Лишний контекст сборки замедляет
  `docker build` и может протащить данные в образ. Тестовый фреймворк в рантайме —
  мёртвый вес и лишняя поверхность.
- **На что влияет.** Сборка образа (размер, время), `video_replay.py` (явный отказ вместо
  тихого), состав зависимостей и lock-файлы (`make lock`, порядок рантайм → modeling → dev),
  таблица зависимостей в `docs/architecture.md:166` (там `pytest` числится рантаймом).
- **Если не делать.** Релиз в контейнере — с тихо сломанной фичей видео.

## Степень важности

🟠 **Подтверждённый долг.** Не блокирует запуск: бот работает, деградирует одна фича.
Но нарушение Global Constraint 4 в выпускаемом образе — находка уровня Important.

## Подробно

### Текущее состояние (сверено 2026-09-22)

- `Dockerfile`: `python:3.11-slim-bookworm`, `apt-get install libpq5` — единственный
  системный пакет; `pip install -r requirements.txt`; `COPY . .`.
- `video_replay.py:129-130` — `_ffmpeg_bin()` → `shutil.which("ffmpeg")`; `:135-137` и
  `:179-180` — при `None` функции просто возвращаются; docstring `download_goal_video`
  (`:225`) так и говорит: «when ffmpeg is available».
- `.dockerignore`: `.venv`, `.ci_venv`, `requirements-modeling.txt`, `artifacts/`,
  `__pycache__`, `*.pyc`, `.env`, `.git`, кэши линтеров, `.DS_Store`, `.idea`,
  `downloads/*.mp4`, `*.mp4` — `all_data/` отсутствует. На этом чекауте каталог весит
  12 КБ (в реестре — 132 МБ после прогона Задачи 23): размер зависит от того, что туда
  выгружали, поэтому исключать надо независимо от текущего веса. В `.gitignore` он есть (`:7`).
- `requirements.in`: `pandas==2.2.3`, `requests`, `psycopg2-binary`, `jinja2`,
  `python-telegram-bot==21.11.1`, `pytest>=8.0`. `requirements-dev.in`: `ruff`, `mypy`,
  `pytest-asyncio==1.4.0`, стабы, `pip-tools` — самого `pytest` там нет, он приезжает
  транзитивно из рантайм-слоя. Задача 25 перевела файлы на `pip-compile`, но состав
  рантайма не пересматривала.

### Что нужно сделать

1. **ffmpeg — одно из двух, без третьего «тихого» варианта:**
   - поставить `ffmpeg` в образ (`apt-get install --no-install-recommends ffmpeg`;
     прибавка к образу заметная — измерить и записать в отчёт) **и** сделать отсутствие
     бинаря громким: `_ffmpeg_bin()` поднимает исключение с понятным текстом вместо
     `None`, ветки «нет ffmpeg — пропустим» в ремуксе и превью удалить;
   - либо отключить фичу видео в контейнере явно (переменная, читаемая на старте, при
     которой кнопки видео не показываются) — только если размер образа с ffmpeg
     неприемлем. Молчаливой деградации не оставлять.
   Рекомендация — первый вариант: фича заявлена в продукте, а отдельный выключатель
   «видео без ffmpeg» — лишняя ветка (Global Constraint 1).
2. `all_data/` → `.dockerignore`. Заодно сверить, что ещё из контекста не нужно образу
   (`tests/`, `plan/`, `docs/`) — но добавлять только требуемое задачей.
3. `pytest` перенести из `requirements.in` в `requirements-dev.in`, выполнить `make lock`,
   обновить таблицу в `docs/architecture.md`.
4. Тест на ошибку при отсутствии ffmpeg (`shutil.which` → `None` → исключение), если
   выбран первый вариант.

### Критерии приёмки (из реестра)

- `ffmpeg` либо в образе, либо фича видео в контейнере отключена явно — молчаливой
  деградации нет.
- `all_data/` в `.dockerignore`.
- `pytest` убран из рантайм-зависимостей, `make lock` перегенерирован.
- `make ci-local` зелёный.

### Проверка

- `docker build -t nhl-bot .` — контекст без `all_data/`;
  `docker run --rm nhl-bot sh -c 'which ffmpeg; pip show pytest'` — ffmpeg есть, pytest нет.
- Живой контейнер: видео гола приходит с превью и играет inline.
- `make ci-local` (CI ставит все три lock-файла — совместный резолв должен сойтись,
  см. комментарий про пин `pandas` в `requirements.in`).

### Подводные камни

- `make lock` в hash-режиме: перенос `pytest` меняет и `requirements.txt`, и
  `requirements-dev.txt`; пересобирать в порядке рантайм → modeling → dev.
- `pytest-asyncio` требует `pytest` — после переноса он должен резолвиться из dev-слоя;
  проверить `pip check` в CI-окружении.
- `ffmpeg` из Debian тянет много библиотек в `slim`-образ; статический бинарь —
  новая зависимость и требует разрешения (Global Constraint 5).
