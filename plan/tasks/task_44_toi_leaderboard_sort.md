# Задача 44. Лидерборд «Среднее игровое время» сортирует время как текст

**Статус:** не начата · **Блок:** продукт · **Надобность:** 🟠
**Область:** `telegram_bot/bot_messages.py` (`player_stats_with_count`), `tests/`.
**Порядок:** любой; маленькая, можно окном между крупным.
**Источник:** ревью ветки `bot-ui-fixes-2` (PR «UI бота по отзыву, пачка 2», 2026-10-01);
реестр — [`../open_tasks.md`](../open_tasks.md), «Продуктовый бэклог».

## Кратко

Экран «Лидеры по среднему игровому времени» (меню `/stats`, хендлер
`bot_player_ice_time`, `stats_handlers.py:545`) сортирует `players_season_stats.time_on_ice_per_game`
— это `varchar` вида `м:сс` — как строку. Лексикографически «9:57» больше «25:00», поэтому
вверху списка оказываются игроки с меньше чем 10 минутами за игру, а настоящие лидеры
(25+ минут) — ниже всех «9:xx».

## Зачем и на что влияет

- **Зачем.** Экран показывает заведомо неверный рейтинг — не «лидеров», а игроков с самым
  большим временем среди тех, у кого меньше 10 минут.
- **Факт (2026-10-01, `nhl_bot-db-1`, БД `nhl_bot_predict_demo`, последний сезон в `games`).**
  `ORDER BY time_on_ice_per_game DESC` → Philp 9:57, Geekie 9:54, Lycksell 9:53, Lammikko 9:52,
  Tverberg 9:52. Та же БД при сортировке по секундам: Hughes 27:44, Werenski 26:37, Seider 25:40.
- **На что влияет.** Только этот экран. Другие лидерборды сортируют числовые колонки.
  Профиль клуба (`team_profile()`, `_BY_TOI`) уже сортирует по секундам — правильно.
- **Если не делать.** Экран остаётся вводящим в заблуждение.

## Степень важности

🟠 **Подтверждённый дефект** в уже выпущенном экране; правка маленькая.

## Подробно

**Текущее состояние.** `player_stats_with_count()` строит
`ORDER BY pl.<column> DESC NULLS LAST` для любой колонки из белого списка. Формат значения
пишет загрузчик: `optional_seconds_to_mmss()` (`pipeline/load_season_modern.py:118`) —
`f"{m}:{s:02d}"` или `NULL`, минуты без ведущего нуля.

**Что делать (один из вариантов, выбрать при реализации).**
1. Сортировать `м:сс`-колонки по секундам — тем же выражением, что `_BY_TOI` в
   `bot_messages.py` (`split_part(...)::int * 60 + split_part(...)::int`); вынести его в общий
   хелпер, чтобы профиль клуба и лидерборд не держали две копии.
2. Или хранить секунды числом (миграция + загрузчик) — дороже; оправдано, только если
   `м:сс`-колонки понадобятся для расчётов ещё где-то.

Проверить, нет ли других `м:сс`-колонок в сортировках лидербордов
(`leaderboard_specs.PLAYER_STAT_TITLES`) — на 2026-10-01 такая одна.

**Критерии приёмки.**
- Первая страница экрана — игроки с наибольшим средним временем (20+ минут), «9:xx» не
  выше «25:00».
- Тест через `fake_db_router` проверяет, что для этой колонки в SQL уходит сортировка по
  секундам, а для числовых колонок `ORDER BY` не меняется.
- Ручная проверка запросом на живой БД (как в «Факте» выше).

**Подводные камни.** Вторичная сортировка (`_resolve_secondary_sort`) и `NULLS LAST` должны
сохраниться; колонку по-прежнему нельзя подставлять из пользовательского ввода — только из
белого списка.
