# Задача 109. Память VM: pydantic 2.10.6 → 2.12, импорт aiogram вдвое легче

**Блок:** релиз · **Надобность:** 🟠
**Область:** зависимости — `requirements.in`, `requirements-modeling.in`, lock-файлы
(`make lock`); код — только если 2.12 сломает `modeling/config.py` или вызовы aiogram/anthropic.
**Зависит от:** ничего.
**Источник:** замер на VM `nhl-bot` (GCP `nhl-bot-prod`) 2026-11-02 по просьбе человека;
реестр — [`../open_tasks.md`](../open_tasks.md).

## Кратко

Каждый процесс `bot.py` (прод и dev) держит ~460 МБ (RSS + swap), из них ~390 МБ — импорт
`aiogram.types`: pydantic строит core-схемы сотен типов Bot API и держит их до конца процесса.
pydantic 2.11+ строит их заметно экономнее. Поднять пин 2.10.6 → 2.12.x — минус ~200 МБ на
бота, ~400 МБ на VM, без изменения кода.

## Зачем и на что влияет

- VM — `e2-small`, 2 ГБ RAM. На 2026-11-02: RAM занято 936 МБ, **swap 2 ГБ занят на ~910 МБ**,
  из них 430 МБ — прод-бот, 227 МБ — dev-бот. OOM не было, но обращение к выгруженным
  страницам — чтение с диска, то есть задержка ответа бота.
- Растущие функции (ИИ, расписания 107–108, премиум) добавляют память поверх уже занятого swap.
- Альтернативы дороже: e2-medium (деньги) или остановка dev-бота между проверками (ручной шаг
  перед каждой живой проверкой).

## Степень важности

🟠 — подтверждённый риск: swap уже занят наполовину. Не блокирует релиз, но дешевле любой
альтернативы и снимает вопрос апгрейда VM.

## Подробно

### Замер (2026-11-02, образ `ghcr.io/karych72/nhl_bot:dev-9842080`)

Чистый импорт в новом контейнере, `VmRSS` после импорта (не пик; `gc.collect()` не меняет):

| Шаг | pydantic 2.10.6 | 2.11.10 | 2.12.5 |
|---|---|---|---|
| голый python | 14 МБ | | |
| `import aiogram.types` | 406 МБ | 221 МБ | 203 МБ |
| + `anthropic` | 442 МБ | 259 МБ | 240 МБ |

2.11/2.12 ставились `pip install` поверх образа во временный контейнер — импорт без ошибок,
pip не сообщил о конфликтах. Работающий бот весит почти ровно столько, сколько импорт, —
утечки нет, экономить больше нечего.

Остальная VM для справки: Postgres 93 МБ (обе базы по ~80 МБ, `shared_buffers` 128 МБ),
sync/predict/backup — 1–26 МБ каждый. pandas бот не импортирует.

### Почему пин 2.10.6

Технической причины нет: `requirements.in` пинует pydantic «тем же пином, что в
`requirements-modeling.in`» — CI ставит три lock-файла одной командой, и пины должны совпадать.
В `requirements-modeling.in` pydantic нужен `modeling/config.py` (валидация YAML).

### Что делать

1. В `requirements.in` и `requirements-modeling.in` — `pydantic==2.12.x` (последний патч 2.12,
   который принимают aiogram 3.31 и anthropic 2.3.0; сверить их ограничения на `pydantic`).
2. `make lock` — пересобрать lock-файлы (вместе подтянется `pydantic-core`).
3. `make ci-local`, `make modeling-dev` + тесты `modeling/` (config.py).
4. Замер после сборки образа: тот же скрипт, что выше, на новом образе — `aiogram.types` +
   `anthropic` ≤ 260 МБ.

### Критерии приёмки

- Пины pydantic совпадают в обоих `.in`, lock-файлы пересобраны, `make ci-local` зелёный.
- Замер импорта на собранном образе ≤ 260 МБ (было 442).
- После выкатки на dev-бота: `VmRSS + VmSwap` процесса `bot.py` ≤ 300 МБ через сутки работы;
  меню, ИИ-вопрос и расписание отвечают (живая проверка).

### Проверка (VM)

```bash
gcloud compute ssh nhl-bot --zone europe-west1-b --project nhl-bot-prod --command '
for c in nhl_bot-bot-1 nhl_bot_dev-bot-1; do echo $c; sudo docker exec $c grep -E "VmRSS|VmSwap" /proc/1/status; done; free -h'
```

### Подводные камни

- pydantic 2.11 поменял часть поведения валидации (например, порядок вызова валидаторов,
  предупреждения об устаревшем API). aiogram и anthropic его поддерживают, но свои модели
  в `modeling/config.py` прогнать тестами.
- Пины в двух `.in` расходиться не должны — иначе совместный резолв в CI не сойдётся.
- Новых пакетов нет — Global Constraint 5 не затронут, меняется версия существующего.
