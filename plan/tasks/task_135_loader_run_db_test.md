## Кратко

Появляется тест, который прогоняет загрузчик целиком на записанных ответах NHL API и проверяет
строки в настоящем PostgreSQL.

## Зачем и на что влияет

- `run()` — около 430 строк INSERT, UPSERT и DELETE в одной транзакции — не исполняется ни в
  одном тесте. В `tests/test_pipeline_cli.py:30` он подменён заглушкой.
- Тесты построителей строк проверяют порядок полей по списку колонок, скопированному руками
  (`tests/_pipeline_fixtures.py:45-48`, «keep in sync manually»). Расхождение кортежа и списка
  колонок в `run()` сейчас ловится только на реальной загрузке.
- Любая правка схемы или загрузчика (Задачи 136, 137, 138) без этого теста проверяется на
  проде.

## Степень важности

🟠: самый рискованный код проекта без покрытия; блокирует безопасный рефакторинг загрузчика.

## Подробно

**Текущее состояние (снимок 2026-11-16, `origin/develop` = `5a97128`; строки сверять).**
- `pipeline/load_season_modern.py:1712-2138` — `run()`; `:1608` — `execute_upsert`;
  `:256-274` — `get_json` (в тестах не упоминается).
- Записанные ответы API лежат в `tests/fixtures/*.json`, снимаются
  `scripts/capture_nhl_fixtures.py`.
- DB-тесты живут в `tests/test_db_nhl.py`, включаются флагом `RUN_DB_SCHEMA_TESTS`, в CI идут
  отдельным джобом `db-tests` с PostgreSQL 16; данные синтетические (сезон 99999999,
  отрицательные chat_id) с очисткой.

**Что делать.**
1. Подменить в тесте сетевой слой загрузчика (`get_json` или сессию) ответами из
   `tests/fixtures/`. Запрос, которого нет в фикстурах, роняет тест — как `RoutedCursor` в
   `tests/conftest.py:212`.
2. Прогнать `run()` на CI-PostgreSQL и проверить: число строк в каждой таблице, которую пишет
   загрузчик; несколько известных значений из фикстур (счёт матча, три звезды, строка игрока
   и вратаря); целостность внешних ключей.
3. Второй прогон на тех же данных: число строк не меняется (идемпотентность).
4. Отдельные небольшие тесты на `get_json`: повтор на 429 и 5xx, поведение на 404.

**Критерии приёмки.**
- Перестановка двух колонок в списке `run()` роняет новый тест (проверить вручную один раз,
  результат записать в PR).
- Тест идёт в джобе `db-tests` и в `make all-tests`; без БД не запускается и не пропускается
  молча.
- `make ci-local` и `make all-tests` зелёные.

**Подводные камни.**
- Данные теста не должны пересекаться с данными других DB-тестов: отдельный сезон или
  отдельная схема, очистка после.
- Фикстуры покрывают один игровой день; если `run()` запрашивает больше (сезонные отчёты,
  ростеры 32 команд, расписание) — доснять `capture_nhl_fixtures.py`, а не подставлять пустые
  ответы.
- Поведение `get_json` на 404 сейчас — десять повторов любой ошибки. Тест фиксирует желаемое
  поведение только после решения, менять ли его; иначе зафиксировать текущее и отметить в PR.
- Мок вместо реальной проверки — Critical по «Мандату ревьюера»: подменяется только сеть, БД
  настоящая.
