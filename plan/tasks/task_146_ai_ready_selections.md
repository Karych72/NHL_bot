# Задача 146. ИИ: какие готовые выборки добавить (ресёрч)

**Блок:** продукт · **Надобность:** 🟡
**Область:** `telegram_bot/ai_stats.py` (`player_overview`, `_tools`), журнал `ai_stats_log`,
`plan/ai_questions/README.md` (каталог), итог — `plan/ai_questions/ready_selections.md` и задачи
на каждую выбранную выборку.
**Зависит от:** 142 (список повторяющихся вопросов и их стоимость).
**Источник:** обсуждение развития ИИ 2026-11-16; реестр — [`../open_tasks.md`](../open_tasks.md).

## Кратко

Решаем, для каких типов вопросов написать готовую выборку — инструмент, где запрос к базе
написан нами, а модель только называет параметры и пересказывает результат. Сейчас такая
выборка одна: обзор игрока.

## Зачем и на что влияет

- Свободный SQL — самый дорогой и хрупкий путь: до 4 попыток, обязательный ревьюер, схема всей
  базы в промпте. Готовая выборка — один вызов инструмента, цифры проверены кодом и тестами.
- Каталог Задачи 94 уже называет кандидатов («команда и матч — позже»): обзор команды, обзор
  матча. Плюс частые вопросы под свободный SQL: игрок против команды, личные встречи команд.
- Чем больше вопросов закрывают выборки, тем реже нужна схема базы в промпте — это следующий
  шаг экономии после Задачи 144.

## Степень важности

🟡: расширяет круг уверенных ответов и удешевляет их, но выбирать выборки без журнала — значит
писать код под выдуманные вопросы.

## Подробно

**Текущее состояние (снимок 2026-11-16).**
- `player_overview` (`ai_stats.py:322`): сезон и прошлый сезон, последние 10 игр, серия с
  очками; вратарю — свой набор. Запросы — константы `_OVERVIEW_*_SQL`.
- Маршрутизатор отправляет вопрос о клубе на экран `team_profile`, а не в ответ текстом.

**Что выяснить.**
1. По логу 142: какие вопросы с ответом идут через `run_sql` и повторяются по форме. Сгруппировать
   по типам каталога 94, у каждой группы — число вопросов, средняя стоимость, попытки SQL,
   доля правок ревьюера.
2. Для каждого кандидата: параметры выборки, что она возвращает, сколько это строк и токенов,
   какие формулировки вопроса закрывает и какие — нет. Кандидаты из каталога:
   - обзор команды («как дела у Вашингтона») — сейчас экран; нужен ли ответ текстом;
   - обзор матча («кто забил в матче Тампа — Флорида»);
   - игрок против команды («сколько Овечкин забил Коламбусу»);
   - личные встречи команд («как Тампа играет с Торонто»);
   - ближайшие матчи команды («когда играет Миннесота»);
   - сравнение двух игроков.
3. Порог: с какого числа повторений в журнале тип заслуживает выборки (Global Constraint 1 —
   абстракция с третьего повторения; здесь — с подтверждённого спроса).
4. Можно ли после выборок убрать ревьюер с их пути (связь с пунктом 3 Задачи 144) и убрать
   схему базы из первого вызова, отдавая её только когда выборки не подошли (два уровня
   промпта) — оценить экономию и риск.
5. Готовый экран или текст: для каких типов лучше открыть экран бота (цифры рисует код,
   модель не пишет ничего), а для каких — короткий текстовый ответ.

**Критерии приёмки.**
- `plan/ai_questions/ready_selections.md`: таблица кандидатов с числами из журнала, решение
  «делать / не делать / ждать данных» по каждому и обоснование.
- У каждой выборки «делать» — описание параметров и результата и оценка экономии на вопрос.
- Заведены задачи на выбранные выборки, по одной на выборку.
- Ответ на пункт 4: брать ли двухуровневый промпт, с числами.

**Подводные камни.**
- Каждая выборка — описание инструмента в префиксе каждого вызова. Десять выборок по 100
  токенов дешевле схемы, но их нельзя плодить без счёта: в документе — оценка прироста префикса.
- Выборка с пятью необязательными параметрами — тот же свободный SQL, только хуже. Одна
  выборка — один тип вопроса.
- Вопросы dev-базы — вопросы разработчика; спрос считать только по продовой.
- Имена игроков и клубов: поиск без диакритики уже есть в `_fold` — выборки используют его, а
  не свой (Global Constraint 2).
