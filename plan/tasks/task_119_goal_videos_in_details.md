# Задача 119. Видео голов внутри карточки: свёрнутые блоки вместо кнопок

**Блок:** продукт · **Надобность:** 🟡
**Область:** `telegram_bot/bot_messages.py` (`game_message`, `rich_message`, `rich_details`),
`telegram_bot/push_digest_job.py` (`run_game_broadcast`, `_prepare_goal_clips`),
`telegram_bot/stats_handlers.py` (`goal_video_markup`, `send_game_card_message`,
`callback_expand_digest_game`), `docs/telegram_bot.md` §«Стиль сообщений».
**Зависит от:** 117 🟨 (шапка карточки и таблица внутри `<details>` — та же разметка).
**Источник:** просьба человека 2026-11-12 (скриншот сообщения подписки на страну);
реестр — [`../open_tasks.md`](../open_tasks.md).

## Кратко

Сообщение подписки на страну: вместо кнопки «Карточка матча» полная карточка лежит в том же
сообщении свёрнутым блоком, как «Обозначения». Видео голов — не ряд кнопок под сообщением, а
внутри строки гола: строка гола — заголовок свёрнутого блока, в нём сам клип.

```
▸ Карточка матча                         ← уровень 1 (только у подписки на страну)
    1-й период
    ▸ 08:14 Barbashev (Eichel, Marner)   ← уровень 2: строка гола
        [видео]                          ← раскрывается по тапу
```

У подписчика команды и в карточке из меню карточка открыта — уровень один: тап по голу
показывает клип. Глубже двух уровней не идём: схему с двумя уровнями человек принял
2026-11-12, заводя задачу; третий уровень — перебор.

## Зачем и на что влияет

- Кнопка «Карточка матча» шлёт второе сообщение: лента подписчика растёт, а карточка
  оказывается под альбомом голов, а не рядом со счётом.
- Кнопки видео — по одной на гол (`goal_video_markup`, два столбца): при 7–9 голах это
  четыре-пять рядов под сообщением, «кнопки на всё подряд — это дофига» (человек).
- Канал (Задача 118) не может пользоваться callback-кнопками: ответ на нажатие уходит в
  `callback.message.chat.id`, то есть публикуется в сам канал. Видео внутри сообщения —
  единственный формат голов, который подходит каналу; 118 строится на этой задаче.

## Степень важности

🟡: удобство, ничего не блокирует, кроме формата голов в 118.

## Подробно

**Текущее состояние (снимок 2026-11-12, `origin/develop` = `37df559`).**
- Рассылка шлёт rich-сообщения Bot API 10.1 (`bot.send_rich_message`, `InputRichMessage(html=…)`).
- `run_game_broadcast` (`push_digest_job.py:507`): подписка на команду — `game_message` +
  `goal_video_markup`; только страна — `game_score_line` + блоки стран + кнопка «Карточка
  матча» (`dg:<game_id>`, `push_digest_job.py:559–570`), следом — альбом голов игроков страны.
- Кнопка `dg:` используется и в сжатом дайджесте (`stats_handlers.py:405`) — там остаётся.
- Клипы: `_prepare_goal_clips` — `file_id` из `bot_goal_clips` или скачивание и ffmpeg с
  загрузкой; `file_id` появляется только после первой отправки клипа в Telegram.

**Что Bot API позволяет (по типам aiogram, не проверено вживую).**
- `InputRichBlockDetails.blocks` — список любых блоков, в том числе `InputRichBlockVideo`.
- `InputRichBlockVideo.video` — `InputMediaVideo`, значит, годится `file_id` из кэша.
- В HTML-варианте видео — ссылка `tg://video?id=<id>` и поле `InputRichMessage.media`.
- Запасной вариант без видео внутри: `RichTextButton` со стилем `link` — callback-кнопка,
  нарисованная ссылкой прямо в строке гола (каналу не подходит).

**Что делать.**
1. **Spike на dev-боте (первым, до кода).** Скрипт шлёт одно сообщение по реальному матчу с
   8+ голами: карточка в `<details>`, в ней голы `<details>` с видео по `file_id`. Ответить:
   (а) принимает ли Telegram `<details>` внутри `<details>`; (б) лимит медиа и длины на одно
   rich-сообщение; (в) грузит ли клиент видео только при раскрытии; (г) вид на iOS, Android,
   Desktop — смотрит человек; (д) можно ли загрузить mp4 прямо в rich-сообщении (`attach://`
   в `media`) и каков предел размера запроса — от этого зависит п. 3. Итог spike — в эту
   карточку, решение по форме — человеку.
2. **Карточка с видео в голах.** `game_message` собирает строку гола заголовком `<details>`
   с клипом внутри; гол без клипа — обычная строка. `goal_video_markup` удалить вместе с
   обработчиком `gv:`, если spike подтвердил форму для всех мест (меню, `/tonight`, рассылка);
   две формы рядом не держать (Global Constraint 3).
3. **Откуда `file_id`.** В рассылке клипы и так готовятся до отправки — переиспользовать
   `_prepare_goal_clips`. В карточке из меню незакэшированный гол — отдельное решение по итогам
   spike (загрузить в самом сообщении, если (д) позволяет; иначе строка без видео и прогрев
   кэша на прогоне sync).
4. **Подписка на страну.** Кнопку «Карточка матча» заменить на `rich_details("Карточка матча",
   …)` с текстом `game_message`. Альбом голов игроков страны после сообщения — оставить или
   убрать (видео уже в карточке) — решение человека после spike.
5. Документация: `docs/telegram_bot.md` §«Стиль сообщений» — правило «видео гола — в его
   строке», `docs/architecture.md` — если удалены модули/обработчики.

**Критерии приёмки.**
- Под сообщением рассылки и карточкой нет кнопок видео голов; клип открывается из строки гола.
- Сообщение подписки на страну — одно, карточка в нём свёрнута; кнопки «Карточка матча» нет.
- Матч с 10+ голами уходит одним сообщением (или поведение при превышении лимита описано и
  проверено).
- Живая проверка на dev-боте на iOS и Desktop; `make ci-local` зелёный.

**Подводные камни.**
- Лимит размера запроса Bot API (50 МБ на загрузку): 10 клипов по ~9 МБ одним сообщением не
  загрузить — только `file_id` из кэша.
- Rich-сообщения новые: старые клиенты могут рисовать их иначе — проверять на телефоне, не по
  документации.
- Бюджет 300 строк: spike-скрипт не коммитится, если не нужен дальше.
