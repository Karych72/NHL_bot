# План: команда «матчи сегодня» (`/tonight`)

**Статус:** выполнено (архив). Реализация: `telegram_bot/nhl_scoreboard.py`, `telegram_bot/bot.py` (`/tonight`, callback), тесты `tests/test_nhl_scoreboard.py`. Этапы A–B покрыты; опциональный этап C (аргумент даты `YYYY-MM-DD`, кэш TTL) в коде не делался.

## Цель

Отдельная от `/day_games` команда: **живое расписание слейта NHL** на календарный день лиги (как в `scoreboard`), с **превью** матчей (пары команд, время, эфир, статус, при наличии — счёт). Источник — **не** PostgreSQL, а **NHL Web API**.

## Отличие от `/day_games`

| | `/day_games` | `/tonight` |
|--|--------------|------------|
| Данные | БД, последний загруженный игровой день | `GET https://api-web.nhle.com/v1/score/now` (следовать редиректам) |
| Контент | Полные карточки завершённых игр | Компактные превью слейта на `currentDate` из ответа |

## UX (что показать)

1. Заголовок с датой **`currentDate`** и пояснением, что это день **в терминах NHL**, не обязательно «полночь у пользователя».
2. Список игр из массива `games`, согласованный с календарным днём лиги: по возможности включать только записи с `gameDate == currentDate` (на границах слейта API может теоретически отличаться — правило зафиксировать в коде/комменте). Сортировка по `startTimeUTC`. Строка: `AWAY @ HOME`, время в одном согласованном поясе (напр. US/Eastern или UTC).
3. Статус: `gameState` / `gameScheduleState` (не начался / лайв / финал и т.д.).
4. При лайве/финале — счёт из полей команд, если API отдаёт.
5. ТВ: укороченный список из `tvBroadcasts`.
6. Пустой слейт — дружелюбное сообщение; ошибка API — короткий текст + лог.

## Техника

- Новый модуль (например `telegram_bot/nhl_scoreboard.py`): HTTP с `timeout`, сессия/`requests`, разбор JSON.
- `CommandHandler("tonight", ...)` в standalone-группе в `bot.py`.
- Лимит 4096 символов: `truncate_telegram_text` из `bot_messages.py` или разбивка на два сообщения.
- Обновить `help_text.py` и при необходимости хвосты подсказок в `stats_handlers.py`.

## Этапы

- **A (MVP):** клиент + форматирование + команда + help + тест форматтера на фикстуре JSON.
- **B:** кнопки «NHL.com» по URL из поля `gameCenterLink` ответа API (см. п. 7); если игра уже в БД — кнопка карточки бота (`game_exists` / deep link).
- **C (опционально):** аргумент даты → `GET /v1/score/{YYYY-MM-DD}`; кэш 30–60 с.

## Риски

Схема неофициального API может меняться; без редиректов часть ответов пустая.

## Пошаговая инструкция выполнения

### Этап A (MVP)

1. **Зафиксировать контракт ответа API.** Один раз снять живой JSON с `curl -sSL 'https://api-web.nhle.com/v1/score/now'` и сохранить усечённую копию в `tests/fixtures/` (каталог создать, если его ещё нет) или внутри теста как строку. В фикстуре оставить хотя бы одну игру с полным набором полей, которые читает форматтер (в т.ч. команды, время, статус, при необходимости счёт и `tvBroadcasts`).
2. **Добавить модуль `telegram_bot/nhl_scoreboard.py`.**
   - Константа базового URL `https://api-web.nhle.com/v1`.
   - Функция `fetch_score_now() -> dict`: `requests.get(..., timeout=15)`; редиректы включены по умолчанию в `requests` (при желании оставить явный `allow_redirects=True` для ясности). При не-200 или невалидном JSON — исключение или результат-обёртка `(ok, data|error)` — один стиль на весь модуль/хендлер.
   - Функция `format_tonight_preview(payload: dict) -> str`: взять `currentDate`; из `games` отобрать игры слейта (например `gameDate == currentDate`, если поле есть), отсортировать по `startTimeUTC`; для каждой строки: гости @ хозяева, время (один выбранный пояс), `gameState` (человекочитаемо), счёт если есть, ТВ (1–2 сети или обрезка).
   - Обработать пустой список игр на этот слейт — отдельная короткая фраза без ошибки.
3. **Подключить команду в `telegram_bot/bot.py`.** Функция `cmd_tonight`: вызвать `fetch_score_now`, при успехе — `reply_text(format_tonight_preview(...), parse_mode=...)` в одном стиле с остальным ботом (сейчас в коде смешаны `MARKDOWN` и `Markdown` — выбрать один вариант для этой команды). При использовании Markdown экранировать спецсимволы в пользовательском тексте, если в вывод попадают «сырые» строки из API. При ошибке — одно дружелюбное предложение пользователю + `logger.exception` или `warning`.
4. **Зарегистрировать хендлер:** `CommandHandler("tonight", cmd_tonight)` в списке `standalone` (та же группа, что `/day_games`), порядок не критичен.
5. **Обновить `help_text.py`:** строка в `_COMMAND_LINES` и при необходимости в `START_MESSAGE` — что `/tonight` это слейт NHL на «сегодня по лиге», не то же самое, что `/day_games`.
6. **Тест без сети:** в `tests/` добавить тест, который подаёт в `format_tonight_preview` фикстуру и проверяет наличие ключевых фрагментов (дата, трикоды, время) и поведение на пустом `games`.

### Этап B (кнопки)

7. **URL NHL Gamecenter.** Опираться на поле **`gameCenterLink`** в объекте игры (относительный путь вида `/gamecenter/.../.../.../{id}`): итоговый URL = `https://www.nhl.com` + значение `gameCenterLink`. Не полагаться только на шаблон `https://www.nhl.com/gamecenter/{game_id}` — сезон и slug в пути могут отличаться; API даёт канонический путь.
8. **Inline-клавиатура.** Для каждой игры в ответе — при необходимости **не более одной строки кнопок на игру** (лимит Telegram на кнопки): например «NHL.com» с `url=...`.
9. **Карточка в боте.** Если для `id` игры `game_exists(id)` из `bot_messages.py` возвращает `True` — добавить кнопку с `url` deep-link бота: `https://t.me/<BOT_USERNAME>?start=game_<id>` (имя бота из конфига/окружения, как уже сделано для `/start` в `bot.py`). Если имени бота в конфиге нет — завести `BOT_USERNAME` в `.env.example` или собрать ссылку только когда переменная задана.
10. **Разбивка сообщений.** Если текст + кнопки не помещаются или кнопок слишком много: либо укоротить текст, либо слать первое сообщение текстом, второе — только с частью кнопок; либо убрать дублирование ТВ в тексте, оставив только таблицу матчей + ссылки.

### Этап C (опционально)

11. **Аргумент даты.** В `cmd_tonight` читать `context.args`: если ровно один аргумент `YYYY-MM-DD` — вызывать `GET /v1/score/{date}` той же обёрткой, что и `score/now`; иначе — прежнее поведение `score/now`.
12. **Валидация даты.** `datetime.strptime` + ограничение разумным диапазоном (сезон), при ошибке — краткая подсказка по формату.
13. **Кэш in-memory.** На уровне модуля: TTL обязателен — **не** использовать «голый» `functools.lru_cache` без срока жизни. Варианты: обёртка с `(timestamp, data)` и ключом `(endpoint_kind, date)`, игнор записи старше ~45 с; или `cachetools.TTLCache`, если зависимость добавлена в проект; иначе простой `dict` + время последнего запроса.
14. **Документация.** В `help_text` одна строка: `/tonight [YYYY-MM-DD]` при включённой фазе C.

После каждого этапа — ручная проверка в Telegram и прогон `make test-fast` (или `pytest` для затронутых тестов).
