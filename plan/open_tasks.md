### Задача 34. Автообновление данных 🟨 🔴
Все цели `season-sync-*` — ручные. В `.github/workflows/` только `ci.yml`, в
`docker-compose.yml` сервиса загрузчика нет.

Область: `docker-compose.yml` либо `.github/workflows/`, `Makefile`.
Приёмка: загрузчик идёт по расписанию без участия человека, минимум раз в сутки; окно дат
вычисляется переносимо — `make season-sync-week` сейчас использует macOS-синтаксис
`date -v-7d` (`Makefile:228`) и в Linux-cron не заработает; неуспешный прогон виден
(Global Constraint 4 — молчаливый отказ cron равен протухшим данным); повторный прогон
по уже загруженным дням идемпотентен.

Кодовая часть выполнена в ветке `sdd-task-34-auto-sync` (PR #38, 2026-09-28): сервис `sync` в
`docker-compose.yml` на образе бота, планировщик `pipeline/scheduled_sync.py` (stdlib) —
ежедневно в 08:00 UTC окно «сегодня − 2 дня … сегодня», затем дайджест; при старте
контейнера прогон без дайджеста. Отказ виден как `unhealthy` в `docker compose ps`
(healthcheck `scheduled_sync.py check`: последний прогон неуспешен или старше 26 ч) и
ERROR в `docker compose logs sync`. `season-sync-week` считает окно Python-ом
(`WEEK_AGO`). Идемпотентность проверена: окно 2025-10-07…08 загружено дважды, счётчики
`games`/`all_goals`/`game_player_stats` не изменились. Задача остаётся открытой до
проверки на живом стеке: `docker compose up -d --build sync`, через сутки
`SELECT max(day) FROM games WHERE season_id = <текущий>` сдвинулся без ручного запуска.
Смена сезона по-прежнему требует правки `SEASON_ID` в `.env` (дизайн Задачи 33).
