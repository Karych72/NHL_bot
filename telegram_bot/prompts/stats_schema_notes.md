## Какие данные есть в базе

PostgreSQL, читать можно только перечисленные ниже таблицы (схема — после этого описания).
Это статистика НХЛ из официального API, больше в базе ничего нет.

Что и за какие сезоны:
- Сезонные итоги и матчи — с 1917/18; 2004/05 не игрался. 20262027 — текущий
  неполный сезон. `season_id` — целое вида 20262027. Метрики имеют разную глубину (ниже);
  отсутствие метрики (NULL) не означает нуль. Два матча 1917/18 без протокола не загружены.
- `game_type`: 2 — регулярный чемпионат, 3 — плей-офф; колонка есть в `games` и в сезонных
  таблицах (`teams_stats`, `players_season_stats`, `goalies_season_stats`,
  `players_advanced_stats`, `players_shot_types`), где у игрока или клуба по строке на тип.
  По умолчанию отвечай по регулярке: в сезонных таблицах `game_type = 2`, в поматчевых суммах
  («последние N игр», «против команды», «дома») — JOIN с `games` и `games.game_type = 2`.
  Плей-офф (`game_type = 3`) — только по явному вопросу о плей-офф, серии плей-офф или Кубке
  Стэнли; в ответе тогда назови рамку «в плей-офф». Регулярку и плей-офф не складывай,
  если об этом не просят. Без явного вопроса о плей-офф не добавляй даже отдельный
  итог плей-офф к ответу «всего» или «за карьеру»: запрашивай game_type = 2.
- Плей-офф и Кубок Стэнли года Y разыгрываются весной в конце сезона (Y−1)/Y: «Кубок 2024» —
  `season_id = 20232024`.
- Нет: травм, контрактов, обменов, драфта, КХЛ и сборных, коэффициентов, составов до игры,
  стартовых вратарей, роста и веса игроков. Возраст — `rosters.currentage` на момент загрузки.
- Имена игроков и названия клубов в базе латиницей (`Kirill Kaprizov`, `lastname` = `Kaprizov`,
  клуб `MIN`/`Minnesota Wild`). Русское имя из вопроса переведи в латиницу сам; однофамильцев
  (в том числе одного клуба, например братьев Хьюзов) отличай по `player_id`, клубу или позиции.
  У части имён диакритика и апострофы (`Stützle`, `Slafkovský`, `O'Reilly`): в SQL ищи по
  `lastname ILIKE 'St_tzle'` (символ `_` вместо буквы с диакритикой) либо берёт `player_overview`.
- Все ключи составные с сезоном: игрок и клуб в разных сезонах — одни и те же `player_id` /
  `team_id`, но строки разные. Присоединяй `rosters` и `teams` по `(id, season_id)`.

Какую таблицу брать:
- `players_season_stats` — итоги сезона по полевому игроку (игры, голы, передачи, очки, броски,
  ±, время на льду за игру, большинство, победные голы). `goalies_season_stats` — то же по
  вратарю (процент отражённых, коэффициент надёжности, сухие матчи).
- `players_advanced_stats` — расширенные метрики сезона (Corsi-подобные проценты, старты в зонах).
  `players_shot_types` — голы и броски по типам броска за сезон.
- `game_player_stats`, `game_goalie_stats`, `game_team_stats` — строка на игрока, вратаря,
  команду в конкретном матче; пара с `games` по `game_id`. Отсюда считаются «против команды»,
  «за последние N игр», «дома/в гостях», личные встречи.
- `games` — матчи завершённых игр: `day`, домашняя и гостевая команда, `winner_id`,
  `is_overtime`, `is_shootouts`. Счёт матча — сумма `goals` из `game_team_stats` по `game_id`.
- `all_goals` — каждый гол: автор, передачи, период, время, большинство/меньшинство, победный.
  `time` — «ММ:СС» внутри периода; пользователю время гола называй от начала матча:
  (`period` − 1)·20 минут + `time` (2-й период 09:37 → 29:37).
  `goalie_id` — вратарь, пропустивший гол (`rosters.player_id`; имя — LEFT JOIN `rosters` по
  `(player_id, season_id)`, сезон — `games.season_id`, группируй по `goalie_id`, а имя бери
  отдельно). `NULL` — гол в пустые ворота (`empty_net`), редкий гол без вратаря в данных API и матчи без play-by-play. «Кому игрок забил
  чаще всего» и «кто пропустил от игрока» — `GROUP BY goalie_id` по голам автора с
  `goalie_id IS NOT NULL`: пустые ворота в счёт не берутся. Голы буллитов (регулярка,
  `period = 5`, JOIN `games` и `game_type = 2`) тоже исключай; в плей-офф период 5 — овертайм.
  `game_three_stars` — три звезды матча.
- `shot_attempts` — каждая попытка броска с координатами. Есть у 20092010–20202021 и
  20262027; у 20212022–20252026 — только у игр плей-офф, регулярки нет. Число бросков
  игрока или клуба бери из `players_season_stats.shots` и `game_player_stats.shots`, а
  `shot_attempts` — для координат, типов и зон бросков.
- `teams`, `teams_stats` — клубы сезона и их итоги (место в таблице считай по очкам
  `points` сам). `rosters` — игроки сезона: имя, фамилия, позиция, клуб, страна (`nationality`).
- `scheduled_games` — расписание будущих игр на 14 дней вперёд.
- `playoff_series` — представление: серия плей-офф на строку, собрана из игр `games` с
  `game_type = 3`. `round` — раунд (финал Кубка Стэнли — серия самого большого `round`
  сезона: в 1917–1980-е раундов бывало меньше четырёх), пара `team_a_id` / `team_b_id`
  (меньший и больший id, а не хозяева и гости), `wins_a` / `wins_b` — победы каждой в серии,
  `goals_a` / `goals_b` — голы каждой, `winner_id` — победитель серии (`NULL`, пока серия идёт;
  в старых сезонах серии бывали «по сумме голов»). Обладатель Кубка завершённого сезона —
  `winner_id` серии самого большого `round`; в идущем сезоне — серии `round = 4`. Названия клубов — JOIN `teams` по `(team_id, season_id)`.

Правила запросов:
- Один SELECT, без точки с запятой в конце и без нескольких запросов. Пиши явные колонки.
- Если вопрос про «этот сезон» — это `season_id = 20262027` (в сообщении пользователя указана
  сегодняшняя дата). «В прошлом сезоне» — 20252026.
- `player_career_stats`, `goalie_career_stats` — итог карьеры на `(player_id, game_type)`:
  игры, голы, передачи, очки / победы, сухие матчи. Для имени найди DISTINCT player_id в
  rosters; не присоединяй карьерную строку ко всем сезонам состава (суммы умножатся).
  Полную карьеру по базовым метрикам называй карьерой, без «в наших данных».
  Исключение: в сезонных отчётах нет игроков плей-офф 1919/20; если карьера пересекает
  этот сезон, итог плей-офф неполный. Ранние финалы с клубами других лиг тоже покрыты
  не для всех игроков; отсутствие строки не превращай в нулевую статистику.
  Действующим игрокам назови дату данных из сообщения. Карьера включает текущий сезон.
  Суммы поздних метрик частичные: shots и plus_minus с 1959/60, хиты и блоки с 2005/06,
  голы в большинстве/меньшинстве с 1933/34. Если first_season_id раньше границы метрики,
  обязательно назови границу суммы; полностью NULL — «тогда не учитывали», а не нуль.
  В goalie_career_stats save_percentage — процент 0–100 из сумм сейвов и бросков
  за сезоны с обоими счётчиками; карьера до 1955/56 требует оговорки о неполноте.
  goal_against_average — GAA из пропущенных шайб и времени за одни и те же сезоны.
  Сезонные проценты и GAA не усредняй. При пропусках метрики внутри карьеры тоже назови
  неполноту: SUM пропускает NULL; при необходимости проверь count(метрика) против count(*).
- `franchise_stats` — командный итог на `(franchise_id, game_type)`: сезоны, игры, победы,
  очки, голы, playoff_seasons (число сезонов с сыгранными матчами плей-офф).
  Квебек и Колорадо — одна франшиза; ищи franchise_id через teams, затем одну строку
  представления. Голы восстановлены округлением сезонного среднего × игры до сложения.
  NULL franchise_id исключён. Участия — не число Кубков; очки плей-офф могут быть NULL.
- В сезонной строке игрока нет клуба: rosters.current_team_id — последний клуб сезона,
  не основание для «за клуб» или «бомбардир франшизы». Такие срезы считай только по
  game_player_stats + games (team_id в протоколе), с проверкой полноты нужного периода.

Глубина метрик (сезонные итоги; поматчевые ограничения отдельно):
| Метрика | Первый сезон |
| --- | --- |
| Игры, голы, передачи, очки, штраф; команды: игры, победы, очки, голы; вратари: победы, сухие | 1917/18 |
| Голы/очки в большинстве и меньшинстве | 1933/34 |
| Вратари: броски, сейвы, процент отражённых | 1955/56 |
| Броски полевых, плюс-минус; броски команд | 1959/60 |
| Процент реализации | 1960/61 |
| Команды: большинство и меньшинство, проценты | 1977/78 |
| Голы в овертайме | 1917/18; в регулярке перерыв 1942–1983, возобновление с 1983/84 |
| Полевые: время на льду, смены, вбрасывания; вратари: сейвы по составам | 1997/98 |
| Хиты и блоки за сезон, буллиты | 2005/06 |
| Corsi/Fenwick, зоны вбрасываний, типы бросков | 2009/10 |

Матчи загружены с 1917/18, но базовые счётчики не означают полный протокол:
хиты/блоки в протоколах — с 1997/98 (2002/03 местами неполон), координаты бросков —
с 2009/10; до 2009/10 shot_attempts не загружается. У старых голов нет situationCode:
all_goals.is_ppg/is_shg/empty_net и производные показатели могут быть NULL. Проверяй
count(метрика) против count(*) перед поматчевым выводом, при неполноте назови её.
Сезонные и карьерные итоги бери из отчётов, не пересчитывай из протоколов.

Сравнение эпох: до 1940-х передач на гол начисляли примерно втрое меньше; сезон длился
22–84 игры. До 2003/04 были ничьи, с 2005/06 — буллиты; сезоны 1994/95, 2012/13,
2019/20, 2020/21 неполные. При сравнении итогов и темпа учитывай длину сезона и правила
учёта; цифры сравнения всё равно бери из SQL, не из памяти.
